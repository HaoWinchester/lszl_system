# 发布与耗时

UAT：在已提交、干净的工作树执行 `bash deploy/update-uat.sh`。保持现有完整验证或受限的做题快速验证，成功后核对公网版本并更新远端部署基线。用户明确验收通过后，才允许将已验收内容合入 main 并正式发布。

正式环境继续执行 `bash deploy/update.sh` 的备份、同步、镜像、健康检查流程。发布前必须确认代码归档和数据库 dump 非空；正式备份要求不因缓存命中而改变。

## 看耗时

部署和验证输出 `STAGE scope=... stage=...` 与 `TIMING scope=... stage=... seconds=... status=...`。`stage=total` 是本次总耗时，失败阶段保留非零退出码；秒级计时含验证环境清理。

UAT 外层日志在终端，release 管理器输出保存在 `/tmp/kg-uat-release.log`。该文件会给出本次详细验证日志路径；验证尚未结束时可用 `tail -f` 查看该路径，完整日志包含后端测试、前端契约、浏览器和视觉检查阶段。

rsync 输出文件总量、实际发送字节和传输统计；Docker 输出各镜像层耗时与缓存命中。首次完整验证与后续复用应分别统计，不能把缓存命中耗时当成新代码的完整验收耗时。

## 验证结果何时复用

保留 release 目录中的 `source/`、`site/`、`release.json` 和 `validation.json`，继续使用管理器的 `update` 入口；无需增加跳过检查的参数。相同输入的成功完整验证可以在相同运行环境的不同工作树间复用。管理器每次仍检查关键页面、文件数、源和 site 内容及验证上下文。

旧版证据、新代码/依赖/测试/配置、未知文件、运行环境变化、发布包损坏，都会拒绝复用或重新验证。`docs/superpowers/`、`docs/verification/` 下的 Markdown 运维记录，以及 `frontend/new-legacy-sync-report.json` 同步差异报告不使缓存失效。该报告在重复同步时会从“上次变更”变成“无变更”，不代表发布内容变化；源、site 和 manifest 仍按实际内容校验。其他文档、脚本和未知报告仍计入。快速验证结果不能代替完整验证。

不要手工复制覆盖远端 active site，也不要使用 `--skip-browser` 来制造缓存命中。验证通过只代表开发自检，不代表用户已完成 UAT 业务验收。
