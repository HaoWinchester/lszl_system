# 试卷管理按需加载设计

## 背景与问题

UAT 的 `paper-management.html` 当前把试卷管理首屏绑定在题库全量快照上。实测加载链路如下：

- 页面加载了 58 个 JavaScript 和 13 个样式资源，`DOMContentLoaded` 约在第 4 秒触发。
- `GET /api/v1/question-catalog/bootstrap?mode=managed&include_questions=true` 返回约 23.8 MB，包含 12 个题库、605 道完整题目，耗时约 33 秒。
- `KGPaperDraftApi.ready()` 已经请求过试卷摘要和分类，但页面等待题库全量快照后，又重复请求试卷摘要、分类，并并发请求每一份试卷详情。
- 因此当前选中试卷的详情约到第 36 秒才开始显示，并形成 `1 + N` 试卷请求。

Runtime bootstrap 本次实测约 144 KB、0.8 秒，不是 23.8 MB 的来源，也不是首要性能瓶颈。它仍包含已经迁入领域 API 的旧试卷草稿键，后续应继续收口，但本设计不以删除整个 Runtime 机制为前提。

## 目标

1. 页面进入后并行加载试卷摘要、试卷分类和题库摘要，不等待完整题目正文。
2. 只加载当前选中试卷的详情；切换试卷时再按需加载并进行页面生命周期内缓存。
3. 题目只按当前选择的题库和分页范围获取；预览缺失正文时再按题目 ID 获取详情。
4. 题库 revision 变化只失效相关缓存，不自动触发全量题库下载。
5. 保持现有 `paper-management.html` DOM、样式、中文文案和全部操作入口不变。
6. 试卷和题库业务数据仍以 PostgreSQL 领域 API 为唯一权威源，不写入 Runtime 或浏览器持久化状态。

## 数据分层

### 试卷摘要

`GET /api/v1/papers` 只负责返回试卷目录需要的摘要字段：

- `id`
- `name`
- `subject`
- `description`
- `categoryId`
- `totalCount`
- `questionCount`
- `status`
- `revision`
- `publishedVersion`
- `publishedReleaseId`
- 生命周期时间与组卷批次摘要

摘要响应不包含 `questions`。前端收到摘要后可以立即渲染试卷列表。

### 当前试卷详情

`GET /api/v1/papers/{paperId}` 返回当前试卷元数据与有序题目引用。页面只为当前选中的试卷调用该接口。

前端维护页面生命周期内的 `paperDetailCache: Map<paperId, paper>`：

- 首次选中时加载详情。
- 再次选中时使用缓存。
- 保存元数据、替换题目、发布、撤回、归档、恢复或删除后，只失效对应试卷缓存和必要的摘要。
- 请求失败时保留试卷列表和已加载详情，显示可重试的具体错误，不清空整个页面。

### 题库摘要

`GET /api/v1/question-catalog/bootstrap?mode=managed` 只返回题库摘要和 revision，不传 `include_questions=true`。

摘要用于：

- 题库筛选下拉框；
- 题库名称、科目和题量展示；
- 导入、组卷对话框中的候选题库选择。

### 题库题目分页

选择具体题库后调用现有分页接口：

`GET /api/v1/question-catalog/banks/{bankId}/questions?page={page}&page_size={pageSize}`

前端按 `bankId + page + revision` 缓存当前页面需要的题目。切换题库或分页时才加载对应数据。

“全部题库”筛选不允许恢复全量下载。首版采用按题库分页的明确选择：页面默认选择当前科目的第一个可用题库；如果保留“全部题库”入口，则必须由后端提供跨题库分页查询，不能由浏览器把所有题库合并后分页。

### 单题详情

试卷题目引用、候选题目分页响应中若没有预览所需的完整正文，打开预览时调用：

`GET /api/v1/question-catalog/questions/{questionId}`

单题详情同样只做页面生命周期内缓存。题库 revision 提升后清空题目分页缓存和单题详情缓存。

## 页面初始化时序

```text
HTML 与必要脚本就绪
  ├─ 获取当前会话/权限
  ├─ GET /papers（试卷摘要）
  ├─ GET /paper-categories
  └─ GET /question-catalog/bootstrap?mode=managed（题库摘要）

试卷摘要返回
  ├─ 立即渲染试卷列表
  └─ 选择首个或用户上次选中的可见试卷
       └─ GET /papers/{selectedId}

题库摘要返回
  └─ 初始化题库筛选
       └─ GET /question-catalog/banks/{selectedBankId}/questions?page=1&page_size=...
```

试卷列表渲染不依赖题目分页请求。题目请求失败不会阻止试卷列表、试卷元数据和已有题目引用显示。

## 公共模块职责

### `question-catalog-adapter.js`

- 管理模式默认只拉题库摘要。
- 提供或复用按题库分页加载方法。
- 提供按 ID 获取单题详情的方法。
- revision 变化时只失效缓存并广播变化，不自动下载完整题库。

### `paper-draft-adapter.js`

- `ready()` 只完成摘要和分类首载，并复用同一个 Promise，避免重复请求。
- 增加页面生命周期内的详情缓存、并发请求去重和精确失效。
- 业务数据仍只来自领域 API；缓存不是持久化来源。

### `65-question-bank-admin.js`

- 试卷页初始化不再等待 `Catalog.ready` 中的全量题目。
- 首屏使用摘要渲染列表，只加载当前选中试卷详情。
- 题库候选区按选中题库和页码获取数据。
- 切换试卷时保存未完成请求的选择一致性：旧请求晚返回时不得覆盖新选择。

## 错误与恢复

- 试卷摘要失败：显示“试卷列表加载失败”，允许刷新重试。
- 当前试卷详情失败：列表仍可切换；详情区显示失败提示，再次选择或点击重试重新请求。
- 题库摘要失败：试卷列表与当前试卷详情仍可使用；禁用新增候选题和组卷入口，并给出重试提示。
- 题目分页失败：保留已加载页面，不清空当前试卷；用户可以切换题库或重试当前页。
- 单题详情失败：只影响该题预览，关闭预览后页面继续可用。
- revision 更新：清空题目相关缓存，保持当前试卷选择，并按需重新获取当前题库页。

## 性能验收标准

在 UAT 当前 12 个题库、605 道题、5 份试卷的数据量下：

- 首屏不再发起 `include_questions=true` 的题库全量请求。
- 首屏只调用一次 `/papers` 和一次 `/paper-categories`。
- 首屏最多调用一个 `/papers/{id}` 详情接口。
- 未选择其他题库时，不请求其题目列表。
- 未打开题目预览时，不请求单题详情。
- 试卷列表不等待任何题目正文响应即可显示。
- 切换已打开过的试卷不重复请求详情；相应试卷发生写操作后重新请求一次。

## 测试要求

### 自动化回归

1. 页面初始化测试：断言不出现 `include_questions=true`。
2. 请求次数测试：5 份试卷时只请求 1 份默认选中试卷详情。
3. 切换测试：首次切换请求详情，再次切回使用缓存。
4. 竞态测试：快速切换 A、B，A 晚返回不能覆盖 B。
5. 缓存失效测试：保存当前试卷后仅重新加载当前详情。
6. 题库分页测试：选择题库 A 只请求 A 的当前页；切换 B 才请求 B。
7. 错误恢复测试：题库题目失败不影响试卷列表和当前试卷详情。
8. 数据源扫描：试卷与题目业务数据不得新增 `localStorage`、`sessionStorage` 或 Runtime 持久化写入。

### 浏览器验证

- 在 UAT 使用真实数据库账号记录 Network 时序与响应体积。
- 验证试卷列表、切换、题目预览、导入题库、导入试卷、一键组卷、保存和发布入口仍可操作。
- 验证空试卷、详情失败、题库分页失败和重试路径。
- 保持现有页面 DOM 与视觉结构，不进行样式改版。

## 非目标

- 本次不重做 `paper-management.html` 的视觉设计。
- 本次不把一键组卷算法迁回前端；后端继续负责预检与事务创建。
- 本次不删除全站 Runtime bootstrap；只保证试卷领域数据不依赖它。
- 本次不合并到 `main`，在 UAT 验证通过并获得用户确认前保留在功能分支。
