# Bootstrap 全量抓取防护

## 目标与边界

修复匿名或普通学员通过 question-catalog/bootstrap 的 include_questions=true 一次获得全部公开题目、答案的问题。首次明确违规即拒绝返回内容、停用已识别的普通账号并持久锁定来源 IP。普通做题、目录摘要、分页读取及教师管理导入/导出保持兼容。普通 429 不触发封禁。

## 方案

- 在 bootstrap 限流之前检查全量读取权限；具有 accessQuestionBank 权限的教师/管理员仍能使用批量读取。其他身份的全量读取请求返回 403。
- 新建 security_ip_blocks 表，事务内保存 IP、原因、路径、关联账号、时间及审计日志；已登录普通账号复用 paused 状态。无登录身份只能封 IP，不能推断其账号。
- 全站请求中间件查库拦截封禁 IP，健康检查保留。数据库记录跨进程、跨重启有效；不使用内存封禁缓存。
- 共用客户端 IP 解析模块：仅信任明确配置的反向代理发来的 X-Real-IP，不使用未经信任的 X-Forwarded-For。UAT 的 Docker 网关已经只读核实为 172.22.0.1，端口仅绑定宿主机 loopback。
- 明确跨站的请求只拒绝、不封禁，防止第三方页面诱导用户发请求导致封号；合法管理请求仍正常鉴权。
- 提供管理员 IP 列表、解除锁定 API，解锁 IP 不自动恢复账号，账号由现有用户管理恢复。

## 验证与发布

先补匿名/学员第一次全量读取、跨客户端/伪造 IP、账号会话失效、教师批量读取、普通目录/分页及普通限流不封禁的回归测试。修改原来明确期望匿名全量读取的旧测试。运行后端、前端现有检查及浏览器正常做题验证。合入并推送 uat，通过现有 release 和部署流程上线 UAT，只用临时测试身份/真实测试来源验证封禁，随后清理测试封禁。等待用户业务验收，不合 main。

## 已知代价

同一公网 IP 可能由多个用户共用，封 IP 会阻止该出口其他用户；采用用户要求的首次锁定策略，并保留管理员解锁和审计。全站 IP 检查增加一次数据库主键查询；不额外引入依赖。
