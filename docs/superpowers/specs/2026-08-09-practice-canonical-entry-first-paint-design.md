# 做题模式统一入口与无闪烁首屏设计

## 背景

当前生产环境把三个相近但语义不同的入口混在一起：

- `/` 与 `/learning-path.html` 返回旧的引导学习路径页面；
- `/login` 重定向到 `/practice-mode.html?auth=login`；
- `/practice-mode.html` 才是当前要求的完整做题模式页面。

因此，访客从学习入口进入时会先看到旧页面；即使已经进入做题模式，试卷目录尚未完成初始化时，HTML 默认可见的试卷设置和模式卡片也可能短暂出现，随后才被空状态替换。用户要求学习入口不再进入旧学习路径：访客和登录用户都进入做题模式，访客首屏直接显示“暂时没有可练习的已发布试卷”，登录用户显示其可练习的已发布试卷。

## 目标行为

| 入口与状态 | 最终地址/页面 | 首屏行为 |
| --- | --- | --- |
| 未登录访问 `/` | `/practice-mode.html` | 直接显示做题模式空状态，不自动打开登录框 |
| 未登录访问 `/learning-path.html` | `/practice-mode.html` | 直接显示做题模式空状态，不自动打开登录框 |
| 已登录访问 `/` 或 `/learning-path.html` | `/practice-mode.html` | 显示做题模式，目录就绪后显示当前账号可用试卷或真实空状态 |
| 主动访问 `/login` | `/practice-mode.html?auth=login` | 显示做题模式并打开登录框 |
| 直接访问 `/practice-mode.html` | `/practice-mode.html` | 与当前登录状态一致，不自动打开登录框 |

旧学习路径不再承担默认学习入口。`/graph`、`/training`、`/workspace` 等其他稳定别名及权限边界保持不变。

## 方案

### 1. 服务端统一规范入口

FastAPI 在返回任何旧学习路径 HTML 之前处理 `/` 与 `/learning-path.html`，统一返回 `307` 到 `/practice-mode.html`。重定向不附带 `auth=login`，也不保留旧学习路径的 `stage`、`part`、`practiceReturn` 等页面状态参数，避免它们污染做题模式或意外打开登录框。

`/login` 继续作为唯一自动打开登录框的稳定入口，并继续强制输出 `auth=login`。

选择服务端重定向而不是浏览器脚本跳转，是为了确保旧学习路径 HTML 根本不会发送给这两个入口，浏览器也就没有机会先绘制旧页面。

### 2. 首次绘制状态由服务端认证信息预判

后端已经在页面头部、样式表之前注入 `window.__KG_DIRECT_BOOTSTRAP__`，其中包含可靠的 `authenticated` 状态。注入脚本同时在 `<html>` 上写入只用于首屏渲染的认证标记：

- 访客标记：做题大厅标题与空状态立即可见；试卷库、练习设置和模式卡片在目录初始化前不可见。
- 登录标记：在目录初始化完成前只显示做题模式外壳和“正在读取已发布试卷”的中性加载状态，不显示访客空状态，也不提前显示未确认的试卷设置。

该标记只决定首次绘制，不作为业务权限或数据来源。账号、试卷和订阅数据仍以服务端会话、后端 API 与数据库为准。

### 3. 做题模式显式结束初始化

`src/100-practice-mode.js` 在以下任一结果完成后标记页面为 `practice-ready`：

- 已成功读取目录并完成 `syncLobby()`；
- 目录不可用并显示明确错误状态。

进入 `practice-ready` 后，首屏保护样式退出，由现有 `hidden` 属性和做题模式控制器负责最终界面。这样不会出现错误状态被永久遮住，也不会把首屏认证标记当成后续业务状态。

## 数据与交互流程

1. 浏览器请求 `/` 或 `/learning-path.html`。
2. FastAPI 直接返回到 `/practice-mode.html` 的 `307`，未输出旧学习路径 HTML。
3. FastAPI 返回做题模式 HTML，并在 `<head>` 中注入当前会话的认证状态。
4. 浏览器首次绘制：访客立即看到真实空状态；登录用户看到中性目录加载状态。
5. 做题模式读取服务器目录并同步大厅。
6. 页面进入 `practice-ready`，显示可用试卷、真实空状态或具体错误状态。
7. 只有访问 `/login` 或主动点击账号菜单“登录”才打开登录框。

## 错误与恢复

- 目录请求失败时，页面退出初始化保护并显示现有“题目目录暂不可用”错误，允许刷新重试。
- 登录框关闭后，访客仍停留在可用的做题模式空状态，可从账号菜单再次打开登录框。
- 登录或退出触发远程会话变更时，现有 `direct-entry.js` 继续整页刷新；刷新后服务端重新注入认证标记，避免沿用旧状态。
- 重定向不依赖客户端 JavaScript，因此禁用脚本或脚本加载失败时也不会出现旧学习路径页面。

## 测试策略

### 路由契约

- `GET /` 返回 `307 /practice-mode.html`。
- `GET /learning-path.html` 返回 `307 /practice-mode.html`。
- 两个入口都不附带 `auth=login`，旧页面查询参数不会重新引入登录弹窗。
- `GET /login` 仍返回 `307 /practice-mode.html?auth=login`，来访 `auth` 不能覆盖登录模式。

### 首屏与交互

- 真实浏览器以访客身份进入 `/learning-path.html`，最终 URL 是 `/practice-mode.html`；旧 `.gl-app` 从未成为页面内容。
- 在目录初始化完成前，访客的空状态已可见，试卷库、设置卡和模式卡不可见，登录框不可见。
- 登录用户进入统一入口后落在做题模式；目录完成时显示真实试卷或真实空状态，而不是旧学习路径。
- 主动访问 `/login` 仍打开登录框；关闭后页面可用，并可从账号菜单重新打开。
- 模拟目录失败，确认加载保护退出并显示可恢复的错误状态。

### 回归范围

- 后端完整 pytest。
- 新版发布契约与线上回归 Node 测试。
- 做题模式浏览器测试和直连运行时 smoke。
- 发布前核对待发布 `site` 与当前 active release 的文件总数、关键页面存在性，并通过 `manage-new-legacy.js update new-legacy --skip-browser` 生成和提升 release；不手工覆盖 active release。

## 非目标

- 不重写做题模式的试卷、订阅、答题或登录业务。
- 不修改图谱编辑器、训练页、回忆页或管理端页面外观。
- 不用浏览器存储替代服务端认证或数据库数据。
- 不通过客户端延时、动画遮罩或硬编码等待时间掩盖闪烁。
