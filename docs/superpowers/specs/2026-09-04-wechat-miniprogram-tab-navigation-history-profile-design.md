# 微信做题小程序页签、记录与个人页优化设计

## 目标

解决首页、记录、我的三个主页面切换时的白屏和卡顿，修正记录页的对齐问题，并在不虚构用户资料的前提下补充个人页信息。视觉继续沿用已确认的米白纸张、墨绿色文字、低装饰原生移动端风格。

## 已确认的原因

- 当前底部导航调用 `wx.reLaunch`。每次点击都会销毁当前页面并重新创建目标页面，因此切换过程中会露出窗口背景，表现为短暂闪白。
- 记录页和个人页在每次 `onShow` 时都把页面重置为加载状态并重新请求接口，进一步放大了切换停顿。
- 记录页筛选按钮按内容宽度排布，记录操作按钮使用绝对定位和固定右侧留白；不同文案和系统字体下无法稳定共用一条对齐基线。

## 方案

### 主页面导航

- 将首页、记录、我的声明为原生 `tabBar` 页面，并使用自定义 tab bar 保留现有视觉语言。
- 页签跳转统一使用 `wx.switchTab`，不再使用 `wx.reLaunch`。
- 每个主页面只在首次进入时显示完整加载态；之后切回页面先展示已有内容，再按刷新策略更新。
- 自定义 tab bar 只负责当前态和路由，不承担业务数据请求。
- 登录失效仍允许使用 `wx.reLaunch` 回到登录页，因为此时需要清空受保护页面栈。

### 数据刷新策略

- 记录页和个人页记录最近一次成功加载时间。
- 首次进入或无数据时显示结构稳定的骨架屏。
- 再次切回时保留已有内容，不清空页面；超过短刷新间隔后静默更新。
- 下拉刷新始终执行显式请求并保留现有错误提示。
- 静默更新失败时保留上次可用数据，只有首次加载失败才展示整页错误态。

### 记录页

- 筛选区域改为三等分分段控件，标签共享同一高度、宽度和文字基线。
- 选中态使用底线与字重区分，不增加厚重胶囊或渐变。
- 记录项改为正常文档流：日期与模式位于顶部元信息行，试卷名独占正文区域，结果和操作位于同一底部行。
- 操作按钮不再绝对定位，长标题、不同状态文案和窄屏下都不会挤压错位。
- 加载、空状态和列表共用页面主栅格与左右边距。

### 个人页

- 顶部身份区增加由显示名称生成的文字头像，保留姓名、账号和身份标签。
- 新增“个人信息”分组，展示系统已有的真实信息：显示名称、登录账号、账号身份、学习权限和数据同步状态。
- 学习数据继续展示累计经验、本周经验、完成练习，三个数字使用等宽栅格和统一基线。
- 隐私政策、用户协议、退出登录保留在“账号与安全”分组。
- 不新增无法从接口确认的手机号、学校、地区、注册时间等字段，也不提供无后端支持的编辑入口。

## 状态与异常

- 快速重复点击当前页签不触发导航。
- 页签切换期间不出现业务遮罩、全屏 loading 或人为延时动画。
- 接口返回空数据时仍展示完整页面框架；错误信息不会造成布局跳动。
- 退出登录后清理本地草稿并跳转登录页的现有行为不变。

## 验证

- 契约测试确认三个主页面进入 `tabBar`、导航使用 `wx.switchTab` 且页面不再挂载旧底部导航组件。
- 单元/契约测试覆盖记录页三等分筛选、列表正常流布局、个人信息字段和静默刷新条件。
- 运行小程序现有完整测试。
- 在微信开发者工具中连续切换首页、记录、我的，检查首次进入与二次进入是否闪白，检查筛选项、记录行和个人信息行在手机宽度下的对齐。

## 非目标

- 本次不增加个人资料编辑、头像上传或新的后端用户字段。
- 本次不修改做题流程、计分逻辑、订阅逻辑或网页端界面。
- 不使用转场动画掩盖页面销毁；流畅度来自正确的导航和缓存机制。
