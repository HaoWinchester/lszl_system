# 深度回忆与多题画布笔迹工具（已确认方案）

日期：2026-09-25。用户已确认方案；实现、发布及 UAT 验收状态记录在实施计划与验证报告。

## 用户目标

1. 查看系统真实用户反馈，判断值得改进的事项。
2. 为深度回忆与多题画布增加画笔、荧光笔，两类笔均可改变颜色和粗细，交互参考博思白板。

## 已核查事实

- 页面为 `new-legacy/knowledge-recall.html` 和 `new-legacy/question-workspace.html`，共享 `new-legacy/src/canvas/` 的画布基础能力，未找到现成自由笔迹功能。
- 深度回忆由 `86-knowledge-recall.js`、`99-deep-recall-server-adapter.js`、后端 `RecallProgressSaveRequest` 和 `recall_progress` 保存进度。前后端会挑选字段，后端拒绝未知字段；只加前端显示不能保证笔迹保存。
- 多题画布使用 `65-canvas-workspace-store.js`、`77-multi-question-workspace.js` 和同步层 `canvas-workspace-adapter.js`，已有画布历史操作及数据库 JSONB payload。
- 正式环境为 https://lszl.aihuanpu.com 。通过显式服务器地址解析的 HTTPS 健康检查成功；管理员反馈接口要求登录。SSH 连接超时，现有浏览器会话未取得管理员登录状态，文档默认账号登录返回用户名或密码错误。
- 本地 `kg_graph_dev.feedback` 只读查询结果为 0 条，不能据此认定线上没有反馈。
- 未读取到真实反馈内容，因此现在不能按用户反馈作优先级判断。尚未修改反馈状态或回复用户。
- 参考：[博思白板官方画板说明](https://boardmix.cn/online-board/)：提供画笔类型、颜色、粗细等设置。本次仅采纳用户指定的两类笔和颜色、粗细设置。

## 方案比较

| 方案 | 成本与限制 | 结论 |
| --- | --- | --- |
| 在现有画布增加共享 SVG 笔迹层 | 复用现有坐标和保存链路，无需引入白板依赖；需处理事件冲突和保存字段 | 推荐 |
| 覆盖独立位图 canvas | 绘制方便，但需额外维护高清缩放、重绘、笔迹编辑与序列化 | 暂不采用 |
| 引入完整白板编辑器 | 功能超过两类画笔需求，替换现有页面与数据模型成本较大 | 暂不采用 |

## 用户交互

- 两页均加入同一套紧凑工具栏：选择、画笔、荧光笔。多题画布继续使用原有手型、移动和布局功能。
- 点击笔工具显示颜色与粗细面板：常用色板加自定义颜色，粗细滑杆加当前数值和笔触预览。
- 普通画笔默认蓝色、不透明、3 个世界坐标单位，范围 1–24；荧光笔默认黄色、约 30% 透明度、16 个世界坐标单位，范围 4–48。两类笔独立记住当前页面会话内的颜色和粗细。
- 允许在空白区和卡片上方书写；绘制时阻止触发底下的作答、连线和拖卡动作。退出绘制后恢复这些动作。
- 笔迹使用画布世界坐标，平移、缩放时保持位置一致。第一版笔迹不绑定卡片；移动卡片或自动整理后笔迹留在原画布位置。
- Esc 回到选择模式；临时平移复用现有手势。输入框内不抢占快捷键。切题、切画布、只读状态变化和 pointercancel 时终止未完成笔划，避免半笔写入错误画布。
- 撤销、重做以一整笔为单位；多题画布接入现有历史控制器，深度回忆为笔迹接入共享历史能力。
- 增加“清空笔迹”，确认后仅清理当前画布笔迹，并可撤销。深度回忆“重置本题”会同时清除本题笔迹，确认文案明确说明；“重置视图”不删除笔迹。
- 鼠标、触控笔、单指触摸均可绘制。第一版采用固定线宽，不加入压感、图形识别、多人协作、额外笔类或橡皮工具。

## 结构与数据

- 新增职责单一的共享笔迹模型和控制器，放在 `new-legacy/src/canvas/`。负责笔划采样、平滑 SVG 路径、工具面板、事件生命周期、序列化和历史操作，不直接访问业务 API。
- 两页适配器提供：当前 world/viewport、坐标转换、只读状态、读取笔迹、提交笔迹和历史入口。共享样式放在独立样式文件中，只由这两页加载。
- 笔迹记录包含 `id`、`tool`（pen/highlighter）、`color`、`width` 和世界坐标 `points`；透明度由笔类统一定义。对颜色格式、有限坐标、线宽、唯一 ID、笔划数和总采样点数实施前后端校验。
- 深度回忆增加明确的 `strokes` 字段、JSONB 列及 Alembic 迁移，接通读取、保存、重试、历史版本与重置。旧记录缺省为空列表。继续按用户、题目及发布版本隔离，并保留修订号冲突检测。
- 多题画布在既有 payload 中加入 `strokes`，规范化与复制、历史快照均保留该字段，沿用数据库保存入口；后端复用同一笔迹数据校验。
- 绘制中只更新当前笔划，落笔后更新数据并触发现有节流保存；失败显示未保存和重试入口，不以本地浏览器存储替代持久化。
- 切换画布前处理未完成保存；新画布不能继承上一画布的笔迹或撤销历史。只读用户可查看已保存笔迹，不能修改。

## 反馈评审方法

获得管理员访问后分页读取全部反馈，核对状态和已有处理回复，区分真实用户问题与测试记录，并去除重复诉求。逐条整理：反馈编号、问题、受影响页面、复现证据、影响程度、建议和实施成本。

优先级依据为：数据丢失或操作阻断优先，其次为高频学习体验问题，再评估低频便利性功能。尚未复现的问题标为待核实。反馈审阅不自动修改处理状态或向用户发送回复；除本次明确要求的画笔功能外，新增改进项先形成建议。
