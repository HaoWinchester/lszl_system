# 学习记录分页

用户已确认问题位于做题大厅“学习记录”，且批准服务端分页、“加载更多”和总记录数。现网只取最近100条后按试卷分组，导致旧卷的整张记录卡片消失；实际数据仍在。本次不恢复数据库，不改变试卷版本的进度统计。

## 行为与接口

- 抽屉首次加载20条，随后只有用户点击“加载更多”才请求下一页；总数来自服务端可见且去重后的记录。大厅最近记录仅请求5条。
- `GET /api/v1/learning/practice/sessions?limit=20&cursor=...` 返回 `{sessions,total,nextCursor}`。limit为1至100，新网页明确传20；不带limit时保留前100条，兼容已发布小程序及旧调用方。无游标为首页。游标按历史时间和唯一标识倒序，保证同一时间的稳定排序及新增记录时的继续翻页。非法游标422，匿名401，任何游标均须重新应用当前用户权限。
- 现代会话和旧完成事件在SQL端统一摘要、去重、排序和分页。旧事件引用已存在的当前用户现代会话时不重复显示，包括隐藏会话。只选界面消费字段，不读答案、题目、画布、整个stats/payload或报告正文；不在Python/浏览器加载全库后分页。
- 不要求release_id存在，补回全局复仇记录；名称退化为“复仇错题”或“练习试卷”。旧版试卷记录保留。原数组服务/适配器入口保留兼容。
- 按paperId合并已加载的轮次。摘要为“已加载X / 共Y条记录”，试卷数只代表已加载分组。尾页明确显示全部；加载失败保留已加载内容，按钮支持重试。首次失败也能重试。
- 连续点击只产生一个下一页请求。账号切换、退出、清空或重新打开重置分页；过期异步响应不能回填。追加不重复、不丢已展开详情和当前滚动位置。续做、查看本次成绩、清空仍有效。

## 约束及验收

权威前端源是new-legacy及同步适配层；不重设计、不引入依赖、不手改release site、不改正式数据库。后端使用现有隔离PostgreSQL测试生命周期。覆盖超过200条混合记录、同时间分页、跨页去重、权限、隐藏、无release、空页、非法请求和正文投影边界。浏览器在桌面与390px实际点击，检查失败重试、账号变更、清空、刷新持久化、旧记录可达、请求次数/响应字段和横向布局。

按原生release脚本同步构建验证，核对候选与原active文件数和关键页，再合入并推送uat、部署UAT。自动化属于开发自检，停在UAT等待用户亲自验收，未经明确通过不合入或部署main。
