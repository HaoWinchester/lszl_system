# 幻谱 PMP 备考官网首页设计

## 1. 背景与目标

当前系统根地址 `/` 会跳转到做题大厅，`/index.html` 则承载知识图谱编辑器。项目已经具备知识图谱、做题、知识归纳、深度回忆等完整学习能力，但缺少一个面向首次访问者的产品介绍页，无法在进入软件之前解释产品价值和备考方法。

本次新增「幻谱」官网首页，面向 PMP 备考学员，借鉴博思白板官网清晰的产品定位、分段展示和工作台直达方式，但不复制其品牌、素材、文案或具体页面。首页要在短时间内回答三个问题：

1. 幻谱解决什么备考问题；
2. 幻谱如何通过图谱、做题、归纳和回忆形成学习闭环；
3. 用户如何直接进入知识图谱开始使用。

## 2. 已确认决策

| 项目 | 决策 |
| --- | --- |
| 品牌名 | 幻谱 |
| 首要人群 | PMP 备考学员 |
| 核心定位 | 把零散知识点连成知识图谱，通过做题、归纳和主动回忆形成长期记忆 |
| 视觉方向 | A「知识生长型」 |
| 官网地址 | `/` |
| 主入口 | `/graph`，进入知识图谱 |
| 登录入口 | `/login` |
| 软件原页面 | `/index.html` 与 `workbench.html` 保持不变 |
| 产品展示 | 使用当前系统的真实界面截图 |
| 价格 | 首版不展示价格或会员套餐 |
| 社会证明 | 不虚构用户数、通过率、评价或合作机构 |

## 3. 范围

### 3.1 本次范围

- 新增官网页面 `landing.html` 及其独立样式和交互脚本；
- 将根地址 `/` 改为展示官网；
- 保留 `/graph` 到知识图谱的稳定跳转；
- 提供登录入口、锚点导航、移动导航、产品展示标签和 FAQ 手风琴；
- 使用知识图谱、做题模式、知识归纳和深度回忆的真实界面素材；
- 随 `new-legacy` active release 链路同步、构建、预览、验证和发布；
- 增加路由、静态契约、交互、响应式和发布门禁测试。

### 3.2 非目标

- 不修改 `legacy/` 源文件；
- 不重写知识图谱编辑器或现有学习页面；
- 不新增会员价格、支付或营销活动；
- 不新增账号体系、业务 API、数据库表或浏览器持久化；
- 不承诺尚不存在的 AI、实时协作或统计能力；
- 不把官网页面做成新的应用壳层，也不改变现有角色权限。

## 4. 视觉语言

### 4.1 概念

视觉主题为「知识生长」。页面不是传统培训机构的促销页，也不是泛用 SaaS 仪表盘，而是一张逐步展开的 PMP 知识网络。第一眼应传达温暖、理性、可信和可以立即动手的感觉。

最具记忆点的元素是由真实 PMP 考点组成的关系图。首屏以“关键路径、浮动时间、进度压缩、挣值分析”等节点演示知识从孤立卡片变成网络，并通过克制的生长动效呼应“幻谱”名称。

### 4.2 色彩和材质

| Token | 用途 | 建议值 |
| --- | --- | --- |
| `--landing-ink` | 深色背景、标题和主品牌 | `#153c34` |
| `--landing-paper` | 页面主背景 | `#f5f1e7` |
| `--landing-surface` | 卡片和截图容器 | `#fffdf7` |
| `--landing-accent` | 主行动、关键强调 | `#e45f35` |
| `--landing-gold` | 学习步骤和节点辅助色 | `#f5c668` |
| `--landing-muted` | 次级文本 | `#65756f` |
| `--landing-border` | 细边界 | `rgba(21, 60, 52, 0.14)` |

背景可使用极轻的纸张颗粒、圆形轨道和点阵关系网，不使用紫色渐变、玻璃拟态堆叠或与产品无关的抽象 3D 插画。容器圆角控制在 10–18px，阴影短而柔和。

### 4.3 排版

- 品牌和主标题强调中文阅读节奏，以清晰、有性格的中文标题字体栈为先；
- 正文使用项目可稳定加载的本地中文字体栈，不依赖外部 CDN；
- 主标题在桌面端保持强对比和短行长，手机端避免逐字强制换行；
- 不使用全站大写英文字距作为主要层级，英文眉题只作为小面积辅助。

### 4.4 动效

- 首屏节点按“中心节点 → 连线 → 相邻节点”顺序出现；
- 内容区块进入视口时做一次轻微上移和淡入；
- 产品标签切换只做短距离淡入；
- 导航吸顶时仅改变背景、边界和高度，不制造跳动；
- `prefers-reduced-motion: reduce` 下关闭节点生长、滚动渐入和平滑滚动，内容立即可见。

## 5. 页面信息架构

页面顺序固定如下：

1. 顶部导航；
2. 首屏定位；
3. PMP 痛点共鸣；
4. 学习闭环；
5. 真实产品展示；
6. 学习方法说明；
7. 常见问题；
8. 终态行动区；
9. 页脚。

### 5.1 顶部导航

左侧为「幻谱」品牌标识。中部锚点为“为什么选择幻谱”“备考闭环”“产品体验”“常见问题”。右侧为次级入口“登录”和主按钮“进入知识图谱”。

桌面端滚动后转为轻量吸顶栏。手机端使用明确的菜单按钮展开同一组入口；展开后支持再次点击关闭、点击页面空白关闭和 `Escape` 关闭。页面内锚点跳转后，焦点应落到目标区块或保持符合键盘预期的位置。

### 5.2 首屏定位

主标题：

> 把零散知识点，连成一张会生长的图谱。

说明文案：

> 为 PMP 备考打造的知识图谱学习平台。从理解、做题到主动回忆，让每一个知识点都找到位置。

主按钮为“免费进入知识图谱”，跳转 `/graph`。次按钮为“看看如何备考”，滚动到学习闭环。右侧或背景展示 PMP 节点关系图，不使用虚构软件界面。

“免费”只表达进入知识图谱不要求先完成支付，不表达所有会员能力永久免费；如上线政策与该表述冲突，应改为“进入知识图谱”。

### 5.3 痛点共鸣

标题：

> PMP 难的不是内容多，而是知识始终没有连起来。

展示三项真实痛点：

- 看完就忘：章节学完后，面对情境题想不起对应知识；
- 错题零散：做过很多题，错误原因没有回到知识体系；
- 复习失焦：不知道哪里薄弱，只能反复从头翻书。

### 5.4 学习闭环

以四步横向流程解释产品方法：

1. 构建图谱：看见过程、原则和知识领域之间的关系；
2. 做题验证：在真实情境中检验理解，而不是背答案；
3. 归纳错因：把题目、线索和易错点放回知识网络；
4. 主动回忆：脱离答案重建路径，形成长期记忆。

桌面端横向表达，手机端改为纵向时间线。箭头和步骤编号只表达顺序，不作为可点击控件。

### 5.5 真实产品展示

使用四个标签展示当前系统真实界面：

| 标签 | 对应页面 | 展示重点 |
| --- | --- | --- |
| 知识图谱 | `/index.html?mode=free` | 知识节点、关系线、画布与图谱结构 |
| 做题模式 | `/practice-mode.html` | 学习入口、题目训练和答题反馈 |
| 知识归纳 | `/question-workspace.html` | 多题对比、线索归纳和关系整理 |
| 深度回忆 | `/knowledge-recall.html` | 主动回忆、节点联想和掌握反馈 |

截图必须来自当前 active release 对应的真实页面，不使用外部素材或手绘成假界面。截图中不得出现敏感账号、个人数据或测试密钥。首张首屏需要的图谱截图可优先加载，其余截图延迟加载。

标签为真实交互：点击后更新选中态、说明文案、图片、替代文本和 `aria-selected`，方向键可在标签间切换。图片加载失败时显示该功能的文字说明和“进入知识图谱”按钮，不留下破图图标。

### 5.6 学习方法说明

说明每项产品操作对应的学习行为：

- 用关系理解知识，而不是孤立背诵；
- 用题目暴露误区，而不是追求刷题数量；
- 用主动回忆检验掌握，而不是反复阅读。

此处只解释普遍学习方法，不使用未经来源验证的效率倍数、通过率或医学化结论。

### 5.7 FAQ

首版包含四个问题：

1. 没有整理过知识图谱，可以直接开始吗？
2. 幻谱适合哪个阶段的 PMP 学员？
3. 需要安装软件吗？
4. 我的学习内容会自动保存吗？

FAQ 使用原生按钮语义或等价的可访问手风琴。每项支持展开、收起、键盘聚焦和明确的 `aria-expanded` / `aria-controls` 关系。答案必须与实际上线能力、登录状态和保存机制一致，不把访客临时体验描述为永久保存。

### 5.8 终态行动区和页脚

终态标题：

> 从第一个知识点开始，让备考真正连起来。

按钮“进入知识图谱”跳转 `/graph`。页脚包含品牌说明、登录入口和帮助中心；不新增无内容的“关于我们”“客户案例”或社交媒体占位链接。

## 6. 技术架构

### 6.1 文件边界

官网进入 `new-legacy` 源目录并经过正式同步、构建和 active release 发布：

- `new-legacy/landing.html`：语义化页面结构；
- `new-legacy/styles/landing.css`：官网独立样式，所有选择器置于 `.landing-page` 或同等命名空间下；
- `new-legacy/src/landing.js`：导航、产品标签、FAQ 和渐入增强；
- `new-legacy/assets/landing/`：经过压缩的真实界面截图及必要的本地图形资源；
- `new-legacy/tests/`：静态契约测试和浏览器交互测试。

不得修改 `legacy/`。官网样式不得污染 `index.html` 或其他业务页。

### 6.2 路由

后端 `backend/app/web/routes.py` 的根路由从 307 跳转改为返回 active release 中的 `landing.html`。官网是公开页面，不要求登录，也不需要注入业务 bootstrap；响应使用与 active release 页面一致的安全和缓存头。

稳定入口保持如下：

| URL | 行为 |
| --- | --- |
| `/` | 返回 active release 的 `landing.html` |
| `/graph` | 307 跳转 `/index.html?mode=free`，保留请求查询参数 |
| `/login` | 307 跳转 `/practice-mode.html?auth=login`，保留允许的查询参数 |
| `/index.html` | 继续返回知识图谱编辑器 |
| `/workbench.html` | 继续返回知识图谱兼容页面 |

`/__preview/{version}/` 应同步预览候选版本的 `landing.html`，便于发布前直接验收官网；候选版本内相对资源继续由既有 preview asset 路由提供。

### 6.3 数据和状态

官网不新增业务数据。移动菜单、当前产品标签和 FAQ 展开项均为当前页面生命周期内的 UI 状态，不写入 `localStorage`、`sessionStorage`、IndexedDB 或后端数据库。

链接使用普通可导航 URL，保证 JavaScript 失败时仍能进入知识图谱和登录。JavaScript 只做渐进增强；关闭脚本时全部正文、截图、FAQ 答案和关键入口仍可访问。

### 6.4 真实截图生产

截图在实施阶段通过受控浏览器从当前 active release 页面生成，统一使用无敏感数据的演示账号或安全种子数据。每张截图应记录来源页面、视口和生成日期，裁切到有代表性的产品区域。

优先使用 WebP 或 AVIF，并保留兼容格式或 `<picture>` 回退。按实际展示尺寸生成桌面和窄屏候选资源，避免把超大原图直接缩放。截图更新属于产品版本变更，应随 release 构建纳入文件数和关键资源校验。

## 7. 交互状态与失败恢复

| 功能 | 正常路径 | 反向或失败路径 | 恢复路径 |
| --- | --- | --- | --- |
| 主行动按钮 | 跳转 `/graph` | 路由目标不可用时由服务器返回明确错误 | 浏览器返回官网，页面状态不损坏 |
| 登录 | 跳转 `/login` | 登录服务失败由现有登录流程反馈 | 返回官网或重新尝试登录 |
| 锚点导航 | 定位相应区块 | 禁用 JS 时使用原生锚点 | 浏览器原生回退可用 |
| 移动菜单 | 展开、导航、关闭 | 重复点击不产生多个菜单或锁住滚动 | 再次点击、点击空白或按 `Escape` 关闭 |
| 产品标签 | 更新图片、说明和选中态 | 图片缺失或解码失败 | 显示文字回退和产品入口，可继续切换标签 |
| FAQ | 展开和收起答案 | 重复点击不丢焦点或出现重复内容 | 再次点击收起，键盘可继续访问下一项 |
| 渐入动画 | 内容进入视口时显示 | 不支持 IntersectionObserver 或关闭动效 | 内容默认可见，不依赖动画解锁 |

## 8. 响应式与可访问性

- 桌面端以非对称首屏和横向学习闭环建立视觉记忆；
- 平板端减少节点图占比，保持主标题和行动按钮优先；
- 390px 手机端使用单列，主文案先于装饰图，学习步骤转为纵向；
- 移动导航展开后不遮挡关闭入口，不出现水平滚动；
- 所有交互元素具有可见焦点态，触控目标不小于约 44px；
- 标题按 `h1` → `h2` 层级组织，地标使用 `header`、`nav`、`main`、`section`、`footer`；
- 产品截图提供描述其功能的替代文本，纯装饰线条和纹理隐藏于辅助技术；
- 颜色对比满足正文和控件可读性，信息不只依赖颜色传达；
- 支持键盘访问、减少动效偏好和 200% 页面缩放下的基本可用性。

## 10. 测试与发布计划

### 10.1 静态契约测试

- `landing.html` 引入独立 CSS 和 JS；
- 所有“进入知识图谱”链接指向 `/graph`；
- 登录链接指向 `/login`；
- 页面不包含价格、虚构用户数、通过率或评价；
- 四个产品标签、真实截图资源、FAQ、语义区块和替代文本存在；
- 不使用外部 CDN、业务数据浏览器存储或通用占位点击处理。

### 10.2 后端路由测试

- `/` 返回官网且状态码为 200；
- `/graph` 仍按现有契约跳转图谱并保留查询参数；
- `/login` 仍打开登录流程；
- `/index.html`、`workbench.html`、`practice-mode.html`、`question-workspace.html` 和 `knowledge-recall.html` 继续可访问；
- preview 根路径返回候选版本官网；
- active release 缺少 `landing.html` 时，根路由明确返回 503，不降级为旧首页或模糊的 404。

### 10.3 浏览器控制矩阵

逐一点击并验证：

- 桌面导航的四个锚点、登录和主 CTA；
- 手机菜单开关、每个菜单项、空白关闭和 `Escape`；
- 四个产品标签的鼠标、键盘和重复点击；
- 四个 FAQ 的展开、收起、连续操作和焦点顺序；
- 首屏及终态所有 CTA；
- 图片正常加载和强制加载失败两种状态；
- 390px、平板和桌面视口；
- `prefers-reduced-motion` 开启；
- JavaScript 禁用后的链接和内容可访问性。

### 10.4 视觉与性能验收

- 对桌面、平板和 390px 手机端生成基准截图；
- 检查首屏没有水平滚动、遮挡、截断或字体跳动；
- 真实产品截图在常见 DPR 下清晰但不过度增大体积；
- 首屏只预加载必要资源，非首屏图片延迟加载；
- 不因首页引入外部运行依赖；
- 对首页做一次键盘和“好奇用户”手工遍历。

### 10.5 发布纪律

正式发布使用：

```text
node frontend/scripts/manage-new-legacy.js update new-legacy --skip-browser
```
