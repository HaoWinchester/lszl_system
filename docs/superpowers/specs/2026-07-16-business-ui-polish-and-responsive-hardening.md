# 业务页面 UI 精修与响应式加固设计

## 目标

在不修改业务 API、权限、数据结构和图谱 iframe 引擎的前提下，将文件管理、题库、训练、回忆、用户管理、系统设置和会员页收敛为一套克制、可信、适合高频操作的专业工作台，并解决当前移动端首屏不可用、导航重复、弱化文字对比不足和触控目标过小的问题。

## 已确认的设计方向

- 图谱编辑器继续保持现有博思白板式无限画布，不修改 `legacy/` 源码及其业务行为。
- 业务页面采用“精密工具型工作台”：冷灰画布、白色工作面、蓝色仅用于主操作与选中态、8–12px 圆角、清晰边界和极少量短阴影。
- 保持系统字体和紧凑信息密度；标题用于定位当前任务，不使用营销页式超大字号、渐变、玻璃卡片或装饰性入场动画。
- 页面优先展示当前任务。统计、帮助、系统级导航在手机端必须让位于文件、题目、用户、训练和回忆操作。
- 所有操作图标继续通过 `AppIcon` 使用同一套 Lucide 语义映射。

## 页面结构

### 文件管理

- 桌面端保留侧栏、顶部工具栏、文件工作区和详情面板。
- 小于 800px 时改为真实可用的只读文件浏览：品牌栏恢复正常高度，文件列表立即出现在首屏；隐藏创建、导入、删除、拖放等复杂编辑入口。
- 显示常驻但不遮挡内容的“移动端仅支持查看”提示，并提供关闭入口。
- 文件卡仍可打开图谱；详情、排序、搜索、网格/列表切换保持可用。

### 题库

- 只保留一套主导航。桌面端使用左侧导航，移动端把同一套导航变为横向/网格入口，不再在工作区内重复三枚相同标签。
- 当前题库、题量和账号信息并入工作区标题上下文行，移除独立悬浮状态卡。
- 工作区、标注区和检查区不再层层套卡；边界只用于真正独立的交互区域。

### 用户管理

- 桌面端保持列表、编辑区和辅助面板三栏。
- 手机端将用户列表放到统计摘要之前；统计改为紧凑 2×2 摘要，避免首屏只看到四张大卡。
- 顶部次级操作允许折行，但主要“新用户”操作始终可见。

### 训练与回忆

- 手机端保留返回、身份、当前任务和必要工具；题库、用户、系统设置等后台入口收进可展开的“管理入口”。
- 训练字号按钮和回忆缩放按钮保持 28–32px 图标视觉，但点击热区达到 44px。
- 无试卷、未选择题库、未开始回忆时展示包含下一步动作的空状态，不留下无解释的大面积空白。

### 系统设置与会员

- 系统设置手机端使用横向可滚动标签栏，不再铺成两列按钮矩阵。
- 角色主题编辑器显示色块预览、颜色值和清晰标签；保存按钮使用统一工作台按钮样式。
- 会员弹窗固定头部和关闭操作，方案区独立滚动；移动端关闭按钮、兑换和购买按钮使用 44px 点击热区。

## 设计系统与无障碍

- `--kg-muted` 调整到在白色与画布背景上均达到正文 4.5:1 对比度；为禁用态单独保留更浅颜色，避免用正文弱化色承担禁用表达。
- 增加桌面紧凑控制尺寸与触摸热区令牌。指针精确设备可保持 32–36px，`pointer: coarse` 或移动断点下关键操作至少 44px。
- 保留全局 `focus-visible` 和 `prefers-reduced-motion`；移除跨页面无语义的按钮上浮动画。
- 任何纯图标按钮必须有 `aria-label` 或 `title`；空状态按钮必须执行真实导航或状态变化。

## 样式边界

- `design-system.css` 只放全局颜色、尺寸、层级、交互状态和触控规则。
- `boardmix-overrides.css` 只保留必要的跨页面兼容修正，不再承载页面布局和无差别按钮动画。
- 页面布局和断点规则分别留在 `file-manager.css`、`question-bank-admin.css`、`question-training.css`、`knowledge-recall.css`、`user-management.css`、`system-settings.css` 和 `subscription.css`。
- 不修改 `legacy/`；不改变 API、路由、权限和数据库数据来源。

## 验收标准

1. 390×844 下 `/files` 首屏显示品牌栏、只读提示和文件内容，不出现空白 100vh 侧栏。
2. 业务页在 390、768、1024、1440px 下无根级横向溢出。
3. 题库只有一套主导航；用户管理手机端首屏可看到用户列表入口或列表内容。
4. 移动端关键点击目标至少 44px；正文弱化文字对比度不低于 4.5:1。
5. 训练与回忆的空状态说明下一步；会员弹窗可关闭、可滚动且 CTA 可点击。
6. 无未命名交互控件、浏览器控制台错误或 React 运行时警告。
7. `pnpm test:design`、`pnpm exec tsc -b`、`pnpm build` 与后端测试全部通过。
