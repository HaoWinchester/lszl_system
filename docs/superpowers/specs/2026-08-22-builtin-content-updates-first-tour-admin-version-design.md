# 内置教学数据可更新、首次引导与后台版本标识设计

## 背景与现状证据

UAT 已安装三份 PMP 内置数据，但管理页和领域数据库仍存在双轨数据源：

- `admin-subjects.html` 通过旧 runtime 仓库读取 `taxonomy-pmp-main`，因此显示 12 个知识点。
- `/api/v1/content-prep/shared-content?subjectId=PMP` 返回的领域数据已是 `taxonomy-pmp-complete-v1`，共 317 个节点。
- 内置联想库已有 471 个节点和 2,840 条关系，但它因版本冲突被安装为 v2；现有导入发布链路仍更新 v1，学习端继续读取 v2，造成“发布成功但内容未更新”。
- 8 条原则和 8 张归纳卡已在领域表中，但启动 seed 会将人工导入的修改重置为项目内的 JSON。
- 首页引导在服务端 runtime 快照载入之前就检查“已看”标记，每次都误判为首次进入。

## 目标

1. 三份数据仍然是项目内置数据，新环境和新账号无需上传即可使用。
2. 内置数据是初始默认基线，不是不可更改的强制快照。
3. 管理员通过现有导入界面发布新版后，新版成为服务端当前版本，重启和后续部署不得回滚。
4. 新建试卷读取当前已发布教学数据；已发布试卷、题目和发布快照不受影响。
5. 首页教程每个账号只自动展示一次，帮助中心仍可手动重播。
6. 所有管理后台页面顶部显示当前实际发布版本。

## 方案比较

### 方案 A：领域数据库为权威源，内置数据仅做缺失补齐（采用）

- 知识树、联想库和原则卡都从领域 API 读取。
- seed 只在基线记录不存在时创建，不再覆盖现有记录。
- 当前版本由服务端显式指针选择，不再根据“更新时间最新”或“版本号最大”猜测。
- 优点：重启不回滚，页面与学习端一致，可测试、可审计。
- 代价：需要将知识树管理页从旧 runtime 仓库接到现有领域 API。

### 方案 B：领域表与 runtime 数据双向镜像

- 保留现有页面的 runtime 读写，后台定时双向复制。
- 优点：页面修改较少。
- 缺点：仍有双权威源和覆盖竞态，无法从根本上避免本次问题。

### 方案 C：继续每次启动强制恢复内置 JSON

- 优点：实现最简单。
- 缺点：人工导入无法长期生效，与已确认的需求相反。

## 数据所有权与版本规则

### 内置基线

- 内置 JSON 继续包含在 `backend/app/seed/builtin_teaching_content/`。
- 启动时检查知识树基线、联想库基线、原则和归纳卡是否缺失。只创建缺失项，不覆盖同 ID 数据。
- 内置知识树和联想库保留为可追溯版本。人工发布新版时不删除它们。
- 内置原则卡 JSON 作为可重新导入的基线文件；人工导入只改服务端当前配置和审计记录，不反向修改项目文件。

### 当前版本指针

- `ContentSubject.content_metadata` 保存 `currentTaxonomyId` 和 `currentRecallLibraryId`。
- 读取知识树和联想库时优先按指针获取；旧数据没有指针时，仅做一次兼容回退并写回指针。
- 首次安装且没有当前指针时，seed 把内置基线设为当前版本。
- 管理员发布新版后，在同一数据库事务中切换指针、写审计记录并提升内容修订号。

## 管理端读写流程

### 知识树

1. `admin-subjects.html` 启动后从服务端获取科目、当前知识树和版本列表，不再把前端默认的 12 节点树当成权威数据。
2. 导入 JSON 时服务端校验格式、节点 ID、父子引用和版本冲突，保存为新草稿版本。
3. 点击“设为当前”后才切换 `currentTaxonomyId`。旧当前版本保留在历史列表。
4. 管理页、嵌入式知识树工作区、联想库关联下拉框和学习端使用同一当前指针。

### 科目级联想库

1. 保留“导入检查 → 加入草稿 → 发布启用”界面和操作语义。
2. 草稿保存到服务端，不仅保存在当前浏览器。
3. 发布时创建或更新目标版本并切换 `currentRecallLibraryId`，不再固定更新 v1。
4. 联想节点与当前知识树稳定 ID 对齐后，管理页的“未关联知识点”指标使用 317 节点树重新计算。

### 原则与归纳卡

1. 保留现有组合 JSON 导入入口。
2. 导入前完整校验原则/归纳卡一对一引用和题目引用冲突。
3. 用户确认导入后在一个服务端事务中更新当前原则与卡片，写审计和内容修订号。
4. 启动 seed 不再恢复同 ID 内容，因此导入更新在重启和部署后仍然有效。

## 新建试卷与历史数据

- 新建试卷的知识树、联想库和原则配额从当前已发布内容读取。
- 导入、发布或切换当前版本不修改 `questions`、`exam_papers`、`paper_releases` 或 `paper_release_questions`。
- 已发布试卷继续读取发布时快照。仅后续新建或重新配置的试卷使用新当前数据。

## 首页教程仅自动显示一次

- 新增按账号原子领取的首次引导状态，服务端在账号级 runtime 记录中保存“已领取”标记。
- 首次进入首页时，领取成功才自动显示教程；之后同账号在任何设备上都不再自动显示。
- “跳过”、点击遮罩关闭、按 Escape 和完成教程都属于该次已展示，不会下次重弹。
- 帮助中心使用 `startGuidedTour(true)` 手动重播，不改变自动展示状态。
- 领取请求失败时不自动打开遮罩，避免每次进入都打扰用户；帮助中心仍可用。

## 后台顶部版本号

- 共享后台 UI 脚本在 `.admin-topbar` 中注入一枚紧凑版本标识，覆盖总览、科目、教师工作台、课程、用户、反馈、消息、操作记录和系统设置页。
- 版本值从发布脚本注入的 `document.documentElement.dataset.release` 读取，例如 `v9.0-p4.1.134`；不在业务 JS 中手写固定版本。
- 仅增加文字标识，不改后台导航、账号胶囊、DOM 主结构和原有视觉层级。

## 错误处理

- 导入解析失败、节点引用无效、版本冲突或题目引用冲突时，整个服务端事务回滚，当前版本指针不变。
- 草稿保存失败时页面保留当前编辑内容和重试入口，不显示虚假“保存成功”。
- 发布修订号冲突时提示用户重新载入后再发布。
- 管理页服务端读取失败时显示明确错误态，不回退成 12 节点的前端示例数据。

## 测试与验收

### 后端测试

- 空库启动会安装 317 节点知识树、471/2,840 联想库以及 8/8 原则卡数据。
- 人工发布后再执行 seed，人工版本和当前指针不变。
- 知识树草稿发布、联想库草稿发布和原则卡原子导入都能修改服务端当前数据。
- 重启后保持人工版；发布失败时当前版和修订号不变。
- 教程原子领取对同一账号仅第一次返回 `claimed=true`，跨会话、跨浏览器均为 `false`。
- 上述任何操作都不修改已发布题目、试卷和发布快照。

### 前端与浏览器验收

- UAT `admin-subjects.html` 的 PMP 当前知识树显示 317 个节点，不再显示旧的 12 个节点。
- 联想库显示 471 个节点、2,840 条关系，并能按当前 317 节点知识树识别关联。
- 导入一个只改动可识别字段的测试版，发布、刷新、重新登录和重启 UAT 后仍显示新值；验收后恢复测试数据。
- 新账号首次进入首页自动显示教程；关闭后刷新、重新登录和另一浏览器均不再自动显示；帮助中心手动重播正常。
- 遍历所有管理后台页，版本标识与 HTML `data-release` 一致，且不挤压账号菜单。

## 非目标

- 不改首页引导教程的步骤、文案或样式。
- 不重新设计管理后台布局。
- 不自动修改项目内置 JSON 文件；项目文件由维护者手动替换。
- 不对既有已发布试卷或题目做批量迁移。
