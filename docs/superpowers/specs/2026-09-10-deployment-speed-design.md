# 部署提速

用户已确认按部署分析结论优化。基线 UAT a2f2c8d，独立工作树 codex/deployment-speed。

目标：复用相同输入的完整验证，避免文档和工作树路径引起重复执行；保留备份、关键页面/文件数校验、失败阻断、用户 UAT 验收边界。Docker 和数据库架构不变。

选择在现有 release 管理器上局部优化。暂不迁移 systemd，不扩大未被浏览器测试覆盖的页面白名单。

1. 验证指纹使用相对路径，对同内容不同 checkout 可复用。只排除明确的非执行性运维记录（docs/superpowers、docs/verification）；其他文档、未知路径、后端/迁移/依赖/测试/部署配置变化继续失效。绑定实际候选 source/site 内容，拒绝损坏产物复用；运行环境指纹至少包括 Node/Python 版本、平台和架构。旧证据不自动信任。
2. UAT 现有做题快速路径允许伴随上述运维记录变更；不允许单独文档/产物/后端变更绕过完整检查。
3. 通用 Bash 计时模块供 UAT、生产脚本与 release 验证脚本复用。记录阶段、秒数、失败退出码及总时长，不打印命令参数/密钥。详细发布验证日志实时可查。保留各脚本的失败和清理语义。
4. 发布时继续用正式管理器；复用经过同样输入校验的不可变包。提交源与生成物，合入并推送 UAT 后部署，等待用户验收，禁止推送 main。

验证：先用隔离 Git 仓库/本地 release 夹具证明跨路径缓存复用及代码/产物变更失效；部署脚本模拟检查失败阻断与计时；运行 frontend pnpm test；执行真实 UAT 完整发布一次记录各阶段，随后同输入复核缓存复用。不能把自动化成功算作用户 UAT 验收。
