# 多选题专项试卷设计

- 日期：2026-08-31
- 状态：已获用户设计批准，待实施计划
- 范围：多选题录入与导入、多选题专项试卷、发布快照、四种练习玩法、错题与复仇闭环
- 明确不在本期：连线题、Excel/CSV 题库导入、普通试卷混入多选题、部分得分

## 1. 背景与目标

当前题库界面虽然列出了 `multiple_choice`，后端内容准备服务也能识别部分多选答案形式，但题目编辑器仍以单选框设置唯一正确答案，练习页只提交单个 `selectedAnswer`，前后端也按单字符串完全相等判分。因此当前状态只是局部数据兼容，不是可用的端到端多选题能力。

本期目标是在不复制试卷系统的前提下，新增独立的“多选题试卷”，并完整贯通：

1. 教师手工录入多选题；
2. 单题/批量文本粘贴和题库 JSON 导入；
3. 只从多选题池组卷；
4. 发布时冻结题型和正确答案集合；
5. 学生在普通练习、挑战、学霸、复仇四种玩法中作答；
6. 后端按答案集合完全匹配判分；
7. 错题进入复仇、补救和验证闭环；
8. 历史单选题、普通试卷、会话、成绩和发布快照保持兼容。

成功标准是：正确选项集合完全一致才得分；少选、多选、错选均计 0 分；选项点击顺序不影响结果。

## 2. 已确认的产品规则

### 2.1 试卷边界

- 新增试卷类型 `multiple_choice`，产品名称为“多选题试卷”。
- 现有试卷类型记为 `standard`，产品名称保持“普通试卷”。
- `standard` 试卷不能加入多选题；`multiple_choice` 试卷不能加入其他题型。
- 只有尚未加入题目的未发布草稿可以切换试卷类型。
- 一旦加入题目或已有发布版本，试卷类型锁定。
- 历史试卷默认物化为 `standard`，不迁移题目、不重发版本、不重新判分。

### 2.2 多选题结构

- 每题 3–8 个选项。
- 选项 ID 必须非空且唯一。
- 至少 2 个正确选项。
- 至少保留 1 个错误选项。
- 正确答案以选项 ID 数组表达，不以字符串拼接作为新数据契约。
- 完整解析字段为 `analysis`，发布前必填。
- 选项级错误原因字段为 `trap`，可选，用于错选反馈和复仇补救。

### 2.3 判分规则

- 规范正确答案为 `correctOptionIds: string[]`。
- 规范学生答案为 `selectedOptionIds: string[]`。
- 比较前按冻结题目中的选项顺序规范化并去重。
- 只有两个集合完全一致时 `correct=true`。
- 少选、多选、错选、未确认、未作答和超时均不得分。
- 前端可以镜像判分以提供即时反馈，但最终成绩、生命值、经验、错题和复仇状态只能由后端根据发布快照权威计算。

## 3. 方案选择

采用“扩展现有试卷体系并引入统一答案集合契约”的方案。

不采用以下方案：

- 在现有单选逻辑中到处增加 `multiple_choice` 条件并继续使用 `"AC"`。该方式会产生顺序、多字符选项 ID、复仇记录和分支重复问题。
- 新建独立的多选考试系统。该方式会复制题库、组卷、发布、权限、会话、成绩和错题系统，维护成本过高。

目标链路如下：

```text
多选题录入/导入
        ↓
统一题库（type=multiple_choice）
        ↓
多选题试卷（paperType=multiple_choice）
        ↓
不可变发布快照（correctOptionIds + analysis）
        ↓
普通练习 / 挑战 / 学霸 / 复仇
        ↓
后端答案集合判分
        ↓
成绩 / 错题 / 补救 / 延迟验证
```

## 4. 数据模型与兼容契约

### 4.1 题目

在 `questions` 增加 `correct_answer_ids` JSONB，应用层名称为 `correctOptionIds`，默认空数组。现有 `correct_answer` 字段保留用于历史单选兼容。

规范写入规则：

- `single_choice`：新旧接口均可读取；规范读取结果为单元素数组。现有写入方式不在本期强制迁移。
- `multiple_choice`：必须写入 `correctOptionIds`；不得只写入拼接字符串。
- 多选题的 `correct_answer` 可以为空，不作为权威答案。
- `options[*].correct` 只作为兼容展示字段，返回时可由 `correctOptionIds` 派生，不作为多选题持久化真值。

历史多选兼容：

- 若旧题只有 `correctAnswer: "AC"`，且所有选项 ID 均为单字符、每个字符都引用现有选项、答案至少包含两个不同选项，则可确定性转换为 `["A", "C"]`。
- 若无法无歧义转换，则题目保留但标记为内容不完整，禁止加入多选题试卷和发布，不猜测答案。

### 4.2 试卷与发布版本

- `exam_papers` 增加 `paper_type`，只允许 `standard`、`multiple_choice`，历史行默认 `standard`。
- `paper_releases` 同步增加 `paper_type`，发布时从草稿冻结。
- 试卷创建、更新、导入、导出和目录响应统一使用 `paperType`。
- 发布快照保存 `type`、`correctOptionIds`、完整选项、选项顺序、`analysis`、可选 `trap` 和题目分值。
- 已发布快照保持不可变；原题后续修改不影响历史会话与成绩。

### 4.3 练习会话

`PracticeSession.answers` 已是 JSONB，不新增关系表。多选答案条目使用：

```json
{
  "selectedOptionIds": ["A", "C"],
  "selectionIndex": 3
}
```

超时条目使用：

```json
{
  "selectedOptionIds": [],
  "selectionIndex": 3,
  "timedOut": true
}
```

历史单选条目继续支持 `selectedAnswer`。兼容层将其读取为单元素集合，但历史存储不批量改写。

尚未点击“确认答案”的选择不是正式答案。为支持切题、保存退出和恢复，在 `runtimeState.pendingSelections` 中保存：

```json
{
  "question-id": ["A", "C"]
}
```

后端必须校验题目归属和选项合法性，但 `pendingSelections` 永远不参与已答数量、判分、经验或错题计算。确认后从 pending 中删除并写入锁定答案。最终交卷时仍留在 pending 的选择按未作答计 0 分。

### 4.4 错题与验证

- `PracticeMistake.selected_answers` 继续使用现有 JSONB，但语义明确为“最近一次真实错误选择集合”。
- 单选错题仍为 `["B"]`，多选错题可为 `["A", "C"]`。
- 超时不伪造成真实选项集合。
- 错题 API 新增 `previousWrongOptionIds`；现有 `previousWrongAnswer` 保留给历史单选客户端。
- `PracticeVerification` 增加 `selected_answer_ids` JSONB；旧 `selected_answer` 保留用于历史单选验证记录。

## 5. 公共能力边界

### 5.1 后端答案集合服务

新增职责明确的公共模块，供内容准备、题库、发布、练习会话和学习错题服务统一调用。该模块负责：

- 从新旧载荷解析规范答案集合；
- 按题目选项顺序去重和规范化；
- 验证未知、重复和空选项 ID；
- 校验多选题 3–8、至少 2 对、至少 1 错规则；
- 判断集合是否完全一致；
- 计算 `correctSelectedIds`、`missedCorrectIds`、`wrongSelectedIds`；
- 为导入去重生成与答案顺序无关的规范签名；
- 为历史单选和旧拼接答案提供窄兼容入口。

路由只负责参数、权限和响应编排，不得自行实现集合比较。

### 5.2 前端答案集合核心

在 `new-legacy/src/` 新增共享答案集合模块，供题目编辑器、导入预览、试卷预览和学生作答统一调用。该模块负责：

- 选项集合规范化；
- 合法性提示；
- 与后端同构的本地集合比较；
- 漏选和错选差异计算；
- 新旧题目载荷兼容读取。

练习页的多选交互应放入独立控制器，不继续把所有状态塞进 `100-practice-mode.js`。控制器只维护勾选、待确认、确认锁定和视图反馈；会话编排仍由现有练习模式负责。

## 6. 教师端设计

### 6.1 手工录入

- 题型切换为“多选题”时，正确答案控件由 radio 切为 checkbox。
- 选择状态实时显示“已设置 N 个正确答案”。
- 增删选项后重新校验正确答案集合，不静默选择默认答案。
- 草稿可暂时缺少解析，但发布就绪状态必须要求 `analysis` 非空。
- 保存时前端提示所有结构错误，后端再次执行相同结构校验；缺少 `analysis` 只把题目标记为未达到发布条件，不阻止保存草稿。
- 题目列表和预览明确显示“多选题”、全部正确答案和完整解析。

### 6.2 文本粘贴导入

首期支持现有单题粘贴和批量粘贴入口，不新增 Excel/CSV。模板示例：

```text
【题型】多选题
【题干-中文】以下哪些说法正确？
【A-中文】……
【B-中文】……
【C-中文】……
【D-中文】……
【答案】A,C
【解析-中文】A、C 正确；B、D 不符合题干条件。
```

文本解析接受 `A,C`、`A，C`、`A C` 和无歧义的 `AC`。解析后立即转换为数组，后续流程不再传播拼接字符串。

### 6.3 JSON 题库导入

规范模板：

```json
{
  "type": "multiple_choice",
  "title": "示例多选题",
  "stemParts": [{"text": "以下哪些说法正确？"}],
  "options": [
    {"id": "A", "text": "选项 A", "trap": ""},
    {"id": "B", "text": "选项 B", "trap": "选择该项错误的原因"},
    {"id": "C", "text": "选项 C", "trap": ""}
  ],
  "correctOptionIds": ["A", "C"],
  "analysis": "A、C 正确。这里填写完整判断依据以及 B 错误的原因。"
}
```

导入行为：

- 预览显示题型、题干、选项、正确答案数量、具体正确项和解析。
- 每题独立报告未知选项、重复答案、正确项不足、没有错误项和选项数量越界；这些是阻止该题导入的结构错误。
- 缺少 `analysis` 作为发布就绪警告展示，允许题目以未就绪草稿导入，但后续不能进入发布版本。
- “仅导入解析通过的题目”开启时只提交合法题；关闭时任一失败阻止整批写入。
- 重复检测使用规范化答案集合，`["A","C"]` 与 `["C","A"]` 视为同一答案。
- 导入不得静默丢弃第二个及后续正确答案。

### 6.4 试卷管理

- 复用现有试卷管理页面，不新增独立管理页。
- 新建时选择“普通试卷”或“多选题试卷”。
- 多选题试卷的题目选择器和自动组卷候选池固定过滤 `type=multiple_choice`。
- 前端隐藏不符合题型的候选只是体验优化；后端在替换题目、导入试卷和发布时均重新校验。
- 空草稿允许切换类型；已有题目或已有发布版本时控件锁定并说明原因。
- 试卷导入包优先使用显式 `paperType`。旧包缺少该字段时：全部题目都是 `multiple_choice` 才推导为 `multiple_choice`；全部题目都不是 `multiple_choice` 才推导为 `standard`；混合题型直接拒绝，不猜测类型。

## 7. 发布校验

发布多选题试卷前，后端重新读取全部题目并逐题检查：

- 题目存在且未被安全删除；
- `type` 必须为 `multiple_choice`；
- 选项数量、唯一 ID、正确项数量和错误项数量合法；
- `correctOptionIds` 只引用现有选项；
- `analysis` 非空；
- 试卷至少包含一道题；
- 启用的学习模式合法。

错误响应包含稳定错误码、题目 ID、教师题号、试卷顺序和可读信息，教师端可定位具体问题。任何错误都阻止生成新发布版本。

## 8. 学生端作答设计

### 8.1 通用交互

- 多选题选项使用可访问的复选语义；点击只切换勾选状态，不立即判题。
- 每题显示“确认答案”按钮。
- 未选择任何选项时确认按钮禁用。
- 勾选但未确认的题目在答题卡标记为“待确认”，不算已答。
- 切换题目保留 pending 选择；保存退出后也可恢复。
- 确认后答案锁定，不能修改。
- 最终交卷时，pending 选择按未作答处理，并在交卷确认中明确提示数量。

### 8.2 确认后的差异反馈

- 选中且正确：绿色。
- 选中但错误：红色，标记“错选”。
- 未选但正确：橙色，标记“漏选”。
- 未选且错误：保持中性。
- 允许展示解析的模式显示完整 `analysis`；错选项存在 `trap` 时追加对应说明。
- 未确认前不得泄露正确答案数量或正确项。

### 8.3 四种玩法

- 普通练习：确认后立即显示集合判分、差异反馈和解析。
- 挑战模式：确认后按集合判分更新生命、连胜和经验；少选、多选、错选均作为一次错误。
- 学霸模式：确认或倒计时结束时锁定；超时保存空集合和 `timedOut=true`。
- 复仇模式：使用同一多选控制器，确认后进入错题状态机。

## 9. 复仇模式设计

### 9.1 错题进入复仇池

- 首次答错保存最近错误选择集合，例如 `["A", "C"]`。
- 全局复仇池的可用性检查必须理解多选正确答案集合，不能再要求正确答案是单个选项 ID。
- 复仇候选响应返回 `previousWrongOptionIds`。

### 9.2 复仇作答与补救

- 默认显示“上次选择：A、C”，学生可以关闭显示。
- 不提前显示正确答案或正确答案数量。
- 学生重新勾选并点击“确认答案”。
- 完全匹配时进入现有延迟验证阶段。
- 不匹配时进入补救阶段，展示选对、错选和漏选分类、完整 `analysis` 以及相关 `trap`。
- 每次错误覆盖“最近错误集合”，同时保留现有错误次数、复仇次数和时间统计。

### 9.3 验证题

- 多选错题的验证题必须也是 `multiple_choice`。
- 优先使用同题族中符合质量条件的另一道多选验证题。
- 没有合适的同题族候选时，延迟后重新使用原冻结题目，不得降级成单选验证题，也不得因缺少候选直接标记掌握。
- 验证仍采用完全匹配规则；通过后进入 mastered，失败后回到补救。

## 10. 并发、错误与安全边界

- 会话答案一旦确认即锁定；后续请求改变 `selectedOptionIds` 返回 409。
- 保存和交卷继续使用现有 revision 乐观并发控制。
- 后端拒绝不属于当前会话题目的答案、未知选项、重复选项和超长数组。
- 客户端提交的 `correct`、`correctOptionIds`、得分和差异分类一律忽略；真值来自冻结快照。
- `pendingSelections` 只能包含当前会话题目及其合法选项，并设置题目数、每题选项数和字符串长度上限。
- 发布和结算保持事务性；失败时不产生半个 release、不部分锁定答案、不部分推进错题状态。
- 只允许现有题库编辑、试卷管理和学习权限角色使用对应入口，题型扩展不放宽权限。

建议稳定错误码包括：

- `MULTIPLE_CHOICE_OPTION_COUNT_INVALID`
- `MULTIPLE_CHOICE_CORRECT_COUNT_INVALID`
- `MULTIPLE_CHOICE_NO_DISTRACTOR`
- `MULTIPLE_CHOICE_ANSWER_REFERENCE_INVALID`
- `MULTIPLE_CHOICE_ANALYSIS_REQUIRED`
- `PAPER_TYPE_QUESTION_MISMATCH`
- `PAPER_TYPE_LOCKED`
- `PRACTICE_SELECTED_OPTIONS_INVALID`
- `PRACTICE_ANSWER_LOCKED`

## 11. 测试策略

### 11.1 单元测试

公共答案集合：

- 点击顺序不同但集合相同；
- 重复、未知和空选项；
- 完全正确、少选、多选、错选；
- 未作答和超时；
- 单选兼容；
- 旧 `"AC"` 的安全转换与拒绝边界；
- 漏选、错选分类；
- 去重签名与答案顺序无关。

### 11.2 后端服务与 API 测试

- 手工保存多选题；
- Content Prep 和题库 JSON 导入；
- 部分导入、重复确认和事务回滚；
- 试卷类型创建、锁定和题型互斥；
- 自动组卷只选多选题；
- 发布校验和不可变快照；
- pending 保存/恢复与确认锁定；
- 四种模式的集合结算；
- 复仇池、补救、验证和掌握状态；
- 409 revision 冲突和答案改写拒绝；
- 历史单选会话、成绩和 release 兼容。

### 11.3 前端契约与浏览器测试

- 题目编辑器 checkbox、计数、增删选项和错误提示；
- 文本与 JSON 导入预览；
- 试卷类型选择、过滤、锁定和发布错误定位；
- 多选勾选、取消、切题、pending 标记、确认锁定；
- 保存退出、刷新和跨页恢复；
- 普通练习、挑战、学霸、复仇的完整流程；
- 移动端和键盘可操作性；
- 漏选/错选/解析/trap 的视觉反馈；
- 所有相关页的认证、权限和导航回归。

- 前端：`cd frontend && pnpm test`
- 定向设计契约：`cd frontend && pnpm test:design`
- 相关浏览器回归覆盖题库、试卷管理、练习和复仇入口。
- 正式前端 release 必须使用 `node frontend/scripts/manage-new-legacy.js update new-legacy --skip-browser`，不得手工覆盖 active release。
- promote 前核对候选 site 与 active site 文件数量及关键页面，遵守仓库发布纪律。

## 12. 实施分批

### 批次 A：答案契约与迁移

- 数据库字段与 Alembic 迁移；
- 后端答案集合服务；
- 前端答案集合核心；
- 新旧载荷兼容和基础单元测试。

### 批次 B：教师端与导入

- 多选题手工编辑；
- 文本与 JSON 导入；
- 预览、校验和去重；
- 多选题试卷类型、过滤、自动组卷和发布校验。

### 批次 C：学生端与复仇

- 多选作答控制器；
- pending、确认、保存与恢复；
- 四种玩法；
- 错题、补救、验证和报告。

### 批次 D：全链路回归与 release

- 后端、前端和浏览器全量验证；
- 历史兼容审计；
- active release 内容校验；
- 使用正式 release 管理脚本构建并 promote。

## 13. 最终验收清单

- 教师可以手工创建合法多选题。
- 教师可以通过单题/批量文本粘贴导入多选题。
- 教师可以通过题库 JSON 导入包含 `analysis` 的多选题。
- 非法题目不能保存为发布就绪状态，也不能进入 release。
- 可以创建只含多选题的专项试卷，且类型锁定规则生效。
- 普通试卷和多选题试卷不能互相混入题目。
- 学生可以在普通练习、挑战、学霸、复仇中勾选、确认、保存、恢复和交卷。
- 少选、多选、错选均为 0 分，答案顺序不影响判分。
- 普通练习和复仇补救正确显示 `analysis`，错选项可显示 `trap`。
- 多选错题可以进入复仇池并完成补救和多选验证。
- 历史单选题、普通试卷、发布版本、会话和成绩行为不变。
- 权威源、同步产物和 active release 保持一致。
