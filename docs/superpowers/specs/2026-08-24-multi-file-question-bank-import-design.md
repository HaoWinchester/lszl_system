# 多文件题库批量导入设计

## 背景

试卷管理页已经提供独立的“导入题库”和“导入试卷”入口。“导入题库”当前只读取文件选择器中的第一个 JSON 文件，但后端 `POST /api/v1/banks/import` 已支持在一个事务中接收多个题库，并对整批数据执行覆盖检查、重复题检查和全量回滚。

本次改动让用户可以在一次文件选择操作中导入多个题库 JSON，同时保留数据库作为业务数据唯一事实源，不引入 runtime state、`localStorage`、`sessionStorage` 或 IndexedDB 持久化。

## 范围

- 试卷管理页“导入题库 JSON”支持一次选择多个 `.json` 文件。
- 每个文件继续支持三种现有格式：单个 Prep Studio 题库对象、题库数组、`{banks: [...]}` 包装对象。
- 所有文件在浏览器内完成只读解析和预检后，将合并后的题库数组通过一次 `POST /api/v1/banks/import` 请求提交。
- 原题库管理页继续复用同一个公共导入控制器；其现有单文件入口不要求改成多文件 UI，但不能产生第二套解析或冲突处理实现。
- 不增加 ZIP 导入、目录扫描、拖拽上传或后台异步任务。

## 已确认规则

1. 一批文件中的任意文件解析失败、格式不受支持或属于试卷包时，整批禁止提交。
2. 所有文件有效后才启用“确认导入题库”。
3. 所有题库合并成一次 API 请求，后端事务保证全部成功或全部回滚。
4. 跨文件重复源题库 ID、重复源题目 ID 等业务冲突由现有后端校验统一拒绝，前端显示具体错误并保留可重试状态。
5. 同来源覆盖确认和重复题清理确认继续按现有顺序执行；确认参数作用于整批请求。
6. API 失败后不丢失已解析的文件和题库，可直接重试；取消或关闭后清空本次临时选择。
7. 导入成功后重新加载题库 API 数据，并刷新组卷候选题库。

## 前端设计

### 文件选择器

`#qbBankImportFile` 增加 `multiple` 属性，文案改为“选择一个或多个题库 JSON 文件”。

文件选择完成后，页面一次读取当前 `FileList` 的全部文件，并把以下数据传给公共控制器：

```text
[
  { name: "bank-a.json", text: "..." },
  { name: "bank-b.json", text: "..." }
]
```

### 公共控制器

`KGTeacherDomains.QuestionBankImportController` 增加批量加载入口：

```text
loadFiles(files: Array<{name: string, text: string}>): Promise<Result>
```

职责：

- 按文件顺序解析 JSON，并复用现有 `classify` 与 `normalizeBanks`。
- 保留题库及题目在各文件中的原始顺序。
- 汇总 `fileCount`、`fileNames`、`bankCount`、`questionCount` 和合并后的 `banks`。
- 任意文件失败时返回带文件名的错误，例如：`bank-b.json：JSON 解析失败……`。
- 失败状态不保留部分可提交的 `banks`，确认按钮必须保持禁用。
- 原有 `load(fileName, jsonText)` 保留，并委托给 `loadFiles`，避免破坏题库管理页和既有测试。
- `confirm()` 仍只调用一次 `api.importBanks(...)`。

### 用户界面

全部文件有效时显示：

```text
已选择 3 个文件
3 个文件 · 5 个题库 · 300 道题 · 格式识别成功
文件：bank-a.json、bank-b.json、bank-c.json
```

文件名过多时仍保留全部名称在可换行区域，不用浏览器持久化保存。

任一文件无效时显示带文件名的错误，隐藏成功汇总并禁用确认按钮。用户重新选择文件后整批重新解析，不拼接上一次选择。

## 数据流与事务

```text
多选 FileList
  -> 逐文件读取文本
  -> 公共控制器逐文件解析/分类/标准化
  -> 任一失败：整批停止，不调用 API
  -> 全部成功：合并 banks
  -> 一次 POST /api/v1/banks/import
  -> 覆盖确认 / 重复题清理确认（需要时）
  -> 后端单事务提交或回滚
  -> 重新加载题库目录与组卷候选
```

前端只保存本次弹窗生命周期内的解析结果；题库和题目正文只由数据库 API 持久化。

## 错误与恢复

| 场景 | 页面行为 | API 行为 | 恢复方式 |
|---|---|---|---|
| 未选择文件 | 保持空状态，确认禁用 | 不调用 | 重新选择 |
| 某文件 JSON 无法解析 | 标出文件名，确认禁用 | 不调用 | 修正后整批重选 |
| 某文件是试卷包 | 标出文件名并提示使用“导入试卷” | 不调用 | 移除错误文件后整批重选 |
| 某文件格式未知 | 标出文件名及支持格式 | 不调用 | 修正后整批重选 |
| 跨文件源 ID 冲突 | 显示后端具体错误 | 一次请求整体回滚 | 修正文件后重选或重试 |
| 需要覆盖/去重确认 | 依次显示整批确认 | 带确认参数重试同一批 | 确认或取消 |
| 网络/API 失败 | 保留文件汇总并显示重试 | 不产生部分前端成功状态 | 点击重试或取消 |
| 重复点击确认 | 复用同一提交 Promise | 只产生一个在途请求 | 等待结果 |

## 测试矩阵

### 控制器测试

- 两个单题库文件合并为两个题库，并保持文件和题目顺序。
- 单题库、题库数组、`{banks}` 三种文件格式可混合选择。
- 任一文件 JSON 错误时整批 `banks` 为空，确认不可提交。
- 任一文件为试卷包时，错误包含文件名和正确入口提示。
- API 请求只发送一次，包含所有文件的全部题库与题目 ID。
- 覆盖确认、重复题确认、取消、失败重试和重复点击对整批仍有效。

### 静态与浏览器测试

- 文件输入具有 `multiple` 属性和多文件文案。
- 浏览器一次上传两个生成的题库文件，显示正确文件数、题库数和题目数。
- 混入无效文件后确认按钮禁用且没有题库 API 请求。
- 修正选择后可恢复并只产生一次批量请求。
- 请求失败后可重试，成功后重新加载 API 目录。
- 业务数据不写入 runtime state、`localStorage`、`sessionStorage` 或 IndexedDB。

### 回归

- 现有单文件 60 题样本仍可识别和提交。
- “导入试卷”入口及 99 题试卷包预检不受影响。
- 题库管理页现有导入流程继续通过公共控制器工作。
- 完整前端脚本测试、设计契约和题库 API 重点后端测试通过。

## 验收标准

- 用户可在系统文件选择器中一次选择多个题库 JSON。
- 页面在提交前准确显示文件数、题库数、题目数和文件名。
- 一批文件只产生一次题库导入 API 请求。
- 任一文件或任一后端校验失败时，不产生部分导入。
- 成功后刷新页面，所有题库仍由数据库返回并可用于组卷。
- `main` 在用户完成 UAT 前保持不变。
