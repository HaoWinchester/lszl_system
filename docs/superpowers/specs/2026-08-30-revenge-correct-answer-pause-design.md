# 复仇模式答对后停留并展示解析设计

## 目标

复仇模式中的原错题答对后，不再自动跳到下一题。页面应停留在当前题，持续展示正误状态、正确答案和题目解析，直到用户主动点击现有的“下一题”按钮。

## 当前问题与根因

`new-legacy/src/100-practice-mode.js` 在复仇原错题答对时会先调用解析渲染，再通过 520ms 定时器调用 `advanceAfterAnswer`。下一题重新渲染时解析面板被隐藏，因此用户无法稳定阅读解析，并感知为直接自动跳题。

## 行为设计

- 复仇原错题答对：锁定当前选项并标记正确答案，展示“回答正确”、正确答案与题目解析，停留当前题。
- 成功反馈改为“复仇成功 · 查看解析后进入下一题”，明确下一步由用户操作。
- 用户点击页面既有“下一题”按钮后进入下一题，不在解析区增加重复按钮。
- 复仇原错题答错：继续进入现有补救流程，不改变。
- 复仇验证题：保持现有验证通过或失败的推进规则，不改变。
- 普通练习、挑战模式、学霸模式：保持现有推进规则，不改变。
- 最后一题答对：继续停留并展示解析，用户可通过现有答题卡交卷入口完成练习。

## 实现范围

仅修改复仇原错题答对分支：移除自动推进定时器并调整成功提示。复用现有解析面板、底部导航和草稿状态，不新增数据字段、接口或后端变更。

## 测试设计

浏览器回归用例需验证：

1. 进入至少两题的复仇会话，在第一题选择正确答案。
2. 正确答案样式和解析面板立即出现。
3. 等待超过原 520ms 延迟后，题号和当前题仍保持不变，解析仍可见。
4. 点击“下一题”后才进入第二题，解析面板随新题隐藏。
5. 作答过程不产生逐题写请求。

现有复仇答错补救、验证题和其他模式测试继续作为回归保护。
