# 多题归纳批量选题、全局个人归纳卡与错题集设计

## 1. 决策摘要

本轮在 `question-workspace.html` 的现有多题归纳画布上增加三项互相配合的学习能力：

1. 题目库支持复选多道题，并一次拖入当前画布；
2. 学生创建的归纳卡进入跨画布的“我的归纳卡”全局个人库；
3. 多题画布中的真实作答结果接入数据库错题集，答错进入、答对一次退出默认列表、再次答错重新激活。

采用用户确认的方案 A：复用现有 `practice_mistakes` 错题状态和 `canvas_workspaces` 画布体系，新增独立的数据库级个人归纳卡模型。浏览器仅保存未提交输入、面板开关和当前复选等瞬时 UI 状态，不作为业务数据事实来源。

## 2. 目标与非目标

### 2.1 目标

- 让学生在题目抽屉中通过复选框一次选择多题，拖动任意已选题时把整组题目加入画布。
- 让“＋归纳卡”创建的学生个人卡片跨画布集中保存、搜索、编辑、归档、恢复和再次插入。
- 在页面顶部提供“我的归纳卡”和“错题集”两个真实入口，并显示有效数量。
- 多题画布作答由服务端根据正式题目答案判定正误，前端不得提交自称的 `correct` 结果作为事实。
- 错题按学生账号、题目和发布版本隔离并去重；重复答错累计次数。
- 所有业务数据刷新、退出重登、切换画布后仍存在，且账号之间完全隔离。

### 2.2 非目标

- 不重做整个多题归纳画布布局、缩放、连线、分组或智能整理系统。
- 不把系统预设原则卡迁入个人归纳卡库；系统卡继续只读，复制为“我的归纳”后才进入个人库。
- 不删除错题历史；“移出错题集”表示转为 `mastered`，仍可在“已掌握”筛选中查看。
- 不建立通用“学习资产”大模型，不把错题和归纳卡强行合并为同一种实体。
- 不使用 `localStorage`、`sessionStorage` 或 IndexedDB 保存个人归纳卡、错题或批量选择结果。

## 3. 需求追踪

| 区域 | 控件或数据 | 成功行为 | 失败/空状态 | 恢复行为 |
| --- | --- | --- | --- | --- |
| 题目库 | 每题复选框 | 选中/取消并更新“已选 N 题” | 当前筛选无题时显示原空状态 | 清空选择或切换试卷自动清空 |
| 题目库 | 批量拖拽 | 已选题按试卷顺序、无重叠加入画布 | 重复题跳过；无有效新题时明确提示 | 保留未加入题选择，可调整后重试 |
| 顶部 | 我的归纳卡 | 打开全局库，显示有效卡数量 | 无卡时显示创建引导 | 请求失败显示重试按钮 |
| 个人卡库 | 新增/编辑 | 写入数据库，所有引用画布下次加载为最新内容 | 必填缺失阻止提交；冲突/网络失败保留表单 | 修正输入或重试 |
| 个人卡库 | 插入画布 | 创建带 `personalCardId` 的画布节点 | 已插入同卡时定位现有卡，不重复创建 | 可关闭面板或选择其他卡 |
| 个人卡库 | 归档/恢复 | 默认列表移除；历史引用保留快照并显示已归档 | 归档请求失败不改变本地状态 | 重试；可从已归档筛选恢复 |
| 顶部 | 错题集 | 默认显示未掌握错题数量和列表 | 无错题显示正向空状态 | 可切换到已掌握 |
| 画布答题 | 选择选项 | 服务端判定；错则 upsert，正确则 mastered | 保存失败明确显示且不伪造成功 | 原选择保留，提供重试 |
| 错题集 | 插入画布 | 将错题引用加入当前画布 | 已存在时定位并提示 | 可继续选其他错题 |
| 权限 | 访客/跨账号 | 访客只读；A 看不到 B 的卡片与错题 | API 返回 401/404 | 登录后重载个人数据 |

## 4. 数据模型

### 4.1 个人归纳卡

新增 `personal_synthesis_cards`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `varchar(64)` | 主键，服务端生成 `psc_…` |
| `owner_id` | `varchar(64)` | 外键到 `users.username`，索引并按账号隔离 |
| `title` | `varchar(200)` | 必填标题 |
| `synthesis_type` | `varchar(32)` | `principle/routine/trap/note` |
| `content` | `text` | 卡片正文 |
| `tags` | `jsonb` | 去空、去重后的字符串数组 |
| `status` | `varchar(32)` | `draft/verified/mastered` |
| `source_question_refs` | `jsonb` | 只保存稳定题目、题库、试卷、发布版本引用 |
| `archived_at` | timezone datetime nullable | 非空表示已归档 |
| `revision` | integer | 乐观并发版本，从 1 开始 |
| `created_at/updated_at` | timezone datetime | 审计与排序 |

约束：

- `owner_id + id` 的所有读写都必须同时过滤；其他账号访问统一表现为 404。
- 标题去首尾空格后不能为空；类型和状态使用数据库 check constraint。
- `revision` 更新时必须匹配，冲突返回 409，避免两个画布静默覆盖。
- 归档不删除记录；恢复清空 `archived_at`。

### 4.2 画布归纳卡引用

个人归纳卡画布节点继续使用 `synthesis-card`，新增：

```json
{
  "nodeType": "synthesis-card",
  "cardType": "user",
  "personalCardId": "psc_…",
  "personalCardRevision": 3,
  "title": "风险判断原则",
  "content": "…",
  "archived": false
}
```

画布保存标题、正文和标签快照，以保证个人卡归档或暂时加载失败时画布仍可读。打开画布或收到个人卡变更事件时，以全局库最新数据覆盖显示字段和 `personalCardRevision`，但不改变节点位置、颜色、连线、分组和来源关系。

既有 `cardType=user` 且没有 `personalCardId` 的归纳卡，在登录用户首次打开时延迟迁移：逐张创建个人卡，成功后回写引用；失败时保留原卡并显示“尚未同步到我的归纳卡”，允许重试。系统卡不参与迁移。

### 4.3 错题状态

继续使用现有 `practice_mistakes`，唯一键保持 `owner_id + question_id + release_id`。

- 答错：不存在则创建 `pending`；已存在则 `wrong_count + 1`、更新最近错误答案和时间，并将 `mastered` 或其他状态重新激活为 `pending`。
- 答对：如果存在同发布版本错题，直接转为 `mastered`、填写 `mastered_at`，退出默认列表；不存在则不创建错误记录。
- 再次答错：清空 `mastered_at`，转回 `pending`，重新进入默认错题集。
- 已有复仇、补救和验证字段继续保留，本轮不删除其历史证据。

## 5. API 与服务边界

### 5.1 个人归纳卡 API

新增：

```text
GET    /api/v1/learning/personal-cards?archived=false&query=
POST   /api/v1/learning/personal-cards
GET    /api/v1/learning/personal-cards/{card_id}
PUT    /api/v1/learning/personal-cards/{card_id}
POST   /api/v1/learning/personal-cards/{card_id}/archive
POST   /api/v1/learning/personal-cards/{card_id}/restore
```

列表返回 `cards` 和 `count`。创建/更新返回 `card`。更新请求携带 `revision`；归档卡默认不进入有效列表。

### 5.2 画布作答 API

新增：

```text
POST /api/v1/learning/practice/answers
```

请求只允许传递：

```json
{
  "questionId": "…",
  "bankId": "…",
  "paperId": "…",
  "releaseId": "…",
  "paperVersion": 1,
  "paperName": "…",
  "sourceMode": "multi_question_canvas",
  "languageMode": "zh",
  "selectedAnswer": "A"
}
```

服务端读取学生有权访问的正式题目，计算正确答案；返回 `{correct, mistake}`。正确且没有历史错题时 `mistake` 为 `null`。请求中即使夹带 `correct` 也不得采用。

## 6. 前端结构与交互

### 6.1 批量选题

题目列表每行编号前增加原生复选框及足够点击区域。抽屉元信息区增加“已选 N 题”和“清空”。选择键由发布版本、试卷、题库和题目稳定 ID 组成。

拖拽规则：

- 拖动已选题：拖拽 payload 包含全部已选题稳定引用；
- 拖动未选题：payload 只含当前题；
- 放下后按试卷顺序创建，采用固定列数的网格布局并通过现有空位检测避开卡片；
- 所有新增题作为一次历史操作，渲染和保存合并执行；
- 已存在题跳过，结果提示“已加入 X 题，跳过 Y 道重复题”；
- 切换试卷、退出账号或关闭题目抽屉后切换工作区时清空选择。

### 6.2 顶部入口与面板

在页面顶部、文件页签与语言/账号区之间增加两个紧凑文字按钮：

- `我的归纳卡 N`
- `错题集 N`

桌面端打开右侧抽屉；窄屏沿用现有只读策略，只允许查看，不允许插入或修改。两个抽屉互斥，支持 `Escape`、关闭按钮和点击遮罩关闭，焦点返回原触发按钮。

“我的归纳卡”面板包含有效/已归档筛选、搜索、卡片列表、编辑、归档/恢复和“插入当前画布”。“错题集”包含未掌握/已掌握筛选、错误次数、最近答错时间和“插入当前画布”。

### 6.3 创建与编辑个人归纳卡

- 顶部“＋归纳卡”保存学生卡时先写个人卡 API，再写画布引用。
- 从多选题目生成的系统预设卡保持系统卡；复制为“我的归纳”时创建个人卡。
- 双击个人卡编辑时更新全局记录，成功后广播 `kg-personal-synthesis-cards-change`，当前画布立即刷新所有同 ID 节点。
- 同一张个人卡再次插入当前画布时定位已有节点，不重复创建。
- 网络错误保留弹窗内容和当前画布节点，不显示成功状态。

### 6.4 作答与错误恢复

普通题目卡选择答案后调用服务端作答 API。请求期间锁定当前选项，避免重复提交；成功后显示现有正确/错误闪烁并刷新错题角标。失败时保留选择，卡片底部显示“错题记录保存失败，重试”，点击后重发同一请求。

系统生成的原则练习题仍保留原有首次作答与连线状态更新，同时并行走统一服务端作答 API；任何一条持久化失败都不能伪造为已经写入错题集。

## 7. 权限、并发与安全

- 所有个人卡和错题 API 要求登录；页面访客保持只读并使用现有登录弹窗。
- 后端以 session 用户名决定 owner，忽略客户端 owner 字段。
- 题目正误由后端正式题目数据判定；前端传入的答案状态不可信。
- 个人卡 revision 冲突返回 409，前端提示“卡片已在其他页面修改”，提供重新加载最新版本，不静默覆盖。
- 跨账号 GET/PUT/归档/恢复统一 404，避免泄露 ID 是否存在。
- 删除题目后错题依赖既有 snapshot 保持可读；个人卡来源只存稳定引用和必要显示快照。

## 8. 验收与测试

### 8.1 后端

- 个人卡创建、列表、更新、归档、恢复和 revision 冲突。
- 标题空白、非法类型、非法状态返回 422/400。
- 账号 A/B 数据隔离及未登录 401。
- 画布作答服务端判定：错进、重复错累计、对后 mastered、再次错重新激活。
- 客户端伪造 `correct` 不影响服务端结果。
- 发布版本不同的同一道题保持独立错题记录。

### 8.2 前端契约与单元测试

- 个人卡适配器只访问数据库 API，不含浏览器业务存储键。
- 批量选择 payload、稳定去重键、切换试卷清空和网格位置计算。
- 个人卡引用水合、归档快照、revision 冲突和重试状态。
- 两个顶部按钮、数量、空状态、筛选、关闭和重试控件都有真实绑定。

### 8.3 真实浏览器 E2E

- 勾选 3 题，拖动其中 1 题，一次出现 3 张不重叠题卡；重复拖入提示跳过。
- 拖动未选题只加入 1 题；取消/清空/切换试卷状态正确。
- 答错后错题数量增加并可从错题抽屉插入；答对后默认列表移除；再次答错恢复。
- 创建个人归纳卡，刷新后仍在；新画布可插入；修改后两个画布打开均显示新内容。
- 归档后有效列表移除，已有画布保留“已归档”快照；恢复后重新可用。
- 网络失败、409 冲突、空列表、未登录和跨账号隔离均有负向及恢复路径。
- 页面所有新增可见按钮、链接、复选框、输入和筛选执行控制矩阵扫描。

## 9. 发布约束

- 源代码只修改 `new-legacy/`、后端和同步/发布脚本；不得直接手工覆盖 active release site。
- 版本必须递增，失败候选不可复用版本号。
- 发布前比较当前 active release 与候选 site 的有效文件数，排除 `__pycache__`/`*.pyc` 后不得少于当前版本。
- 抽查 `admin-console.html`、`question-bank.html`、`question-workspace.html` 和 Content Prep 关键页面均存在。
- 通过后使用 `manage-new-legacy.js update new-legacy` 生成并提升正式候选，再通过标准部署脚本发布。

- 无 TBD/TODO 或未决产品规则。

- 设计没有引入与本轮无关的通用学习资产重构。
