# 优先练未做过的题

用户已确认同一套试卷短练优先未做题；只本地开发/预览，不推送或部署 UAT。用户补充：不足时由做过的题补足题量，例如 3 道新题 + 7 道复习题，仍练 10 题。所有题都做过时整轮为复习，并明确标示。

- 服务端按登录学员 + 发布版本识别历史实际作答，跨网页/小程序/普通模式共用。已答错也算做过；只打开、跳过、未提交、超时占位不算。暂停/继续保持原会话题单。新版试卷按新的冻结版本重新计算。
- 新会话统一优先未做题。顺序/随机在未做题和复习题各自内部生效；未做不足时从已做题补足，保持所选题量。
- 案例题不拆组，含未答子题的案例必须完整带入，明确显示为了保留案例而包含的已答题数。若题量无法容纳完整案例，返回现有可用题量提示，不偷偷拆题。
- 全部已做则整轮为复习，明确显示；不声称自动开启新的去重轮次。错题复仇保持已有选题策略。
- 冻结 selectionSummary 到 scoring_snapshot 并在 session 输出，含 requestedCount, actualCount, unseenCount, reviewCount, totalCount, completedCount, remainingUnseen（开始时未做数）。界面解释新题/补足复习/案例重复/整轮复习，既有历史会话无此字段兼容。
- 复用既有 session 服务与 case grouping 公共入口，无新增数据库表；新增职责独立的 coverage/selection helper，避免继续扩张主服务。
