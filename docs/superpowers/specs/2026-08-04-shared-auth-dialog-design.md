# 做题模式与自由模式共享登录组件设计

## 背景与目标

`practice-mode.html` 顶部的“做题 / 自由”切换中，“自由”指向 `index.html`。目前两页虽然使用相同的 `authModal`、`authUsername` 等元素 ID，但并不是同一个组件：

- 自由模式由 `src/30-auth-guards.js` 管理登录弹窗，并由 `src/32-wechat-login.js` 注入微信扫码入口。
- 做题模式复制了一份精简弹窗 DOM，并由 `src/30-standalone-auth-dialog.js` 独立绑定事件。
- 两套实现已经出现功能和视觉分叉；做题模式曾发生点击登录无响应，而只验证自由模式无法发现该问题。

本次目标是让两种模式真正复用同一个原生 JavaScript 登录组件，而不是继续复制 DOM 或仅统一 CSS。完成后，两页的登录弹窗结构、视觉、账号密码登录、注册、微信扫码、关闭和错误恢复行为保持一致；页面排版与画板不变。

## 用户确认的方向

采用共享原生组件方案：抽出一个登录弹窗视图与交互控制器，由自由模式和做题模式共同挂载。自由模式特有的图谱保存、账号空间切换和编辑权限仍留在自由模式认证运行时中，通过明确接口接入共享组件，不进入做题模式。

没有采用以下方案：

1. 让做题模式直接加载 `30-auth-guards.js`：该文件依赖图谱状态、保存和权限守卫，放入做题页会引入错误依赖。
2. 只复制自由模式的 HTML 和样式到做题模式：外观短期一致，但事件和后续修复仍会再次分叉，不满足“同一个组件”。
3. 从做题模式跳转到自由模式完成登录：破坏当前页操作连续性，也不是同一页内复用组件。

## 范围

### 本次包含

- 新建一个共享原生登录弹窗模块，唯一持有弹窗 DOM 模板和通用交互绑定。
- `index.html` 与 `practice-mode.html` 都只保留组件挂载点，并加载同一个共享模块。
- 两页统一提供账号密码登录、注册并登录、微信扫码登录、错误提示、加载状态和关闭行为。
- 做题模式的弹窗使用自由模式现有 `.auth-*` 视觉，不再被 Focus / Vega 页面皮肤单独改写。
- 保留 `KGAuthRuntime`、`authOpen`、`authClose` 等兼容入口，账号菜单继续通过运行时调用登录组件。
- 将账号菜单中的登录理由交给页面认证运行时提供，避免账号菜单硬编码自由模式的图谱文案。
- 修改后按跨页面认证规则遍历相关学习页，实际验证登录和退出。

### 本次不包含

- 不迁移 React，也不改变原生 JavaScript 渐进方案。
- 不调整做题页或自由模式的页面排版、导航位置、画板、题目区域或业务流程。
- 不修改后端认证协议、账号模型、角色权限和微信 OAuth 服务。
- 不借机重构其他页面的认证实现；其他相关页面只做回归验证，发现被本次改动影响时才修复。

## 组件架构

### `KGSharedAuthDialog`

共享模块负责以下单一职责：

- 在挂载点生成自由模式当前登录弹窗的统一 DOM 结构。
- 管理打开、关闭、`aria-hidden`、初始焦点、消息和按钮忙碌状态。
- 读取用户名与密码，并把登录、注册和退出动作交给配置的认证处理器。
- 统一处理 Enter 提交、Escape 关闭、关闭按钮和点击遮罩关闭。
- 暴露稳定的 `mount`、`configure`、`open`、`close`、`message`、`setBusy` 接口。

组件不直接读取图谱状态、做题记录或页面布局，也不决定登录成功后加载哪份业务数据。

### 页面认证适配

自由模式继续由 `30-auth-guards.js` 负责：

- 登录或注册成功后的图谱账号空间切换。
- 退出前保存当前图谱以及保存失败时取消退出。
- 图谱编辑权限守卫和只读状态。
- 发布环境中沿用后端认证适配器作为认证数据源。

做题模式使用轻量认证适配：

- 通过 `KGAuthCore` 调用同一后端登录、注册和退出接口。
- 登录态变化后刷新账号菜单与做题记录所属用户。
- 不加载任何图谱编辑器依赖。

两侧适配器只提供业务回调；弹窗 DOM、按钮绑定、消息、关闭和键盘行为均由 `KGSharedAuthDialog` 唯一实现。

### 微信扫码

两页都加载现有 `32-wechat-login.js`。共享组件先完成弹窗挂载，微信模块再把同一个微信入口注入 `.auth-actions` 之后。正式微信授权、未配置错误、扫码返回和账号绑定逻辑保持现状，不复制第二份实现。

## 视觉与布局约束

自由模式当前登录弹窗是本次设计基准：

| 维度 | 约束 |
| --- | --- |
| 结构 | 标题与说明、关闭按钮、用户名、密码、消息、登录/注册动作、说明文字、微信入口顺序完全一致 |
| 字体 | 沿用 `styles/main.css` 中现有 `.auth-*` 字号、字重和行高，不新增页面专属字号 |
| 颜色 | 沿用自由模式当前背景、边框、主按钮、错误与成功提示颜色 |
| 间距 | 沿用自由模式弹窗宽度、内边距、字段间距和动作间距 |
| 图标 | 关闭控件与自由模式使用同一组件模板；不在做题页保留另一套图标标记 |
| 响应式 | 在 390px、944px、1440px 下不溢出、不被账号菜单遮挡，页面原布局不得位移 |

`learning-skin.css` 不再对做题页的 `.auth-modal` 单独覆盖背景、圆角或阴影。Focus / Vega 皮肤仍只作用于做题页面的非登录业务区域；画板相关冻结区域不受影响。

## 状态与交互

| 场景 | 预期结果 |
| --- | --- |
| 访客从账号菜单点击登录 | 同一共享弹窗打开，用户名获得焦点，账号菜单关闭 |
| 用户名或密码为空 | 阻止请求，显示具体提示，弹窗保持可重试 |
| 账号或密码错误 | 展示后端错误，不关闭弹窗，不残留忙碌状态 |
| 登录成功 | 关闭弹窗，刷新账号菜单和当前页登录态；各页面执行自己的成功回调 |
| 注册输入无效 | 显示长度或后端校验错误，可直接修正并再次提交 |
| 注册成功 | 关闭弹窗并进入已登录状态，各页面执行自己的成功回调 |
| 连续点击提交 | 忙碌期间登录和注册按钮禁用，不重复发起请求 |
| 点击关闭、遮罩或按 Escape | 关闭弹窗并清理临时消息，不改变登录态 |
| 按 Enter | 在用户名或密码字段中触发一次登录 |
| 点击微信扫码 | 两页进入相同二维码面板；失败时可重试或返回账号密码登录 |
| 退出登录 | 调用当前页真实退出链路，页面恢复访客态，不仅改变显示文字 |

## 需求追踪与测试

| 需求 | 页面 / 控件 | 正向 | 反向与恢复 | 自动化检查 |
| --- | --- | --- | --- | --- |
| 真正复用同一组件 | `index.html`、`practice-mode.html` 登录挂载点 | 两页加载同一模块并生成相同结构 | 源码中出现第二份登录模板或独立绑定脚本时失败 | 源码结构测试 |
| 账号密码登录一致 | 登录按钮、用户名、密码 | 使用后端测试账号登录成功并刷新状态 | 空字段、错误密码后仍可修正重试 | 浏览器 E2E |
| 注册一致 | 注册并登录按钮 | 合法新账号完成注册和登录 | 短用户名、短密码、重复账号有明确提示 | 浏览器 E2E / 认证测试 |
| 微信入口一致 | 微信扫码登录 | 两页入口和面板结构相同 | 未配置或请求失败时可返回密码登录 | DOM / 浏览器 E2E |
| 关闭与键盘一致 | 关闭、遮罩、Escape、Enter | 对应动作只执行一次 | 关闭后重新打开无重复监听或旧消息 | DOM / 浏览器 E2E |
| 页面专属业务不串页 | 登录、注册、退出回调 | 自由模式切换图谱空间；做题模式刷新练习用户 | 自由模式保存失败时仍取消退出；做题页不读取图谱全局变量 | 单元 / 浏览器 E2E |
| 不改变布局和画板 | 两页主体、画板 | 登录关闭时页面几何与改前一致 | 390px 下弹窗无溢出、画板无样式变化 | 截图与几何检查 |

回归验证必须覆盖 `index.html`、`learning-path.html`、`practice-mode.html`、`question-training.html`、`question-workspace.html`、`knowledge-recall.html`。每页都要从访客状态点击真实登录，使用后端账号完成登录，再执行真实退出；不能只验证跳转或仅检查弹窗存在。`index.html` 与 `practice-mode.html` 还需覆盖错误密码后的恢复、关闭方式、Enter 提交和微信入口一致性。

## 发布约束

1. 先新增会失败的共享组件结构与交互测试，再实施代码修改。
2. 修改源目录 `new-legacy/` 和必要的同步适配器，不直接编辑 active release。
3. 发布前比较待发布 site 与当前 active release 的文件总数，并确认 `admin-console.html` 等关键页面存在；文件数异常时停止发布。
4. 正式发布使用 `node frontend/scripts/manage-new-legacy.js update new-legacy --skip-browser`。
5. 先运行聚焦测试，再运行相关前端、后端与发布校验，最后在 active release 上执行跨页面浏览器遍历。

## 完成标准

- 登录弹窗模板和通用事件绑定在源码中只有一个实现。
- 自由模式与做题模式加载同一共享模块，并显示相同的弹窗结构、视觉和微信入口。
- 登录、注册、错误恢复、关闭、键盘操作、退出在两页均真实可用。
- 自由模式图谱保存与空间切换逻辑没有进入做题模式，做题页也不依赖图谱全局变量。
- 页面排版和画板无变化，相关自动化测试和跨页面实测全部通过。
- 发布包通过内容防回退校验，并由项目正式发布命令生成和提升。
