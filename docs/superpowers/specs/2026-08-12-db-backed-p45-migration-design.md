# P4.2–P4.5 数据库化功能迁移设计

日期：2026-08-12
状态：用户授权直接实施

## 背景与目标

当前生产版本为 `v9.0-p4.1.39`。来源目录 `updata-legacy/` 为 `v9.0-p4.5.28`，包含 P4.2–P4.5 的图谱画布、题库/训练、做题、回忆、学习诊断和 Prep Studio 能力。

本次目标是按可独立验收的批次将这些能力迁入当前 FastAPI + PostgreSQL 项目。所有业务数据以 PostgreSQL 为唯一持久化真值；浏览器仅保留页面内存和不包含业务内容的短生命周期导航令牌。

明确不迁移以下首页能力：四个学习入口、新手引导、简易/专业知识点编辑切换、帮助入口改版。

## 已确认约束

- 不直接覆盖 `new-legacy/`、`frontend/public/new-legacy/` 或 active release。
- 每批只从 `updata-legacy/` 取经审计的页面、样式和模块；发布只走 `manage-new-legacy.js update`。
- 题库、试卷、原则、归纳卡、学习事件、做题记录、深度回忆、联想库和工作区数据必须服务端持久化。
- 现有 `RuntimeState` / `SharedRuntimeState` 已在 PostgreSQL 中保存兼容型页面状态，可作为过渡适配层，但不能形成与关系表并列的第二份业务主数据。
- `sessionStorage` 只能保存一次性预览/跳转令牌，不保存可恢复的业务内容；IndexedDB 不再用于正式业务草稿或内容。
- 所有变更按测试先行实施：先验证失败，再实现，再跑后端、前端静态和浏览器回归。

## 方案选择

### 方案 A：整体覆盖静态源

一次把 P4.5.28 覆盖到当前 `new-legacy/`，借助现有 `localStorage` 拦截器落库。

优点是快；风险是会带入被排除的首页功能、未登记的存储键和 IndexedDB，并且会绕开当前项目的 API/权限边界。因此不采用。

### 方案 B：所有功能先重写为全新前后端页面

每项功能都改为全新 UI 和专用关系模型。

数据模型最理想，但会破坏原版 UI 硬约束，并将迁移周期拉长。仅对无法安全兼容的长期域（诊断、推荐、机构/授权）采用这一做法。

### 方案 C：数据库优先的纵向分批迁移（采用）

每批先建立数据库/API 或确认既有服务端主数据，再接入原版页面模块，并通过服务端存储适配器消除浏览器持久化。关系型主数据走专用 API；兼容型画布与显示偏好暂由 PostgreSQL `RuntimeState` 承载，后续在不改变页面契约的前提下逐步下沉专表。

## 数据边界

| 领域 | 权威存储 | 迁移方式 |
| --- | --- | --- |
| 图谱文件及节点/连线 | `graph_files` + `file_contents` | 继续使用文件 API；新画布外观字段随正文 JSON 持久化 |
| 题库、题目、试卷 | `question_banks`、`questions`、`exam_papers` 等 | 仅使用 Question Catalog/Content Prep API，不写 Runtime State 题库键 |
| 原则、归纳卡、标签 | `principles`、`synthesis_presets`、`question_tag_configs` | API 原子写入，题目通过 JSONB 引用稳定 ID |
| 训练/多题画布/回忆进度 | `training_progress`、`canvas_workspaces`、`recall_progress`、`learning_events` | 扩充专用 API；兼容读取由适配层完成 |
| 错题、验证、学习诊断、推荐 | 新建领域表与追加事件表 | 先服务端领域服务，再接 UI；不把分析结果写浏览器 |
| 科目联想库与回忆管理 | 共享教学内容表/API，过渡期为共享 PostgreSQL state | 发布、草稿、版本历史和容量检查都由服务端完成 |
| Prep Studio 工作区 | PostgreSQL 草稿/批次/锁/审计 | 移除 IndexedDB 正式草稿；离线仅允许导出文件，不提供本地持久化草稿 |

## 迁移批次与验收顺序

1. **数据库持久化护栏**：登记 P4.2–P4.5 的兼容键，拒绝未登记持久化，补齐服务端页面存储测试；建立迁移清单和发布阻断。
2. **题库、分类、训练配置**：导入策略、变更摘要、语义标签、Subject Facet、关键词 v2、原则/归纳卡与训练预览。题目/原则/配置只走 API。
3. **画布运行时与图谱编辑器**：P4.2 画布内核、P4.3 统一画布运行时、关系线/多选/配色等，排除首页入口、引导、帮助和简易/专业编辑。
4. **做题与试卷闭环**：双语、免费/VIP、复仇模式、验证题和下一步学习建议；尝试、错题和验证证据均入库。
5. **深度回忆与联想库**：关键词优先、搜索、增量渲染、发布历史、容量预检和事务回滚；联想内容及进度入库。
6. **学习诊断与推荐基础**：证据、诊断、决策、候选、排序、选择、推荐记录、消费事件和效果归因。首期不自动向学员推送内容。
7. **Prep Studio 与外部 AI 契约**：从 IndexedDB 工作区升级为数据库草稿；统一 AI/Word 模板、原则包和 Question Family 质量门槛。

每批必须独立发布、完成浏览器回归并保留回滚点；下一批不得依赖浏览器中的上一批业务状态。

## 第一批的范围

第一批只完成迁移护栏与数据契约，不替换页面行为：

- 对 P4.5.28 源码扫描出的新增存储键建立显式白名单和服务端验证；未登记键构建失败。
- 将教学/学习业务键按“专用 API、共享数据库状态、用户数据库状态、临时会话”标记，禁止新增 `localStorage` 或 IndexedDB 业务写入。
- 为后续源模块建立功能清单，记录来源文件、目标页面、持久化 API、排除项和验收测试。
- 先完成原有系统已经具备的原则/题目 API 与 P4.5 契约间的差异确认，避免把旧前端仓库重新带回 Runtime State。

## 失败与回滚

- 任何 API 持久化失败必须保留页面内存中的可见状态，显示失败，且不得伪报保存成功。
- 多实体写入（原则包、题库包、联想库发布、推荐事件）必须在一个数据库事务内提交。
- 乐观并发使用 revision/ETag；题目编辑继续使用现有数据库锁。
- 每个候选 release 必须通过文件数量、关键页面、数据库 API 回归和视觉对比后才可 promote；不允许手工修改 active release。

## 完成标准

- 所有目标功能分批上线，排除项不出现于首页。
- 浏览器清理站点数据或换设备后，登录同一账号仍能看到同样的业务数据。
- 数据库不可用时，任何业务写入不落本地也不显示已保存。
- 每一批都有后端测试、前端静态测试和至少一条真实浏览器持久化验证。
