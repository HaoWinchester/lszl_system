# Content Prep 关键词联想入口端到端设计

日期：2026-08-14  
状态：用户已批准直接实施

## 背景与问题

冻结表 `Prep Studio差异` 第 1–5 项要求：联想入口可手动模糊搜索，支持中文名、英文名、Alias 与 Recall ID；Recall 可留空，仅非空无效 ID 报错；关键词命中位置按题干或指定选项隔离计算，同词可在不同来源独立存在。

当前服务器 Prep 仍只提供完整下拉框。导入题目含关键词但没有有效 `recallNodeId` 时，教师很难从数百个联想节点中找到并绑定入口。同步链路又在写入本次草稿携带的联想库之前校验题目引用，并且历史校验路径读取旧 Runtime State 投影，而学员端深度回忆读取 `SharedRuntimeState` 中的正式科目联想库快照。三者不一致会造成：Prep 看得到联想库和关键词，正式题目却未保存有效入口，主程序打开关键词后只能显示“没有更多推荐”。

本设计覆盖冻结表第 1–5 项，并把 Prep、服务器正式数据和主程序深度回忆连成同一个稳定 ID 契约。其余 `Prep Studio差异` 项目不在本轮范围内。

## 目标

- 教师可在所有关键词编辑入口按中文名、英文名、Alias 或 Recall ID 模糊搜索正式联想节点。
- 选择节点后，题目关键词保存稳定 `recallNodeId` 和对应 `recallEntryLabel`。
- 空 Recall 合法；只有非空且不存在的 ID 阻止同步。
- 新联想库与引用它的新题目可在同一次草稿同步中完成校验和原子提交。
- 主程序深度回忆从服务器会话绑定的正式联想库快照解析该稳定 ID，并显示节点的后续关系。
- 关键词命中位置只在原题干或指定选项内重算，同词在不同来源可独立绑定。

## 非目标

- 不按关键词文本自动创建正式联想节点。
- 不把未命中的关键词静默绑定到相似节点。
- 不把学员手输的个人回忆节点写回正式联想库。
- 不恢复 Runtime State 或浏览器存储作为正式题目、联想库或进度真源。
- 不一次迁移冻结表中与本问题无关的 Family、Facet、原则包或 Workspace 功能。

## 方案选择

采用端到端稳定 ID 方案：复用 P4.5.29 源文件中已存在的搜索交互和来源隔离规则，补齐服务器有效联想库校验，并以 Prep 到深度回忆的浏览器流程作为发布 Gate。

不采用“只加搜索框”，因为它无法证明所选 ID 已写入草稿、正式题目和主程序快照；不采用“关键词文本兜底自动造节点”，因为同名、Alias 冲突和改名会产生错绑，违反 optional-existing-id-only 契约。

## 数据契约

每个题目关键词继续使用现有结构：

```json
{
  "id": "kw-...",
  "text": "不堪重负",
  "textEn": "overwhelmed",
  "sourceType": "stem",
  "sourceOptionId": "",
  "recallNodeId": "recall-...",
  "recallEntryLabel": "工作负荷与团队支持",
  "matchLocations": [{ "field": "stem", "optionId": "", "count": 1 }]
}
```

规则：

- `recallNodeId == ""`：合法未绑定，不产生引用错误。
- `recallNodeId != ""`：必须存在于本次同步的有效联想库或当前服务器正式联想库。
- `recallEntryLabel` 是显示快照，不作为解析主键；选择节点时由节点中文名自动刷新。
- 导出时 `metadata.keywordSystemV2.keywords` 继续从规范化 `clues` 派生，不能形成另一份可编辑真源。
- 学员端只按会话绑定的正式联想库快照解析；历史图继续使用其原联想库 hash，不静默切换。

## Prep 搜索与编辑交互

### 搜索能力

在关键词浮窗和关键词明细卡中复用同一搜索逻辑：

- 空查询显示完整下拉选择。
- 查询同时覆盖节点 `title`、`titleEn`、`aliases[]` 和 `id`，不区分英文大小写，合并多余空格。
- 排序优先级依次为完全匹配、前缀、包含、多词全部包含、子序列模糊匹配，再按节点 priority 和中文名稳定排序。
- 结果展示中文名、命中的 Alias/英文名和稳定 ID，避免同名误选。
- Enter 选择第一项；选择下拉项后显示“已选择：名称 · ID”；清空搜索不自动清除既有绑定，明确选择“未关联”才清除绑定。

### 保存与恢复

- 保存关键词时以组件内部已选择 ID 为准，不以搜索框自由文本作为 ID。
- 选择或清除入口会触发共享草稿 dirty 状态；必须先保存共享草稿，再同步到主程序。
- 重新打开草稿或刷新页面后，搜索组件从 `recallNodeId` 恢复已选节点。
- 如果旧草稿保存了不存在的非空 ID，界面保留该错误状态并要求重新选择或清除，不静默替换。

### 关键词来源隔离

- 新增关键词时保留选区所在 `sourceType` 与 `sourceOptionId`。
- 重算位置时只搜索该来源：题干关键词只搜索题干；选项关键词只搜索指定选项。
- 判重键为 `text + sourceType + sourceOptionId`，因此同词可分别存在于题干、A 选项和 B 选项。

## 服务器校验与原子同步

### 有效联想库

Content Prep 批次构造本次校验使用的 effective Recall library：

1. 请求携带非空 `recallLibrary` 时，规范化并使用本次库。
2. 请求未携带联想库时，读取当前科目的 `SharedRuntimeState` 正式联想库。
3. 不再通过发布者个人 `RuntimeState` 选择联想库。

题目引用校验只检查非空 `recallNodeId`。空值通过；非空 ID 不在 effective library 时返回精确字段路径和 `REFERENCE_NOT_FOUND`。

### 事务顺序

在单个批次事务中：

1. 规范化本次知识树和联想库，建立校验视图。
2. 校验题目内容、标签、知识点、原则及 Recall 引用。
3. 写入联想库、知识树和配置。
4. 写入题目及其 `clues`。
5. 建立内容 revision、审计和批次结果。
6. 任一步失败全部回滚，草稿保留以便修正和重试。

该顺序允许“本次新增节点 + 本次题目引用该节点”同时成功，又不会让失败批次留下孤立节点或半保存题目。

## 主程序深度回忆消费

深度回忆会话继续由后端返回题目快照与正式联想库快照。前端加载会话后调用 `setSessionLibrary`，并按关键词的 `recallNodeId` 建立根节点：

```text
Prep 选择正式节点
  → 共享草稿保存 clue.recallNodeId
  → 批次原子写入题目 + 科目联想库
  → Deep Recall session 返回相同题目和联想库快照
  → recallNodeId 命中节点
  → 节点 outgoing edges 生成后续推荐
```

若 Recall 为空，关键词仍可作为学员个人探索入口，但不得伪造正式 ID；若非空 ID 在服务器正式库中不存在，发布前即被阻止，不把坏引用交给学员端。

## 错误与恢复

- 搜索无结果：显示明确空态，允许修改搜索词、清空搜索或选择未关联。
- Alias 冲突：结果列出所有候选及稳定 ID，不自动选择。
- 无效旧 ID：显示错误并允许重新选择或清除。
- 草稿未保存：禁止同步并提示先保存。
- 批次引用失败：返回具体 `clues[n].recallNodeId`，事务回滚，草稿不删除。
- 网络失败：保留共享草稿和当前选择，不显示同步成功；重试沿用现有幂等机制。
- 主程序节点无 outgoing edge：允许个人输入继续，但测试会区分“入口未命中”和“入口合法但没有后续关系”。

## 测试与验收 Gate

### 前端单元与交互

- 中文、英文、Alias、ID 的完全、前缀、包含和模糊搜索。
- 同名/Alias 冲突不自动绑定；Enter 选择排序第一项。
- 搜索清空、显式未关联、重新打开恢复选中值。
- 浮窗和明细卡保存同一稳定 ID 与显示标签。
- 题干与指定选项来源隔离；同词在不同来源独立存在。
- 空 Recall 不报错，非空无效 ID 报错。

### 后端

- 当前正式库已有 ID 时题目同步成功。
- 本次请求新增 Recall 节点并由同批题目引用时同步成功。
- 空 `recallNodeId` 同步成功。
- 非空不存在 ID 返回 `REFERENCE_NOT_FOUND`，题目和联想库均不落库。
- 校验读取 `SharedRuntimeState`，不依赖任何个人 Runtime State。

### 浏览器端到端

- 导入包含“不堪重负”的题目与至少一个有后续关系的正式联想节点。
- 在 Prep 按中文、英文、Alias 或 ID 搜索并选择，保存共享草稿后同步。
- 刷新 Prep，重新读取正式题目，确认绑定仍存在。
- 从主程序进入深度回忆，揭示并点击“不堪重负”，确认出现该正式节点的后续推荐，而不是“没有更多推荐”。
- 修改为未关联后再次同步，确认主程序不伪造正式推荐但仍允许个人输入。
- 覆盖保存失败、重试和无效 ID 修正后的恢复路径。

## 发布纪律

- 先在 `new-legacy/` 正式源修改并构建 `content-prep-studio/dist/content-prep.html`。
- 不直接修改 `frontend/public/new-legacy/` 或 active release site。
- 发布前比较候选 site 与当前 active release 文件数，文件数异常不发布。
- 通过 `node frontend/scripts/manage-new-legacy.js update new-legacy --skip-browser` 构建并提升版本。
- 发布后至少复测 `/content-prep`、题库正式读取和 `knowledge-recall.html` 端到端流程。

## 完成标准

- 冻结表第 1–5 项全部有自动化证据。
- Prep 所选稳定 ID 经共享草稿、数据库正式题目和 Deep Recall 会话保持一致。
- “不堪重负”验收场景能进入正确联想节点并显示后续推荐。
- 空 Recall、无效 ID、冲突候选、失败重试和来源隔离均符合契约。
- 全量相关测试通过，候选发布文件完整，功能合入并推送 `main`，已完成的功能分支和工作树清理完毕。
