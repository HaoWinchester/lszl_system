# new-legacy v8.6 持续集成设计

**日期：** 2026-07-21

**上游基线：** `new-legacy/VERSION` = `v8.6.0`

**当前旧基线：** `legacy/CHANGELOG.md` 最新版本 = `v8.4.23`

**状态：** 已与用户确认

## 1. 目标

将 `new-legacy` 相对 `legacy` 新增的功能完整接入当前 FastAPI + React + PostgreSQL 项目，同时满足以下要求：

1. 默认入口、页面流程、视觉样式、交互手感和细节完全以 `new-legacy` 为准。
2. 保留当前 React、API、权限、数据库和微信登录/支付重构成果，不推倒重来。
3. 复杂画布直接复用 `new-legacy` 原版运行引擎；普通管理页面继续使用 React，并对齐原版 DOM 与 CSS。
4. 用户业务数据由 PostgreSQL 持久化并按用户隔离，不把 `localStorage` 当作业务数据源。
5. 建立可重复的上游同步机制。以后用户只需提供一份完整的新 `new-legacy` 目录，即可检测、同步、验证并报告兼容性问题。

## 2. 已确认的产品决策

### 2.1 默认入口

完全跟随 `new-legacy`：

- `/` 进入游戏化学习路径。
- 图谱编辑器迁移到 `/graph`，对应 `new-legacy/index.html?mode=free` 的自由模式。
- 访客体验、登录入口和学习模式切换遵循 `new-legacy` 的页面语义；服务端仍执行真实权限校验。

### 2.2 技术方案

采用 React 主应用与原版 iframe 引擎并存的混合架构：

```text
React 主应用
├── React 页面
│   ├── 登录 / 微信回调 / 会员
│   ├── 文件管理
│   ├── 题库管理
│   ├── 深度回忆
│   ├── 用户管理
│   └── 系统设置
├── iframe 图谱引擎
│   └── 自由模式图谱编辑器
└── iframe 学习引擎
    ├── 游戏化学习路径
    ├── 节点活动
    ├── 部分跳级测试
    ├── 五步单题深学
    └── 多题归纳画布
```

React 继续负责：

- 顶层路由；
- 登录状态与角色守卫；
- Axios API；
- Zustand 会话状态；
- iframe 生命周期和桥接；
- 统一错误边界；
- 后端数据预加载与持久化。

原版引擎负责：

- 原始 DOM 与 CSS；
- 画布缩放、平移、拖动、框选、连线、小地图和动画；
- 学习活动运行器；
- 原版按钮、卡片、状态与视觉反馈；
- `new-legacy` 已有的页面内工作流。

## 3. 备选方案与取舍

### 3.1 全部重写为 React

优点是组件和数据流最统一；缺点是需要重写 Canvas Kernel、五步学习画布、多题画布、活动插件和大量细节交互，视觉与操作偏差风险最高，因此不采用。

### 3.2 直接发布 new-legacy

优点是页面无需改造；缺点是学习进度、题库和工作区仍依赖浏览器存储，无法保证数据库持久化、跨设备恢复、权限校验和用户隔离，因此不采用。

### 3.3 混合架构

保留 React 和后端成果，同时直接运行最难复制的原版引擎；新增的适配代码集中在资源同步、页面宿主和数据桥接三个边界内。这是本设计采用的方案。

## 6. 资源同步架构

### 6.1 上游与生成目录

- `new-legacy/` 是用户提供的完整上游源码目录。
- `legacy/` 保持不动，继续作为旧版参考，不作为新构建输入。
- `frontend/public/new-legacy/` 是构建生成目录，不允许手工修改。
- `frontend/scripts/new-legacy-assets/` 只保存本项目维护的桥接脚本和注入样式；不复制上游业务代码到这里。

### 6.2 同步命令

提供以下标准入口：

```bash
cd frontend
pnpm sync:new-legacy
```

命令完成以下操作：

1. 校验 `new-legacy/VERSION`、必需页面、脚本、样式和 Schema 文件。
2. 读取上一次同步清单并比较新增、修改、删除和重命名文件。
3. 生成 `frontend/new-legacy-sync-report.json`，记录版本、哈希、差异分类、桥接风险和 React 页面影响。
4. 清空并重建 `frontend/public/new-legacy/`。
5. 原样复制上游 HTML、JS、CSS、Schema 和需要的静态资源。
6. 只在生成页面中注入版本化桥接脚本和运行时配置覆盖；不改写 `new-legacy/` 源文件。
7. 为图谱自由模式生成专用 workbench 页面。
8. 写入 `frontend/new-legacy-manifest.json`，记录文件 SHA-256、页面入口、桥接版本和同步时间。
9. 运行静态兼容检查；关键接口不兼容时以非零状态退出，不生成“成功”标记。

### 6.3 未来更新协议

用户以后直接用完整新版目录替换 `new-legacy/`，再运行同一同步命令。

自动同步范围：

- 新增或修改的页面、CSS、JS、Schema 和资源；
- iframe 页面入口；
- 活动类型注册；
- 保持现有桥接接口的上游功能更新。

必须人工适配并由同步报告阻止静默发布的变化：

- 删除或重命名桥接依赖的页面入口、全局接口、DOM ID 或事件；
- 修改认证、题库、学习进度、工作区或 Activity Schema 的业务协议；
- 引入新的浏览器持久化命名空间；
- 修改 React 页面对应的上游 DOM 结构或关键 CSS；
- 数据迁移无法无损完成。

任何未识别的关键变化都采用失败关闭策略：同步命令报错并列出文件和契约差异，不继续声称集成成功。

## 7. iframe 页面宿主与桥接

### 7.1 宿主组件

新增通用 React 页面宿主，职责保持单一：

- 根据页面类型生成 iframe URL；
- 注入当前用户、角色、主题和桥接协议版本；
- 在 iframe 加载前获取所需后端数据；
- 处理 `postMessage`；
- 将内部导航映射回 React Router；
- 显示加载、失败和重试状态；
- 页面卸载时取消监听和未完成请求。

图谱文件仍使用独立图谱桥，因为其同步存储接口和自动保存节奏与学习页面不同。

### 7.2 同步内存数据适配器

`new-legacy` 的学习模块使用同步存储接口，而后端 API 是异步接口。为同时保持原版运行器行为和数据库权威性，采用预加载的同步内存适配器：

1. React 宿主先从后端加载当前页面所需的用户快照。
2. 宿主为本次 iframe 创建不可复用的 `frameToken`，把只属于该用户和页面的快照放入父窗口内存注册表。
3. iframe 生成页面在所有上游业务脚本之前加载 `server-state-bootstrap.js`，使用 `frameToken` 同步读取父窗口快照并创建 `window.KGServerStateStorage`。
4. 同步器只在生成的 JavaScript 副本中进行受测试的标识符替换，将业务模块的 `localStorage` / `window.localStorage` 调用指向 `KGServerStateStorage`；`new-legacy/` 原文件不变。
5. `KGServerStateStorage` 提供与 Web Storage 相同的同步 `getItem`、`setItem`、`removeItem`、`key` 和 `length` 契约，但数据只存在当前 iframe 内存中。
6. 内存写入触发带命名空间和版本号的桥接事件；React 适配器把变化转换为对应的领域 API 写入，并在后端确认后返回保存状态。
7. 刷新页面时重新从后端预加载，不从浏览器持久化恢复业务数据。

同步器扫描所有新增或变更的上游 JavaScript 和内联脚本。出现新的 `localStorage`、`sessionStorage` 或 IndexedDB 调用而未归入允许清单时，同步失败并在报告中列出文件、行号和存储键。认证运行时的短期远程会话不依赖该替换；当前项目继续使用同源 HttpOnly Session Cookie。

### 7.3 消息信封

所有消息使用统一信封：

```json
{
  "channel": "kg:new-legacy",
  "version": 1,
  "requestId": "唯一请求 ID",
  "page": "learning-path",
  "type": "kg:progress:save",
  "payload": {}
}
```

父子窗口均校验：

- `origin` 必须等于当前应用 origin；
- `channel` 和 `version` 必须匹配；
- `page` 必须匹配当前宿主页；
- 带响应的请求必须匹配 `requestId`；
- 不接受未知写操作。

### 7.4 桥接域

桥接按领域分开，不建立一个无限扩张的通用事件处理器：

- `auth`：当前用户、登录变化、退出和角色；
- `navigation`：页面与查询参数映射；
- `questions`：发布试卷、题目目录和题目详情；
- `training`：学习会话、完成记录和学习事件；
- `workspace`：多题工作区 CRUD 和批量布局；
- `guidedLearning`：课程、活动库、进度和跳级记录；
- `graphFiles`：现有图谱文件读取、自动保存和切换；
- `subscription`：升级入口和使用限制。

### 7.5 浏览器存储边界

允许保留的前端瞬时状态：

- 当前打开的弹窗或工具栏；
- 当前页面未提交的表单输入；
- 一次页面会话内的拖动状态；
- 不影响业务结果的短期视觉偏好。

必须经后端保存的状态：

- 题目、题库和试卷；
- 答题选择、步骤、复述和完成结果；
- 学习事件和统计；
- 画布工作区、卡片、关系、分组、布局和视口；
- 引导学习节点、挑战和跳级进度；
- 用户、权限、订阅和系统配置；
- 图谱文件与学习状态。

桥接脚本不得把这些业务数据写入 `localStorage`、`sessionStorage` 或 IndexedDB。同步检查必须扫描上游新增存储键，并要求明确归类。

## 8. 后端数据设计

### 8.1 复用现有模型

- `users`
- `question_banks`
- `questions`
- `exam_papers`
- `paper_questions`
- `training_progress`
- `recall_progress`
- `graph_files` / `file_contents`
- 订阅、订单、兑换码、系统设置和管理日志表

### 8.2 扩展训练进度

`training_progress` 增加版本化的 `session_data JSONB`，保存单题深学的完整会话快照，包括：

- schemaVersion；
- 当前步骤与已完成步骤；
- 答案、信心、关键词、推理和复述；
- 活跃用时；
- 画布视口与五张核心卡布局；
- 完成统计和更新时间。

现有 `selected_answer`、`submitted`、`found_clues` 和 `reasoning_state` 继续读写，作为兼容字段。服务层负责在旧字段和新快照之间迁移。

### 8.3 学习事件

新增 `learning_events`：

- `id`；
- `owner_id`；
- `question_id`；
- `event_type`；
- `payload JSONB`；
- `created_at`。

事件只能追加，列表按当前用户过滤，并设置合理分页与保留策略。

### 8.4 多题工作区

新增 `canvas_workspaces`：

- `(owner_id, id)` 联合唯一；
- `title`；
- `schema_version`；
- `payload JSONB`；
- `created_at` / `updated_at`。

`payload` 保存节点、关系、分组、视口、显示模式、高亮和布局。创建、重命名、删除和保存均按 `owner_id` 校验。

### 8.5 引导学习课程与活动

新增：

- `guided_courses`：课程元数据、版本、阶段/部分/节点编排和发布状态；
- `guided_activities`：稳定活动 ID、活动类型、Schema 版本和 Activity Schema v1 内容；
- `guided_course_activities`：课程与活动关系或节点活动次序；
- `guided_learning_progress`：用户、课程、schemaVersion、节点状态、挑战统计、跳级记录和更新时间。

v8.6.0 的课程和活动库由受版本控制的后端种子包导入。前端不把硬编码活动数组作为用户数据源。导入包必须通过 JSON Schema、稳定 ID 唯一性和节点引用完整性校验。

### 8.6 用户隔离和写入规则

- 所有学习业务表均带 `owner_id` 或以用户字段组成联合键。
- 查询必须同时按对象 ID 和当前用户过滤。
- 管理员预览通过显式 `preview=true` 运行，禁止写入学员正式进度。
- 写操作 `commit` 后必须 `await db.refresh(obj)` 再访问 ORM 属性。
- 创建父子记录时先 `flush` 父记录，再写子记录。

## 9. React 页面视觉同步

文件管理、题库、回忆、用户、设置等 React 页面继续保留，但每个页面建立对应关系：

| React 页面 | 上游设计文件 |
|---|---|
| `Files.tsx` | `new-legacy/file-manager.html` |
| `QuestionBank.tsx` | `new-legacy/question-bank.html` |
| `Recall.tsx` | `new-legacy/knowledge-recall.html` |
| `Users.tsx` | `new-legacy/user-management.html` |
| `Settings.tsx` | `new-legacy/system-settings.html` |

同步规则：

1. 使用上游相同的 DOM 层级和 className。
2. 复用上游对应 CSS，不另写一套近似样式。
3. 上游未修改的页面不做无关重构。
4. 当前会改变上游视觉的全局覆盖层必须逐页审计；与 `new-legacy` 冲突的覆盖移除或限制作用域。
5. 图标、按钮、空状态、响应式布局、页头、页脚、弹窗和抽屉均纳入截图对比。
6. 每个可见控件必须有真实路由、状态变化、API、弹窗或领域动作，禁止通用占位提示。

## 10. 认证、权限和订阅

- `new-legacy/src/01-runtime-config.js` 的生成版本配置为远程认证模式。
- 生成页面在 `01-runtime-config.js` 前加载本项目的配置覆盖，利用上游合并规则设置远程端点；不手改上游配置文件。
- 端点映射到当前 `/api/v1/auth/login`、`register`、`logout` 和 `me`。
- 同源 Session Cookie 仍是会话来源；不在 iframe 保存持久令牌。
- React store 与 iframe 会话变化双向同步。
- iframe 的前端角色装饰只负责显示；后端依赖继续执行真实角色和 owner 校验。
- 管理员页面继续由 React Router 角色守卫保护。
- 订阅限制使用后端套餐和订单状态；不得用 iframe 内本地演示订阅绕过。
- 保留当前工作区未提交的微信登录、微信支付和订阅修改，迁移不得覆盖这些文件中的用户改动。

## 11. 错误处理与恢复

### 11.1 初始化失败

后端数据预加载失败时不启动业务运行器。宿主显示具体失败领域、重试按钮和返回入口，避免以空数据启动后覆盖服务器状态。

### 11.2 保存失败

- iframe 先显示“保存中”。
- 后端确认后显示“已保存”。
- 失败时保持内存中的用户操作，显示具体错误和“重新保存”。
- 不发送虚假的成功事件。
- 重复保存使用版本或更新时间进行冲突检测，防止旧快照覆盖新快照。

### 11.3 权限和登录变化

- 401：刷新一次会话；仍失败则显示登录入口。
- 403：保持页面可查看状态并隐藏或禁用写操作。
- 用户切换：销毁当前 iframe，清空内存快照，再按新用户重新加载。
- 管理员预览退出：丢弃预览会话，不写正式进度。

### 11.4 数据迁移失败

保留原始 JSONB 快照，不执行破坏性覆盖。接口返回明确迁移错误；同步和部署检查失败，直到迁移器通过旧版本夹具。

## 12. 需求追踪与测试设计

### 12.1 测试先行

每组生产代码前先添加会失败的测试，确认失败原因是功能缺失，再实现最小代码使其通过。新增函数、API、数据迁移和桥接行为均遵循 Red → Green → Refactor。

### 12.2 上游基线测试

- 运行 `new-legacy/tests/guided-learning-v2.test.js`。
- 运行上游 JavaScript 语法检查。
- 条件允许时运行 `new-legacy/tests/browser-smoke.py`。
- 同步后再次运行同一测试，证明派生和桥接未破坏上游运行器。

### 12.3 同步器测试

覆盖：

- 完整 v8.6.0 目录成功同步；
- 缺少 `VERSION` 或关键页面时失败；
- 文件新增、修改、删除被正确分类；
- 关键 DOM ID、全局接口或存储键变化时失败关闭；
- 生成目录不存在手工漂移；
- 同一版本重复同步结果可复现；
- 指定一份模拟新版本目录时生成准确的兼容报告。

### 12.4 后端测试

覆盖每个领域的正向、反向和恢复路径：

- 会话创建、更新、读取和旧格式迁移；
- 学习事件追加和分页；
- 多题工作区 CRUD、批量布局和冲突；
- 引导学习进度、单一当前位置、挑战完成和跳级通过/失败；
- 活动包校验、重复 ID、坏引用和非法 Schema；
- 用户 A 数据不被用户 B 读取或修改；
- 管理员预览不写正式进度；
- 401、403、404、冲突和数据库失败后的重试。

### 12.5 前端与桥接测试

- 每条新路由打开正确页面。
- iframe 只接受同源、正确版本和正确页面的消息。
- 内部 HTML 链接映射到正确 React 路由并保留查询参数。
- 登录、退出和切换用户后 iframe 数据正确重载。
- 业务保存成功后刷新可恢复。
- 请求失败时不显示成功，且可重试。
- 源码扫描确认桥接页面不持久化业务数据到浏览器存储。

### 12.6 控件矩阵与 E2E

对学习路径、节点活动、跳级测试、单题深学和多题画布执行：

- 所有可见按钮和链接绑定检查；
- 输入、选择、切换、拖动、缩放和键盘交互；
- 正确、错误、空输入、取消、重复点击、刷新、后退和重试；
- 学员、教师、管理员和无权限状态；
- 跨页面数据链路：发布试卷 → 单题深学 → 多题画布 → 返回定位；
- 跨用户隔离；
- 移动端只读行为。

### 12.7 视觉验收

在相同视口、主题、用户和种子数据下，对 `new-legacy` 原页与当前项目页面进行并排截图：

- 桌面端；
- 平板端；
- 移动端；
- 初始、数据、空状态、弹窗、禁用、选中、错误和完成状态。

比较范围包括尺寸、位置、间距、字体、颜色、边框、阴影、按钮底座、图标、动画前后状态和响应式折叠。差异必须修复或在设计变更记录中获得用户明确批准。

## 13. 实施分段

为保持每一段都可运行和验证，实施按以下依赖顺序推进：

1. 上游同步器、版本清单、兼容报告和派生资源。
2. React 路由调整、通用 iframe 宿主和导航/认证桥。
3. 图谱资源升级到 `new-legacy` 并验证 `/graph`。
4. 后端学习会话、事件和多题工作区模型/API。
5. 五步单题深学与多题归纳画布接入。
6. 引导课程、Activity Schema、活动包和学习进度模型/API。
7. 学习路径、节点活动和跳级测试接入，切换默认 `/`。
8. React 页面与 `new-legacy` 视觉和交互对齐。
9. 全量功能、权限、持久化、浏览器和截图回归。

每段完成后运行聚焦测试；最终运行后端全量测试、前端类型检查、构建、设计契约、上游 Node 测试和 E2E。

该设计覆盖多个有明确依赖关系的子系统。实施计划必须拆成三个可独立验证、按顺序执行的计划文件：

1. 上游同步器、路由宿主与基础桥接；
2. 单题深学、多题工作区及其后端持久化；
3. Activity Schema、引导学习、React 页面对齐与最终全量验收。

前一计划通过验收后再执行后一计划；每份计划均交付可运行的软件状态，而不是只提供中间脚手架。
