# 原则、归纳卡与题目绑定统一设计

## 已确认的业务规则

- 原则是稳定的规则身份（`id`、名称、状态），归纳卡是该原则的一对一教学呈现。
- 归纳卡顶部自动显示原则名称；卡片正文是解释，不单独维护会与原则名冲突的标题。
- 题干原则与选项原则分别保存；`metadata.principleIds` 仅保存两者的并集以兼容检索。
- 多题归纳只读取正确选项的原则。每题正确选项必须恰好绑定一个活动原则，且所选题目必须解析为同一原则。
- 已被题目引用的原则不能物理删除，只能停用/归档；先解除或重绑引用才可删除未引用原则。
- Prep Studio 的原则与归纳卡只能成对导入导出。
- 关键词层级的权威来源是 `clues`；`metadata.keywordSystemV2` 仅为兼容镜像。

## 数据契约

```text
metadata.stemPrincipleIds: string[]
metadata.optionPrincipleMap: Record<optionId, string[]>
metadata.principleIds: string[] // 从上述两个字段求唯一并集
```

旧题如只有 `principleIds`，首次保存前保持原值；编辑器将其显示为“题干/通用原则”。有选项映射的旧题不会被自动猜测题干归属。

## 删除与状态

批量“删除”是归档：原则和其归纳卡一同设为 `inactive`。若任一题目的题干、选项或兼容汇总字段引用该原则，操作拒绝并返回引用题数量。这样既不破坏学习历史，也不会留下悬空绑定。
