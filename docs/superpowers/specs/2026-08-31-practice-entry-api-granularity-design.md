# 做题入口接口粒度优化设计

## 1. 背景

做题大厅当前把“判断是否存在未完成进度”和“读取完整练习会话”混在同一个接口中。用户选择试卷或大厅状态变化时，前端会调用未完成会话列表；该列表为每个会话组装完整题目快照、答案和运行状态。点击挑战、学霸或复仇后，前端又串行读取未完成会话、目标会话和新会话数据。

生产证据表明这不是理论问题：`/learning/practice/sessions/active` 已出现数 MB 响应并在一次大厅生命周期内重复请求；未完成挑战会话平均题量超过用户常用的 10 题入口。即使用户选择 10 题，当前后端仍可能读取整份发布试卷或其他未完成会话的题目快照。

本设计替换 2026-08-26 入口加载设计中“通过完整 active session 识别可恢复进度”的部分。多题归纳按需取题设计不受影响。

## 2. 本轮目标

1. 选择试卷时只查询该试卷在当前账号下的挑战、学霸进度摘要。
2. 大厅和选卷过程不读取题目、答案、解析或完整会话。
3. 点击挑战或学霸后才进入会话；无历史进度时按用户选择的题量创建，有历史进度时继续原会话。
4. 复仇模式继续使用账号级全局错题池，不与当前试卷绑定；大厅只读取统计摘要，点击复仇后才读取本次题目。
5. 合并同一页面内重复的摘要和进入请求，避免状态事件造成请求风暴。
6. 保留全部现有用户进度，不清理、不重写生产会话。

## 3. 明确不做

- 不修改作答、判题、草稿保存、暂停、放弃、交卷和报告接口。
- 不修改挑战、学霸、复仇的计分、生命、计时或错题规则。
- 不改变多选题全对才得分的规则。
- 不调整题目冻结快照的数据模型，不新增数据库迁移。
- 不把正确答案或解析的下发时机迁移到作答接口；该优化需要单独设计，不能混入本轮。
- 不一次性删除或结束历史未完成会话。

## 4. 设计原则

“最小粒度”指一次交互只返回完成该交互所需的数据，不是把每个字段拆成一个网络请求。

- 查询摘要与读取内容分离。
- 选卷与进入做题分离。
- 当前试卷与账号全局复仇分离。
- 会话列表与单个会话内容分离。
- 服务端继续作为“恢复旧会话还是创建新会话”的最终判定者，避免多标签页竞态。
- 前端事件只使摘要失效，不直接触发多份完整内容请求。

## 5. 轻量进度摘要

### 5.1 当前试卷摘要

选择试卷后调用：

```http
GET /api/v1/learning/practice/papers/{paperId}/progress
```

可选查询参数 `releaseId` 仅用于说明当前目录版本，不把旧版本的未完成进度排除在外。服务端按 `paperId + mode` 查找 `active` 或 `paused` 会话；若历史数据中同一模式存在多份，则只返回 `lastSavedAt` 最新的一份，不删除其余记录。

响应示例：

```json
{
  "paperId": "paper_xxx",
  "modes": {
    "challenge": {
      "sessionId": "ps_xxx",
      "status": "paused",
      "releaseId": "release_old",
      "answered": 20,
      "total": 60,
      "currentIndex": 20,
      "revision": 4,
      "lastSavedAt": "2026-08-31T09:00:00Z"
    },
    "scholar": null
  }
}
```

响应禁止包含：

- `questions`、`questionOrder`；
- `answers`；
- `analysis`、`reasoningSteps`、正确答案；
- `reportSnapshot`、完整 `runtimeState`；
- 其他试卷或其他模式的会话内容。

### 5.2 全局复仇摘要

做题大厅调用：

```http
GET /api/v1/learning/practice/revenge/summary
```

响应只包含复仇统计、可选题量和全局未完成复仇会话摘要：

```json
{
  "stats": {
    "active": 18,
    "pending": 9,
    "needsRemediation": 4,
    "verificationDue": 5,
    "mastered": 30,
    "unavailable": 0
  },
  "resumable": {
    "sessionId": "ps_revenge",
    "status": "active",
    "answered": 3,
    "total": 10,
    "currentIndex": 3,
    "revision": 2
  }
}
```

该接口禁止返回 `mistakes`、`revengeCandidates` 和 `questionSnapshot`。完整错题池只在用户点击复仇后由服务端内部使用。

## 6. 进入做题

### 6.1 统一进入命令

挑战、学霸和复仇使用同一个入口：

```http
POST /api/v1/learning/practice/sessions/enter
```

挑战或学霸请求：

```json
{
  "paperId": "paper_xxx",
  "releaseId": "release_xxx",
  "mode": "challenge",
  "count": 10,
  "order": "paper"
}
```

复仇请求不传 `paperId`、`releaseId`，`count` 来自全局复仇题量选择。

服务端在现有账号级事务锁内原子执行：

1. 查找该账号、试卷和模式的未完成会话；复仇按账号全局查找。
2. 若存在未完成会话，返回该会话并标记 `resumed=true`。此时忽略请求中的 `count` 和 `order`，不得裁剪、扩充或重排旧会话。
3. 若不存在未完成会话，才按 `count` 和 `order` 创建新会话并标记 `resumed=false`。
4. 双击或多标签并发使用相同业务锁；第二个请求在锁内重新查询并恢复第一个请求创建的会话，只能得到同一会话。
5. 入口失败后重试必须恢复已创建的会话，不能重复创建。

### 6.2 进入响应

进入响应只包含恢复界面所需的会话摘要、轻量题号引用和首批题目内容：

```json
{
  "resumed": false,
  "session": {
    "id": "ps_xxx",
    "paperId": "paper_xxx",
    "releaseId": "release_xxx",
    "mode": "challenge",
    "status": "active",
    "total": 10,
    "answered": 0,
    "currentIndex": 0,
    "revision": 1
  },
  "questionRefs": [
    {"questionId": "q1", "index": 0, "status": "unanswered"}
  ],
  "questionPage": {
    "offset": 0,
    "limit": 10,
    "items": []
  }
}
```

`questionRefs` 只包含答题卡、恢复位置和分页所需的 ID、序号、状态；不得重复嵌入题目内容。

## 7. 题目按需读取

后续题目通过单会话分页接口读取：

```http
GET /api/v1/learning/practice/sessions/{sessionId}/questions?offset=10&limit=10
```

规则：

- `limit` 本轮固定最大为 10。
- 选择 10 题的新会话在首次进入响应中得到全部 10 题，不增加第二次往返。
- 选择 20、60、180 题时先返回当前批次；首题渲染完成后只预取下一批。
- 恢复会话从 `currentIndex` 所在批次开始，不从第 1 题重新加载。
- 已加载批次只缓存在当前页面内存；相同分页请求共用一个进行中的 Promise。
- 服务端只查询本批 `questionId` 对应的发布题目，不得为了返回 10 题读取并实例化整份 180 题快照。
- 媒体继续返回稳定 URL，不把二进制或 base64 内容嵌入 JSON。

为保持现有作答接口不变，本轮不改变“单道冻结题目快照”的字段契约。字段级拆分正确答案、解析和复盘内容属于后续优化；本轮性能收益来自不再提前传输其他会话、其他试卷和未进入批次的题目。

## 8. 前端调用时序

### 8.1 大厅初始化

1. 从已发布试卷目录读取轻量元数据。
2. 选中默认试卷后，仅请求该试卷进度摘要。
3. 单独请求一次全局复仇摘要。
4. 根据摘要更新挑战、学霸、复仇按钮。
5. 不调用完整 active session 列表，不读取题目。

### 8.2 切换试卷

1. 立即更新选中态。
2. 取消前一试卷尚未完成的摘要请求，或用请求令牌丢弃过期响应。
3. 请求新试卷的进度摘要。
4. 相同 `paperId` 的并发摘要请求合并；成功结果按账号和试卷键缓存在当前页面内存，直到相关会话状态变化。

### 8.3 点击模式

- 按钮显示历史进度时，调用 `enter` 后继续原会话。
- 无历史进度时，`enter` 才使用当前选择题量。
- `enter` 进行中禁用三个入口按钮并显示现有统一加载框。
- 成功收到首批题目后立即进入第 1 题或恢复位置；后续预取不阻塞首次渲染。
- 失败后恢复按钮，不保留半初始化的本地会话。

### 8.4 摘要失效

登录变化、完成、放弃或暂停会话只标记相关摘要缓存失效。只有大厅可见且确实需要刷新按钮时才重新请求；会员、目录和复仇统计事件不得各自触发一份完整会话请求。

## 9. 兼容与错误处理

- 未登录用户沿用现有公开试卷读取边界；需要持久化进度的入口仍先要求登录。
- 当前版本已撤回但存在可恢复会话时，沿用现有发布快照续学规则；新建会话必须使用当前可访问的 published release。
- 权限或会员失效时，新建返回 403；历史会话能否续学沿用现有服务端策略，本轮不另改规则。
- 摘要与点击之间出现并发新会话时，以 `enter` 的原子结果为准。
- 历史异常产生多份未完成会话时，恢复最近保存的一份并记录诊断日志，不自动删除其余数据。
- `enter` 以账号、试卷和模式作为业务幂等边界；重复请求返回同一未完成会话。
- 分页越界返回 422 `PRACTICE_QUESTION_PAGE_INVALID`，不返回整份会话兜底。

## 10. 后端边界

- 新增专用 summary 查询构造器，只投影摘要列，不调用 `_session_payload()`。
- 完整会话详情继续保留给现有保存、完成和报告流程；大厅不再消费它。
- 会话题目查询接收明确的 `question_ids` 或分页范围，只加载本批快照。
- 新建会话选择题目时可先读取轻量排序字段并确定选中 ID，再读取选中批次快照；不能先加载全部快照再切片。
- 复仇摘要用数据库聚合与轻量状态计算，不序列化错题快照。
- 现有 owner、角色、会员、发布状态检查必须继续在服务端执行。

## 11. 验收标准

### 11.1 契约

- 试卷进度摘要只含当前 `paperId` 的挑战和学霸摘要。
- 复仇摘要不含错题列表或题目快照。
- 摘要响应中出现 `questions`、`answers`、`analysis`、`reasoningSteps` 即测试失败。
- 题目分页最多返回 10 题，且只返回当前会话题序内的题目。
- `enter` 对已有会话忽略新题量，对新会话严格使用选择题量。

### 11.2 请求数量

- 大厅首次稳定后，同一选中试卷的摘要请求最多一次，全局复仇摘要最多一次。
- 登录、目录、会员和复仇事件同时到达时，相同请求必须合并。
- 点击模式只产生一次 `enter`；首批已含当前 10 题时不立即重复请求同一分页。

### 11.3 数据读取

- 选择试卷不得查询 `paper_release_questions` 的快照内容。
- 10 题新会话不得读取或序列化未选中的发布题目快照。
- active session 摘要不得逐会话调用完整载荷构造器。

### 11.4 行为回归

- 覆盖挑战、学霸的无进度新建与有进度恢复。
- 覆盖新选 10 题但历史为 60 题时继续原 60 题。
- 覆盖复仇全局进度，不受当前试卷切换影响。
- 覆盖 10、20、60、180 题入口和分页。
- 覆盖双击、多标签、摘要过期、权限变化与请求失败重试。
- 现有作答、保存、放弃、完成、报告和多选题测试保持通过。

## 12. 发布顺序

1. 从 `uat` 建立功能分支。
2. 先增加后端摘要、进入和分页契约测试，再实现最小接口。
3. 调整做题大厅只消费轻量摘要和按需题目。
4. 在 UAT 核对请求数量、响应字段、10/20/60/180 题和历史恢复。
5. 由用户完成 UAT 验收。
6. 用户明确批准后合入 `main`，备份正式环境代码与 PostgreSQL，再部署生产。
