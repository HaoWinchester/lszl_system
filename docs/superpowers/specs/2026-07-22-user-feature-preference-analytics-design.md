# 用户功能偏好分析设计

**日期：** 2026-07-22  
**状态：** 已实施，随 v8.6.9 发布

## 目标

为管理员提供“系统设置 → 功能分析”标签页，在任意日期范围内按全站或角色汇总用户对各项功能的使用偏好，并同时展示功能使用热度与结果价值，帮助团队确定优化优先级。

首期覆盖图谱、文件、题库、训练、回忆和学习路径六类面向用户的功能。管理员配置、用户管理和系统设置操作不纳入偏好统计。

## 已确认的产品决策

- 分析同时回答两个问题：哪些功能最常用，哪些功能最能产生成果。
- 数据可按全站或单一角色筛选，并支持任意开始日期与结束日期；范围只覆盖功能上线后已经采集的日期。
- 不提供单个用户画像、行为明细或可识别用户的结果。
- 原始事件不保存图谱正文、文件内容、题目回答文本、IP、设备指纹或浏览轨迹。
- 数据采集失败不得影响任何页面的正常功能；仪表盘没有足够数据时必须明确提示。

## 现状与边界

当前后端已有 `learning_events`，但它面向题目学习事件，只按当前用户读取，不能完整覆盖图谱、文件和学习路径等跨功能行为，也不适合管理员聚合查询。因此首期新建独立的通用功能事件表，不改变既有学习事件的语义或接口。

网页使用 `new-legacy/` 作为上游静态资源，发布版本位于 `frontend/public/new-legacy/`，由同步脚本生成。新前端行为必须在上游资源和生成链路中实现，不修改 `legacy/` 源文件。

## 架构与数据流

```text
用户功能页面
  └─ 进入页面 / 完成关键动作 / 有效停留结束
       └─ 轻量功能事件上报（同源、登录用户）
            └─ FastAPI 校验并写入 feature_usage_events
                 └─ 管理员聚合接口（日期 + 角色）
                      └─ 系统设置「功能分析」仪表盘
```

采集模块是一个共享的 new-legacy 脚本。它负责记录页面进入与有效停留；各页面在既有成功回调中显式发出关键操作和成果事件。上报使用非阻塞请求；请求错误只在开发控制台可诊断，不弹出提示、不阻止保存或跳转，也不重试可能已经成功提交的事件。

## 数据模型

新增 `feature_usage_events`：

| 字段 | 说明 |
| --- | --- |
| `id` | 服务端生成的事件 ID |
| `owner_id` | 内部关联用户；管理员聚合响应绝不返回该字段 |
| `feature_key` | 固定枚举：`graph`、`files`、`question_bank`、`training`、`recall`、`learning_path` |
| `event_type` | 固定枚举：`opened`、`engaged`、`key_action`、`outcome` |
| `action_key` | 允许的功能内动作代码；`opened` 与 `engaged` 为空 |
| `duration_seconds` | 仅 `engaged` 可填；页面前台停留的秒数，单次会话上限为 30 分钟 |
| `occurred_at` | 服务端写入时间，建立索引 |

`feature_key`、`event_type` 和 `action_key` 全部由后端白名单校验，客户端不传递自由文本或业务内容。查询将使用 `occurred_at`、`feature_key`、`owner_id` 的索引，以支持管理员按日期和角色汇总。

## 事件与成果定义

| 功能 | 关键操作（`key_action`） | 成果（`outcome`） |
| --- | --- | --- |
| 图谱 | 创建、修改或整理节点/关系 | 成功保存有变更的图谱 |
| 文件 | 创建、导入、移动或归档文件 | 成功保存文件库变更 |
| 题库 | 创建题库、创建或编辑题目 | 成功保存题库或题目 |
| 训练 | 开始训练、提交答案 | 完成一次答案提交；准确率单列展示 |
| 回忆 | 新增、调整或保存回忆节点 | 成功保存回忆进度 |
| 学习路径 | 开始节点活动 | 完成学习节点或通过阶段测试 |

页面进入仅用于识别访问；`engaged` 只有前台停留达到 10 秒才写入。所有关键操作和成果事件只在原业务操作成功后记录，避免把失败尝试计入偏好。

## 指标口径

每个日期范围和角色条件下，先筛选事件时间，再以 `users.role` 在服务端做聚合。管理员界面只收到功能级结果和样本量。

| 指标 | 计算方式 | 用途 |
| --- | --- | --- |
| 有效用户数 | 至少产生一次 `engaged`、`key_action` 或 `outcome` 的去重用户数 | “常用功能”主排序，反映覆盖面 |
| 关键操作数 | `key_action` 事件总数 | 有效用户数相同的次级排序 |
| 有效停留时长 | `engaged.duration_seconds` 总和 | 展示为辅助维度，不以长时间挂机提高排序 |
| 成果用户率 | 至少有一次 `outcome` 的去重用户数 / 有效用户数 | “高价值功能”主排序 |
| 学习质量 | 训练和学习路径额外显示提交正确率、节点完成率；其他功能显示成果用户率 | 区分完成与学习效果 |

“常用程度”按有效用户数、关键操作数、有效停留时长依次排序，不使用无法解释的加权黑盒分数。“高价值程度”按成果用户率排序，界面同时显示分子、分母和该功能的成果定义，避免在不同功能之间隐瞒口径差异。

偏好矩阵的横轴为有效用户数，纵轴为成果用户率；气泡大小为关键操作数。洞察文案由确定性规则生成：高使用且高成果为优先加固，高使用低成果提示检查流程或引导，低使用高成果提示定向推广，低使用低成果提示进一步调研。首期不调用外部 AI 服务。

## 管理员接口

### 写入功能事件

`POST /api/v1/analytics/feature-events`

- 需要已登录用户。
- 请求只接受 `featureKey`、`eventType`、`actionKey`（可选）与 `durationSeconds`（可选）。
- 服务器从会话取得用户，不接受客户端指定的用户、角色或时间。
- 非白名单的功能、事件、动作，以及不符合事件类型的时长均返回 422。
- 匿名访问返回 401。

### 读取管理员分析

`GET /api/v1/system/feature-analytics?start=YYYY-MM-DD&end=YYYY-MM-DD&role=...`

- 仅 `admin` 可调用；教师、学员、游客和未登录请求分别得到现有权限体系的一致拒绝。
- `start` 与 `end` 为必填 ISO 日期，按 Asia/Shanghai 日历日处理，开始日包含、结束日包含；服务端将结束日转换为下一日零点的排他上界。
- `role` 可省略（全站）或取 `teacher`、`student`、`viewer`；不允许把管理员操作计入分析。
- 响应包括筛选条件、样本提示、六项功能的聚合指标、趋势序列和确定性洞察；不含用户名、事件 ID、动作明细或任何用户级数据。

## 管理员界面

在 `system-settings.html` 和既有 `.ss-*` 布局中增加“功能分析”侧栏标签，复用现有系统设置页面的 DOM 结构、主题和响应式风格。

该标签页按以下顺序呈现：

1. 日期范围控件（任意起止日期）和角色筛选。
2. 活跃用户、有效使用次数、成果用户率三个摘要。
3. 功能偏好矩阵：常用程度与高价值程度并列阅读。
4. 每项功能的可访问数据表，显示有效用户、关键操作、有效时长、成果用户率及训练/学习路径的学习质量。
5. 按日趋势与基于规则的本期洞察。

加载时展示与当前系统风格一致的骨架/文字状态；无数据、筛选无结果和请求失败分别给出明确说明。请求失败不会显示陈旧数据为当前筛选结果。窄屏时筛选和摘要纵向排列，矩阵与表格允许横向滚动而不截断指标。

## 验收与测试

后端自动化测试须覆盖：

- 未登录用户不能写事件；普通角色不能读取管理员聚合。
- 有效事件成功写入，服务端不接受伪造的用户、角色或时间。
- 非法功能、动作、时长和事件组合得到 422。
- 日期范围采用包含结束日的正确边界，角色筛选只统计对应角色。
- 聚合返回所有六类功能，排序与指标计算符合上述口径，且响应中不含用户名或事件明细。
- 管理员无数据和筛选无结果均返回可渲染的空结果而非 500。

前端与浏览器验证须覆盖：

- 六个功能页面会在成功关键操作和结果保存后发出白名单事件，失败操作不会发出成果事件。
- 采集请求失败时原有保存、训练和导航仍然完成。
- 系统设置只有管理员能看到并调用分析标签；筛选会刷新摘要、矩阵、表格、趋势和洞察。
- 现有 new-legacy 同步和运行时契约测试继续通过，且桌面与窄屏下不破坏现有系统设置视觉结构。

## 非目标

- 单用户画像、可导出的行为明细、营销追踪、外部统计 SDK、实时流式面板与 AI 自动决策不属于首期。
- 不回填上线前缺失的跨功能行为数据，也不修改原有 `learning_events` 的读写行为。

## 发布说明

该功能随 v8.6.9 发布上线：

- 原始遥测保持最小：`feature_usage_events` 仅记录允许列表内的功能/动作组合与停留秒数，不含图谱正文、文件内容、题目答案、IP 或自由 payload。
- 管理员聚合响应（`GET /api/v1/system/feature-analytics`）在 SQL 内完成去重计数，不含任何用户标识（无 username、ownerId、事件 ID 或行为明细）。
- 历史 cross-function 行为不回填；有意义的分析数据自发布后开始累计，发布前的功能使用不纳入统计。
- 管理员可在「系统设置 → 功能分析」按任意日期区间与角色查看常用度与成果用户率。
