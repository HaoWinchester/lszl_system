# 做题模式、解析开关与退出经验结算设计

## 1. 已确认范围

1. 挑战、学霸模式在做题期间不展示解析，不提供手动交卷功能。
2. 练习模式恢复原来的可作答模式：从学习记录进入对应试卷，无生命和时间限制，可重新练习，保留上一题、下一题与移动端滑动切题。
3. 练习模式使用统一解析开关；选项下方不再动态生成独立的“查看解析”按钮。
4. 正常退出、关闭或完成时保存当前试卷的作答并结算经验，包括中途退出已获得的经验。
5. 作答期间只在前端记录，不逐题请求保存接口，也不做定时或后台合并自动保存。
6. 强制关闭、断网以及关闭请求未送达，不做恢复兜底，不新增离线队列。

用户已撤回“练习模式只读复盘、不允许作答、不产生经验”的提议。普通练习仍按旧规则通过实际作答获得经验；查看原成绩报告仍只读、不产生经验，两者不是同一入口。

本规格定向修订 [2026-08-27 设计](2026-08-27-practice-client-grading-collapsible-answer-sheet-design.md)：保留本地即时判题、显式整卷保存、服务端复核、答案锁定和折叠答题卡；替换挑战/学霸的手动交卷规则，并新增正常关闭的单次保存尝试。未改动的报告、权限、发布版本及复仇补救规则继续有效。

## 2. 现状依据与方案选择

核对基线：`main` 提交 `325f508`；旧练习行为参考提交 `b3b59f3` 及后续移除大厅练习卡片的调整。

- 当前学习记录入口会打开成绩报告或重新进入挑战/学霸，而不是稳定地进入独立练习模式。
- 当前选项作答和答题卡回看均有展示解析的路径，只移除一个按钮不能满足要求。
- 后端 `PracticeSession` 只支持 `challenge/scholar/revenge`，恢复登录用户的普通练习需要补齐 `practice`，不能伪装成挑战。
- `pause_session` 会保存答案并计算经验，但经验面板目前只聚合已完成会话。
- `abandon_session` 目前不接收并保存最新整卷答案，直接退出可能遗漏本次作答。
- 当前 `beforeunload` 只有离开提醒，没有关闭保存请求。

| 方案 | 请求与体验 | 本次结论 |
| --- | --- | --- |
| 退出、关闭、完成时集中保存 | 作答期间无保存请求；异常离开可能丢失未保存内容 | 采用，符合用户确认的边界 |
| 后台合并保存 | 多次作答合并为请求，不是一题一请求，但仍会产生后台写入 | 不采用 |
| 每题保存并等待服务器确认 | 每次作答写入，反馈和失败处理容易受网络影响 | 不采用 |

## 3. 模式与界面规则

| 场景 | 能否作答 | 解析 | 手动交卷 | 经验 |
| --- | --- | --- | --- | --- |
| 挑战 | 可以，沿用生命与失败规则 | 做题期间始终不显示 | 无 | 实际作答后集中结算 |
| 学霸 | 可以，沿用时间池与生命规则 | 做题期间始终不显示 | 无 | 实际作答后集中结算 |
| 练习 | 可以，无生命和计时限制 | 由统一开关控制 | 恢复旧模式，不增加手动交卷入口 | 实际作答后集中结算 |
| 历史成绩及报告错题回看 | 不可修改原答案 | 保留现有报告回看能力 | 无 | 不新增 |
| 复仇 | 沿用现有补救流程 | 保留专用补救解析 | 沿用现有流程 | 使用相同的防重复结算能力，不修改奖励规则 |

### 3.1 挑战和学霸

- 选择选项后保留原有正误反馈、生命、连胜和计时变化，不展示解析面板或“查看解析”按钮。
- 答题卡跳转、上一题/下一题、滑动切题、语言切换、超时、恢复进度均服从同一解析禁用规则。
- 从主页面和答题卡移除交卷入口；事件处理也必须受模式规则约束，不能仅用 CSS 隐藏。
- 全部题目已经作答时自动完成、保存并展示结果。判断依据是有效已答题数（含已确认的学霸超时作答）等于题目总数，不能以“当前位于最后一题”替代。
- 学霸生命归零按既有规则结束；挑战生命归零保留“继续作答 / 返回大厅”，继续作答不提前完成试卷。
- 保留已修复的挑战容错：新开 180 题初始 54 点生命，第 54 道错题触发失败提示；第 3、4 道错题及每 5 题均不触发阶段弹窗。

### 3.2 恢复普通练习

- 学习记录按试卷聚合；“进入练习”指向对应试卷的 `practice` 模式，不再以原挑战/学霸模式重新开局。
- 保留独立“查看成绩”入口，明确区分重新练习与历史报告。
- 重新练习开始新一轮作答，不把上一轮答案灌入当前轮；若该卷已有未完成的普通练习，沿用既有恢复与重新开始确认规则，不静默丢弃进度。
- 同一轮中选定答案后锁定，回看不能改答案或再次获得经验；新开一轮才可重新作答并按原规则获得经验。
- 题量及顺序沿用现有设置规则；恢复时使用该会话冻结题单。历史入口不得误用另一份试卷。
- 新一轮沿用旧入口的发布目录与权限检查，不能利用历史记录绕过下架、订阅或账号权限。题库更新后创建的新练习使用获准的发布版本，原报告不随之改变。
- 全部答完后自动完成，仍可从成绩入口回看；跳到最后一题作答但前面仍有未答时不提前结束。
- 重复练习在列表中只更新同卷次数、最近时间和最近成绩，不重复生成试卷行。后端保留各轮会话，不能覆盖原始成绩。
- 有已答题的暂停及结束记录也进入历史；同一 session 多次保存只算一轮，不能每次退出都增加练习次数。未完成记录展示最近正确率与进度，不冒充正式成绩报告。

### 3.3 统一解析开关

- 只在普通练习显示“显示解析”开关，放在现有题目导航区域，保留已有布局结构。
- 复用已有 `getPracticeAutoExplain/setPracticeAutoExplain` 偏好入口；没有历史偏好时默认开启，符合旧模式。
- 开启后，仅对本轮已答的当前题显示正确答案和解析；未答题不提前揭示。
- 关闭后立即隐藏解析面板，不另生成“查看解析”按钮。再次开启可查看当前已答题解析，不必重新作答。
- 切题与语言切换后仍遵守开关状态；切换开关不产生业务保存请求或经验。
- 移除选项区动态生成的通用解析按钮；复仇的专用补救步骤不混入普通练习的开关逻辑。

## 4. 保存和结束时机

| 操作 | 服务器动作 | 状态与界面 |
| --- | --- | --- |
| 开始或恢复 | 读取题目/创建或恢复会话 | 保留现有进入加载提示 |
| 未触发结束的选择选项、切题、切语言、开关解析 | 不写服务器 | 前端即时反馈 |
| 打开或取消退出确认 | 不保存、不结算 | 继续当前作答 |
| 保存并退出 | 整卷保存、结算新增经验 | `paused`，成功后回大厅 |
| 结束本次练习/放弃继续 | 保存已答、结算新增经验 | `abandoned`，不再恢复该轮 |
| 全部答完或学霸规则结束 | 整卷复核、结算、冻结报告 | `completed`，展示结果 |
| 正常离开页面 | 发送一次关闭保存请求 | 保存为可恢复进度，不伪装成全部完成 |
| 切换浏览器标签、最小化 | 无保存请求 | 不因页面隐藏而结束练习 |

“放弃”只表示不继续这轮，不能丢弃已经获得的经验。退出按钮文案要明确表达这一点，不再承诺“不保存本次作答”。

最后一次作答触发全卷完成，或学霸作答触发模式结束时，会发送一次整卷结束请求；这是结束结算，不是恢复逐题保存。

### 4.1 显式退出和自动完成

前端捕获整卷答案、作答顺序和运行状态，通过统一保存协调入口发送。发起后冻结本轮新增作答和重复点击，沿用公共加载反馈。成功回执后才清除 dirty 状态并离开题目界面。

请求失败时保留当前内存答案，显示可重试错误，不显示“已保存”或虚增经验。这里仅保留现有显式操作的失败反馈，不扩展离线重试、持久队列或后台恢复。

### 4.2 正常关闭

- 直接关闭标签页、刷新或离开当前文档，在 `pagehide` 生命周期使用小体积的 `fetch` keepalive 请求尝试保存。复用暂停保存服务，不复制判题和结算实现。
- 不在 `visibilitychange` 或 `beforeunload` 发送保存请求；切标签不保存，取消原生离开确认不保存。已有 dirty 离开提醒保留。
- 只传答案选择、顺序、必要运行状态、revision 和幂等标识，不上传题干、解析、报告或完整题库。
- 关闭发送仍使用同源登录会话与现有写入安全检查，不为生命周期请求开放匿名写入口或放宽 owner 校验。
- 发布前验证支持的最大题量下关闭载荷处于浏览器 keepalive 限额以内；载荷超限不得静默声称成功，需使用更紧凑的字段表示或调整关闭传输契约。
- 已经显式退出成功的页面不再补发。完成请求与关闭发生竞争时沿用同一保存意图，不再追加会把完成态降为暂停态的请求。
- 如页面进入浏览器往返缓存，恢复显示时读取最新会话状态再恢复作答，避免旧 revision 继续写入。
- 关闭请求发出不等于服务器已确认；仅服务器成功提交的答案和经验才算保存。强制关闭、断网、事件未触发、请求未送达均在用户明确排除的兜底范围内。

该选择不会保证所有设备的关闭事件都触发。浏览器相关边界参见 [MDN sendBeacon 的生命周期与传输说明](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon)。本次不为此增加自动保存或浏览器业务数据缓存。

## 5. 服务端经验结算

### 5.1 单一业务入口

在现有 `practice_session_service.py` 扩展共享保存/结算能力，让暂停、结束本轮、正常关闭和完成都复用：

1. 校验登录账号、会话 owner、状态、revision、题目归属及选项合法性。
2. 校验已有锁定答案不可删除、修改或改写顺序。
3. 按会话冻结的发布快照及有效作答顺序重算正误和整轮经验，不接受客户端的 `correct` 或 `experience` 作为事实。
4. 保存整卷答案和运行状态，计算此次尚未计入账户的经验差额。
5. 在同一数据库事务写入经验差额记录、已结算累计值和会话状态；失败全部回滚。
6. 提交后 refresh，再返回可信的会话统计和本次入账差额。

复用现有经验公式，不另设普通练习奖励倍率。暂停不生成正式完成报告，也不提前推进既有“完成时才写入”的错题与复仇状态。

### 5.2 防止重复和跨日错算

- 会话保留服务端维护的已结算累计经验；本次差额为整轮重算经验减去已结算累计值。非法改写导致累计值回退时拒绝写入，不以客户端请求修正历史。
- 经验差额复用 `LearningEvent` 存储，采用独立事件类型，与历史列表摘要事件分开。记录 owner、session、差额、结算时间和可去重标识。
- 行锁、revision 和稳定的请求幂等标识共同保护重试；同一请求只能增加一次经验。不同载荷不能冒充同一次重试。
- 保存退出得到 100 经验，恢复后整轮累计 140 时，只再入账 40。重复退出、关闭重发、结果刷新均不再增加这 140。
- 不同轮真实重新作答按旧规则计经验；同轮回看、解析开关、历史报告均不计经验。
- 总经验、学习周和每日经验按差额记录聚合。跨日恢复只把新差额记到新日期，不把原有整轮经验移动到最新保存日期。
- 保留现有学习周“周日 19:00”边界及现有统计时区。
- 清空学习记录不得回收已经入账的经验；历史列表清理与经验事件分开，不能随会话删除级联删掉经验事件。

### 5.3 旧数据兼容

- 对既有已完成会话，以服务端可信统计建立一次性结算基线，保留其原完成时间；迁移可重跑而不重复入账。
- 聚合切换到差额记录后，不再叠加同一批已完成会话的 `stats.experience`。
- 旧客户端上传的非可信摘要经验不补记，不恢复使用可伪造的统计入口。
- 既有未完成会话在下一次显式保存、正常关闭或完成时按其服务端有效答案结算，不在升级时擅自结束或放弃进度。

## 6. 模块边界与兼容

| 职责 | 修改位置及约束 |
| --- | --- |
| 模式编排、历史进入、退出和自动结束 | `new-legacy/src/100-practice-mode.js`，不复制持久化实现 |
| 模式显示能力 | 在 `new-legacy/src/` 的共享模块集中定义作答、解析及交卷能力，题目与答题卡统一消费 |
| 答题卡 | 扩展 `112-practice-answer-sheet.js` 的模式能力输入，保持折叠抽屉、筛选及键盘交互 |
| 本地草稿 | 复用 `114-practice-draft-state.js` 的答案锁定、顺序、统计和 dirty 管理 |
| 请求协调与关闭发送 | 在现有公共会话适配器/核心能力上扩展，统一防重复、请求序列和生命周期处理 |
| 持久化与结算 | 后端 service 处理，API 只做权限、参数与响应编排 |
| 普通练习合法模式 | 同步调整服务校验、模型 check constraint、迁移及相关契约，新增 `practice` |
| 经验聚合与历史列表 | `learning_service.py`，包括中途保存记录、试卷聚合和独立成绩入口 |

不得整段回滚旧版页面或适配器；恢复旧模式的产品行为，同时保留现有服务端持久化、账户隔离、不可变发布快照和前端修复。对共享结算的修改需覆盖复仇旧流程，避免其完成经验被计算两次。

旧接口的兼容不等于新界面继续提供手动交卷。后台完成服务继续用于自动结束和兼容旧客户端，新界面的按钮与事件能力单独约束。

## 7. 验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| 挑战/学霸首次作答、回看、语言切换、恢复、超时 | 无解析面板、通用解析按钮、手动交卷入口 |
| 新开 180 题挑战，累计错 3、4、53、54 题 | 前三处不弹失败框，54 处生命为 0 才提示；无五题阶段弹窗 |
| 从历史试卷进入练习 | 实际 mode 为 practice，可作答，无生命/计时，不自动进入原挑战 |
| 已有未完成普通练习 | 正确恢复；重新开始须走现有确认，不覆盖原进度 |
| 练习解析开关 | 已答题随开关即时显示/隐藏；未答题不开解析；无独立解析按钮 |
| 练习切题和重复点击 | 同轮答案锁定，已答题不重复加经验；新一轮可重新作答 |
| 跳到最后一题先作答 | 前面仍有未答时不自动结束；全部答完只完成一次 |
| 未触发结束的连续作答、切题、切语言、开关解析 | 网络记录中没有答案或进度写请求；最后一次触发结束时仅有一次整卷完成请求 |
| 显式保存退出、结束本轮 | 保存最新全部作答，含退出前最后一题；中途获得的经验进入面板 |
| 正常关闭、刷新、页面离开 | 验证网络正常时真实 keepalive 请求到达，服务器答案及经验更新；不能只断言请求已排队 |
| 切换标签、取消离开确认 | 没有业务保存请求 |
| 重复退出、关闭补发、完成竞争、多标签冲突 | 不重复奖励、不降级终态、不静默覆盖另一端进度 |
| 跨日保存与恢复 | 昨日经验不迁移，只新增当日差额 |
| 旧完成会话迁移、清空历史、报告回看 | 基线不翻倍；清空记录不减经验；回看不增加经验 |
| 篡改正误、经验、题目或已锁定答案 | 服务端拒绝或可信重算，无部分提交；owner 隔离有效 |
| 复仇及既有报告 | 补救、错题推进、冻结报告和既有奖励规则无回归 |

验证优先扩展现有草稿、会话、答题卡、后端结算及浏览器测试；只在现有套件没有自然归属时新增测试文件。正常关闭需真实后端验证，不使用仅拦截请求的模拟成功作为入账证据。

## 8. 实施与发布边界

本文不修改业务代码，不改变当前 active release。用户审阅后再制定依赖明确的实施计划。

实施完成后运行相关后端、前端契约及浏览器回归。前端只改权威源 `new-legacy/` 和职责明确的共享适配层；发布前比较候选与 active site 的文件数、路径及关键页面，必须通过 `manage-new-legacy.js update new-legacy --skip-browser` 完成同步、构建、验证和 promote。

最后按仓库纪律提交生成产物、合入并推送 main，核对远端引用。不得将源文件修改或测试通过表述为用户已经运行新版本。
