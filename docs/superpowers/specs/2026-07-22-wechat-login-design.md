# 微信网站登录设计

## 目标与范围

为已审核的微信开放平台网站应用接入真实扫码登录，同时保留仅供开发验证的后端演示登录。首次扫码的微信用户自动创建为 `student`；现有用户名/密码账号可在登录后绑定微信，并在之后使用微信进入原账号。

本设计只覆盖微信登录。Native 支付二维码、订单和支付回调是下一项独立工作，不在本次修改范围内。

## 既定配置

- 微信开放平台的“授权回调域”保持 `lszl.aihuanpu.com`，该字段只能填写域名。
- 项目发送给微信的完整 `redirect_uri` 使用 `https://lszl.aihuanpu.com/api/v1/auth/wechat/callback`。
- AppID、AppSecret 及其他敏感凭证只在后端环境变量或受保护的服务器配置中读取；不写入前端构建产物、Git 或浏览器存储，也不由读取配置接口返回。
- 本次只提交配置键和示例占位值，不提交任何真实凭证。

## 方案选择

采用“后端回调并重定向”方案，而不是让浏览器接收 `code` 后自行换取用户资料。

原因：AppSecret 永不离开服务器；授权 `state` 与登录/绑定意图由服务端会话保存；成功后的 FastAPI session 可被页面 bootstrap 直接读取；用户不会停留在携带授权码的页面 URL。

## 授权流程

```text
页面微信入口
  -> GET /api/v1/auth/wechat/auth-url?intent=login|bind&return_path=<当前相对路径>
  -> 后端将 state、intent、return_path 和（绑定时）当前 username 写入 session
  -> 跳转 open.weixin.qq.com 授权页
  -> 微信 GET /api/v1/auth/wechat/callback?code=...&state=...
  -> 后端验证单次 state，服务器换取 access_token / openid / unionid
  -> 登录或绑定，写入 kg_session
  -> 302 回经过校验的 return_path，并附带一次性结果提示
```

`return_path` 只能是本站以 `/` 开头的页面路径，拒绝协议、主机名、`//` 和未知目标，防止开放重定向。

## 登录与绑定规则

### 未登录扫码（`intent=login`）

1. 依次通过 `openid` 与非空 `unionid` 查找已有微信绑定。
2. 找到且账号状态为 active：更新头像、昵称、最后登录时间，并建立登录会话。
3. 未找到：创建用户名不可预测的 `wx_` 前缀账号，角色固定为 `student`，保存微信标识后建立登录会话。
4. 找到但账号被暂停或归档：拒绝登录，页面给出可理解的恢复提示。

### 已登录绑定（`intent=bind`）

1. 授权开始时将当前登录用户名写入 session；回调时再次确认该账号仍有效。
2. 若 `openid` 或 `unionid` 已绑定到其他账号，拒绝绑定，绝不迁移或覆盖绑定关系。
3. 若已绑定当前账号，按幂等成功处理并刷新昵称、头像和最后登录时间。
4. 否则将微信资料写入当前用户的 `wechat` JSONB 字段，并记录绑定时间。

提供解绑接口与账号中心的“解绑微信”操作；解绑仅移除微信登录标识，不删除用户、订阅或业务数据。管理员可按既有用户管理权限查看绑定状态，但不能获取 token 或密钥。

## 后端边界

- `wechat_service` 继续负责构建授权链接、code 换 token、获取用户资料与按标识查找用户；补充分离的绑定/解绑服务方法。
- `auth` 路由新增回调 GET、绑定授权入口与解绑接口。读取授权配置的公共端点只返回是否已配置和模式，绝不返回 Secret。
- 所有微信账号写入后均 `commit` 与 `refresh`；操作日志记录登录、绑定与解绑结果，不记录 code、access token、AppSecret 或私钥。
- 演示登录继续受 `enableDemo` 开关保护，并返回正常后端 session；正式生产关闭演示模式。

## 前端边界

- 保持现有登录弹窗、className 和 CSS；微信入口的正式动作改为请求后端授权 URL 后整体跳转。
- 移除正式模式中伪二维码、localStorage `state` 和浏览器直接换取 `openid` 的依赖。
- 演示入口调用 `/api/v1/auth/wechat/demo-login`，把返回用户写入现有远程认证运行时并触发页面刷新。
- 在现有账号中心添加“绑定微信 / 解绑微信”入口；按钮根据登录态、绑定状态和配置状态显示实际可执行的动作与明确错误/成功反馈。
- 修改源 `new-legacy/` 与运行时 adapter，随后使用项目既有同步发布脚本生成新的版本化 `frontend/new-legacy-releases/`；不手改活跃生成包。

## 测试与验收

后端测试（HTTP 请求以 mock 代替微信外网）：

1. 未配置正式凭证时，正式授权入口明确拒绝；demo 开关关闭时 demo 登录拒绝。
2. 授权 URL 生成后，正确 state 可以完成首次创建并写入 session；错误或重复 state 被拒绝。
3. 已绑定微信再次登录复用原账号；暂停账号无法登录。
4. 已登录用户可绑定未使用的微信；绑定到其他账号时拒绝；解绑后记录被移除。
5. 外部换 token/用户信息失败时，不创建账号、不写会话，且安全返回原页面。

前端/浏览器验收：

1. 正式微信入口可用时跳转后端生成的授权地址；未配置时给出具体提示。
2. 演示登录由后端 session 驱动，刷新后仍是相同账号，不生成浏览器本地业务账号。
3. 账号中心的绑定、已绑定、解绑和冲突提示都可点击、可恢复，且沿用原有页面结构与样式。
4. 页面刷新后，bootstrap 从服务端读取登录用户和微信绑定状态；不同账户不会互相看到绑定信息。

## 非目标

- 不在本次更换用户现有的 AppSecret 或 APIv3 密钥。
- 不实现 Native 支付下单、二维码展示、订单轮询、支付回调或退款。
- 不允许仅凭微信昵称/头像匹配或合并账号。
