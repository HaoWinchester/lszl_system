# 统一账号菜单设计

## 背景与目标

用户发现已登录状态胶囊与独立“退出”按钮被拆成两组，视觉上悬空且在窄宽度顶栏中进一步挤压导航。该反馈作为全站界面规则处理，而不是仅调整截图中的一个间距或仅改三个账号按钮。

目标：任何同一语义下的信息、动作与状态都必须形成单一、完整且可扫描的视觉组；账号状态与退出只是首个具体落地项。

## 全站界面洁癖规则

以下规则适用于所有顶栏、工具栏、抽屉、弹窗、卡片头部和固定浮层：

1. 同一对象的状态与操作必须同组：例如账号与登录/退出、抽屉标题与关闭、画布选择与改名/删除；不得出现孤立的“第二块”按钮。
2. 同一组内的控件高度、基线、圆角、边框语义和水平间距必须一致；每个按钮、输入框、标签和图标按钮中的文字、图标、数字、箭头都必须在自身命中区域内水平与垂直几何居中。除明确标注为列表项、表格单元格或左对齐文本按钮外，不允许内容无意偏左、偏右、偏上或偏下。
3. 不同语义组之间才使用更大的留白、分隔线或背景区分；不能用随机空隙制造“看起来像断开”的布局。
4. 390px、944px 与 1440px 三档下，不允许中文逐字竖排、控件越界、关闭键被标题挤出、固定浮层遮住主要任务或按钮底部不可达。
5. 任何用户报告的视觉缺陷都要归入上述某条规则，并添加可重复的结构或浏览器回归检查；不再只修截图位置。几何检查必须比较控件盒与其文字/图标盒的中心点，不只检查元素是否存在。

## 已确认的交互方向

采用“单一账号菜单”方案：

- 登录态：入口显示彩色状态点、显示名、角色（当角色与显示名不同）和下拉箭头；不显示“已登录：”前缀，也不显示外置退出按钮。
- 访客态：入口显示“访客只读”和下拉箭头；登录动作在菜单中。
- 菜单：登录态提供“退出登录”；访客态提供“登录”。后续页面若已具备相应能力，可继续提供用户中心等账号动作，但不能重新引入外置退出按钮。
- 可访问性：入口保留 `aria-haspopup="menu"`、`aria-expanded`，菜单支持 Esc、点击外部关闭与键盘导航；退出仍走现有的真实认证登出链路。

## 实现设计

1. 将首页 `41-account-menu.js` 中固定 ID 的菜单行为提取为可复用挂载器；首页继续通过相同接口初始化。
2. 三个目标页面使用同一套菜单标记、样式和控制器；原有 `authLoginBtn` / `authLogoutBtn` 保留为隐藏的行为代理，避免改动认证弹窗和远程登出实现。
3. 菜单内的登录/退出项只触发这些既有代理，因此成功、失败、刷新以及后端 session 清理的语义完全沿用当前实现。
4. 为中等桌面和窄屏设置同一条布局规则：账号入口不可逐字换行；低优先级状态在必要时收纳，不能挤压核心导航。
5. 建立页面级视觉审计清单：每个页面在 390px、944px、1440px 下检查语义分组、控件内部文字/图标的水平与垂直中心偏差、边界安全区、文本换行和固定层遮挡；发现项按全站规则归类、修复并记录。

## 回归与验收

| 场景 | 预期 |
| --- | --- |
| 访客打开三个目标页面 | 只有一个账号入口；菜单内出现“登录” |
| 已登录用户打开三个目标页面 | 只有一个账号入口；菜单内出现“退出登录” |
| 点击退出 | 继续调用现有远程登出链路，刷新后恢复访客态 |
| 390px / 944px / 1440px | 账号入口与导航不重叠、不逐字竖排、不出现外置退出按钮；所有审计页的同组控件不越界、不遮挡、不出现错误的独立视觉块；按钮/标签内的文字与图标中心偏差受统一阈值约束 |
| 键盘与鼠标 | Enter/Space 打开、Esc/外部点击关闭，菜单项可激活 |

测试将新增两层防线：账户控件矩阵覆盖三页无可见外置退出按钮、访客/登录态、菜单开关与登出后的访客刷新；页面视觉清单覆盖全站审计页的分组、控件内部文字/图标中心偏差、边界与遮挡规则。每个新增修复项都必须先补回归用例。
