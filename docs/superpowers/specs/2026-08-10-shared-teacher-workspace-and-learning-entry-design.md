# 教师公共工作区与学习入口整合设计

## 背景

当前系统已经具备 PostgreSQL 题目目录、录入程序批量同步、原则与归纳卡表、部分全局共享运行时数据，以及管理员/教师角色权限，但教师业务仍存在多套数据边界：

- 题库和试卷模型保留 `owner_id`，题库读取主要依靠所有者或逐题库协作者授权。
- 教师工作台部分统计仍读取按当前账号分区的浏览器数据。
- 科目、知识树、课程、学习任务及发布内容中，部分键已经进入 `shared_runtime_states`，部分草稿或工作数据仍按账号保存。
- 录入程序可以同步到服务器题目目录，但主程序已打开时还没有统一的业务版本通知和局部刷新协议。
- 试卷只支持按领域配额补题，原则库尚未成为试卷补题维度。
- 单题深学仍散布在试卷发布模式、课程任务、帮助、跳转和独立学习页中。
- 管理后台总览的统计卡未全部承担业务跳转；登录后也缺少统一的学习方向选择入口。

本次设计把管理员和教师的教学内容统一为服务器权威的公共工作区，同时完成测试题清理、原则补题、单题深学下线、总览跳转、登录后四选一入口，以及录入程序到主程序的自动同步。

## 用户确认的产品规则

1. 所有管理员和所有教师共享教学数据，均可查看、创建、编辑和删除。
2. 正式导入题目保留；示例、演示、手工测试及自动化测试题清空。
3. 公共范围包括题目、训练配置、原则、归纳卡、联想设置、试卷、课程、学习任务和教师工作台统计，草稿与已发布内容都包含在内。
4. 管理后台总览统计卡可以跳转到对应业务页面。
5. 试卷提供“按领域配额”和“按原则配额”二选一补题。
6. 单题深学完整下线；旧历史配置保留但不再展示或运行，旧链接跳转到刷题。
7. 每次成功登录后的首次进入知识图谱显示四选一弹窗，同一次登录只显示一次。
8. 录入程序中业务内容的“保存”和“同步到题库”成功后，主程序无需手动刷新即可看到变化；“保存工作区到本机”仍仅保存本地草稿。

## 目标与非目标

### 目标

- 建立管理员和教师共用、跨账号、跨浏览器和跨设备一致的服务器公共教学工作区。
- 保留操作者归属和审计能力，但不再用创建账号限制管理员/教师访问。
- 安全清理非正式导入题目，并保持历史发布和学习记录可追溯。
- 让原则成为试卷补题的一等配置维度。
- 从产品入口、发布策略和运行路由完整移除单题深学。
- 建立可靠的录入程序保存、服务器提交、版本通知和主程序局部刷新链路。
- 不改变现有页面主体排版、画板结构或用户已批准的 Focus / Vega 局部皮肤边界。

### 非目标

- 不共享个人知识图谱、个人做题记录、学习进度、个人布局和偏好。
- 不向教师开放用户管理、系统设置等管理员专属能力。
- 不删除用户账号，也不清理与题目无关的个人学习数据。
- 不物理删除会破坏已发布历史快照的数据。
- 不借本次工作重写 `new-legacy` 为 React，也不修改 `legacy/` 源文件。
- 不把“保存工作区到本机”改成正式发布或服务器同步操作。

## 总体方案

采用服务器统一公共工作区方案。PostgreSQL 和服务器共享状态是正式数据源；浏览器存储只承担个人偏好、未完成本地草稿和必要的兼容缓存。

现有结构按数据性质分为三类：

| 数据类型 | 权威存储 | 访问边界 |
| --- | --- | --- |
| 题库、题目、原则、归纳卡、试卷及题目引用 | PostgreSQL 业务表 | 管理员和教师共同读写；学员只读已发布、可学习内容 |
| 科目、知识树、联想库、课程、学习任务及兼容发布状态 | 现有共享运行时状态，逐步收口到带修订号的服务器接口 | 管理员和教师共同读写；学员按发布规则读取 |
| 个人图谱、学习进度、做题记录、布局和偏好 | 账号隔离的业务表或运行时状态 | 仅当前账号 |

题库和试卷仍保留原始创建人字段用于审计，不通过把所有记录改绑到虚构“公共账号”来实现共享。服务层直接依据角色和业务范围授权：`admin` 与 `teacher` 对公共教学内容拥有相同的增删改查能力；`student` 与 `viewer` 只走现有学习内容可见性规则。

## 公共数据与权限设计

### 公共范围

公共教学工作区包含：

- 科目、当前知识树、历史版本和科目级联想库。
- 题库、完整题目、标签、关键词、知识点、推理步骤和训练配置。
- 原则、易混原则关系、归纳卡。
- 试卷分类、草稿、手动选题、配额、发布版本和发布历史。
- 课程草稿、课程发布版本和学习任务。
- 教师工作台统计及其数据来源。

### 权限

| 动作 | 管理员 | 教师 | 学员/游客 |
| --- | --- | --- | --- |
| 查看公共草稿 | 允许 | 允许 | 禁止 |
| 创建公共内容 | 允许 | 允许 | 禁止 |
| 编辑公共内容 | 允许 | 允许 | 禁止 |
| 删除公共内容 | 允许 | 允许 | 禁止 |
| 发布/撤回试卷和课程 | 允许 | 允许 | 禁止 |
| 查看已发布学习内容 | 允许 | 允许 | 按现有订阅与学习权限 |
| 管理用户或系统设置 | 允许 | 禁止 | 禁止 |

所有服务端写接口都必须重新校验角色，不能只依赖页面隐藏按钮。逐题库协作者表可以保留用于未来外部协作者场景，但不再成为本组织管理员/教师访问公共题库的前置条件。

### 归属与审计

每个业务实体保留或补齐：

- `created_by` / 创建时间；
- `updated_by` / 最后修改时间；
- 删除人、删除时间和删除原因；
- 业务修订号；
- 发布、撤回、批量同步和清理操作的审计记录。

所有管理员和教师都可以删除，不限制为创建人。界面仍显示创建人和最后修改人，便于协作追溯。

### 删除语义

- 未被引用且未发布的草稿可物理删除。
- 被试卷、课程、任务或发布版本引用的实体从当前公共工作区删除并停止继续使用，但保留墓碑、审计和不可变发布快照。
- 当前草稿中的失效引用在事务内移除并重算题数；历史发布快照不被回写。
- 删除接口返回受影响引用摘要，界面在确认前明确说明影响。

### 并发控制

- 题目继续使用现有数据库编辑租约；其他教师打开被锁题目时进入只读或明确提示占用者。
- 其他公共实体使用修订号进行乐观并发控制。
- 过期修订写入返回冲突，不允许后写无提示覆盖先写；客户端提供重新载入最新版本的恢复动作。
- 批量同步使用幂等键和数据库事务，整批成功或整批回滚。

## 数据清理与迁移

### 清理原则

保留正式导入题目及其必要关联数据，删除其余题目。测试数据识别优先于“是否走过导入接口”，因此自动化测试通过导入接口写入的夹具仍然删除。

保留候选包括：

- 正式题库导入记录、正式录入程序批次或可验证的历史导入标记所关联的题目；
- 上述题目依赖的题库、标签、原则、归纳卡、知识关联和训练配置。

删除候选包括：

- 示例题、演示题和未被确认保留的手工创建题；
- `pytest`、`E2E`、`UI测试`、学习会话测试等自动化数据；
- 带测试时间戳的 Prep 题库和其他明确测试批次；
- 清理后为空且不承载正式配置的测试题库。

### 安全流程

1. 对数据库和相关共享运行时状态做完整备份。
2. 只读扫描题目来源、上传批次、审计、题库名称、测试标记和引用关系。
3. 生成三份报告：保留清单、删除清单、受影响试卷/课程/任务清单。
4. 对来源不明确的数据停止自动删除并放入人工复核区；未完成复核不执行正式清理。
5. 在单个维护事务中执行题目清理、空题库清理、草稿引用修复和共享访问迁移。
6. 校验保留题目数量、内容哈希、题库归属、原则引用和当前试卷题数。
7. 失败时整体回滚，并保留备份和清理报告。

清理不删除用户账号，不修改个人学习进度。已发布试卷和课程的历史快照继续可追溯；重新编辑或发布时只能引用当前公共池内保留的题目。

## 试卷补题设计

### 补题方式

试卷编辑器增加明确的“补题方式”切换：

1. 按领域配额；
2. 按原则配额。

每次点击“按配额补充”只执行当前选择的方式。两套配额分别保存，切换方式不会清空另一套配置，也不会移除已经手动或自动加入的题目。

### 按原则补题

- 原则选项来自公共原则库中的有效原则。
- 候选题必须在公共题池中处于可用状态，并通过 `metadata.principleIds` 等规范字段关联所选原则。
- 手动选题优先保留，自动补题只补足缺额。
- 同一题在同一张试卷中只能出现一次。
- 一道题关联多个原则时，在一次补题计算中只分配给一个尚有缺额的原则，不重复抵扣多份配额。
- 候选选择沿用现有补题的随机化体验，但结果写入确定题目 ID；保存后再次打开不重新抽取。
- 题量不足不回滚已补题目；结果按原则列出目标、已满足和缺额数量。

### 数据结构兼容

新试卷保存：

- 当前补题方式；
- 领域配额；
- 原则配额；
- 最终确定的题目引用。

旧试卷只有领域配额时默认按领域模式打开。发布版本仍以确定题目 ID 和顺序为准，后续原则改名或题目移动不改变历史发布内容。

## 单题深学下线

### 产品行为

- 试卷发布模式只保留刷题、深度回忆和归纳。
- 教师工作台、课程与任务、帮助中心、题目画布和学习入口删除单题深学按钮与文案。
- 不再允许创建新的单题深学学习任务。
- 旧发布配置和学习记录保留在历史数据中，但不在当前界面展示，也不能启动新会话。
- 访问旧单题深学链接时，原链接提供的 `paperId`、`releaseId`、`questionId` 和 `bankId` 必须原样带入刷题路由；目标试卷或发布版本不存在、已撤回或未开放刷题时跳到刷题首页并显示说明。

### 兼容策略

底层历史枚举在迁移读取层暂时保留，避免旧快照解析失败；写入、发布、入口和当前业务 API 均不再产生 `single_deep_study`。相关帮助、测试和发布模式契约同步更新，不能仅隐藏页面按钮。

## 管理后台总览跳转

| 统计卡 | 行为 |
| --- | --- |
| 启用科目 | 整卡跳转到“科目与知识树” |
| 当前知识树 | 整卡跳转到“科目与知识树”的“当前知识树”页签 |
| 题库题目 | 整卡跳转到教师工作台“题目管理” |
| 试卷与任务 | 卡片内提供“试卷管理”和“课程与任务”两个明确入口 |

卡片必须使用真实 `<a>` 链接，提供悬停和焦点状态。统计数字、标题和可点击区域不应产生嵌套交互冲突。

## 登录后四选一入口

### 触发规则

- 所有角色每次成功登录后，首次进入知识图谱时显示一次。
- 同一次登录期间刷新、返回图谱或打开其他标签页不重复显示。
- 退出后重新登录生成新的登录会话标识，并再次具备显示资格。
- 弹窗不允许点击遮罩误关闭，也不提供含义不明的关闭按钮；“知识图谱”就是留在当前页的明确选择。

### 入口映射

| 弹窗选项 | 目标 |
| --- | --- |
| 知识图谱 | 关闭弹窗并留在当前知识图谱 |
| 知识回忆 | 深度回忆 |
| 知识归纳 | 归纳 |
| 知识巩固 | 刷题 |

### 会话去重

登录成功时生成不含敏感信息的唯一登录会话标识。知识图谱将已消费标识写入同源共享状态，并通过跨标签页通知同步；只有当前登录标识尚未消费时才显示。微信登录、账号密码登录和注册并登录使用同一规则。

弹窗使用焦点约束、键盘导航和明确的可访问名称。目标页面不可用时留在图谱并显示错误提示，不能进入空白页。

## 录入程序与主程序同步

### 保存语义

| 操作 | 正式数据变化 | 主程序通知 |
| --- | --- | --- |
| 保存题目、原则、归纳卡或训练配置 | 立即提交公共数据池 | 成功后通知 |
| 同步到题库 | 批量事务提交当前同步范围 | 整批成功后通知 |
| 保存工作区到本机 | 仅更新本地草稿 | 不通知 |

服务器返回成功前，录入程序不能显示“已同步”。失败时保留本地编辑内容，显示可重试的“未同步”状态；版本冲突时提示重新载入最新版本，不静默覆盖。

### 更新通知

每次公共教学内容写入成功后递增公共内容修订号，并返回受影响的实体类型、实体 ID 和最新修订号。

- 同一浏览器的录入程序通过同源 `BroadcastChannel` 立即通知主程序；不支持该 API 的浏览器由窗口聚焦和修订检查补偿。
- 主程序收到通知后只重新读取受影响的题目列表、详情、原则列表、筛选项和统计数字，不整页刷新。
- 不同浏览器或设备通过轻量修订检查及窗口重新获得焦点时补偿同步，确保不会永久停留在旧缓存。
- 删除事件同样进入通知链路。
- 当前页面存在未保存编辑时，不自动覆盖表单，只提示服务器存在新版本；只读列表和统计仍可更新。

通知只是加速刷新，服务器仍是权威数据源；丢失浏览器通知不会造成正式数据丢失。

## 异常处理

| 场景 | 处理 |
| --- | --- |
| 无权限写入 | 服务端返回 403，客户端保持当前输入并提示权限变化 |
| 记录已被删除 | 返回 404/业务错误，列表移除失效记录，编辑内容可导出 |
| 修订冲突 | 返回 409，提供重新载入最新版本；不自动覆盖 |
| 题目锁被占用 | 显示占用者和锁状态，禁止编辑或提交 |
| 批量同步部分校验失败 | 整批回滚，返回逐题问题，不产生半同步结果 |
| 原则配额题量不足 | 保留已补结果并列出各原则缺额 |
| 自动同步通知丢失 | 焦点刷新和修订检查补偿 |
| 四选一目标不可用 | 留在知识图谱并显示提示 |
| 清理扫描遇到来源不明题目 | 停止自动删除并进入复核清单 |

## 实施拆分

### 阶段一：公共数据基础

- 统一管理员/教师服务端授权和公共查询。
- 补齐公共实体的修订、操作者和删除语义。
- 收口教师工作台统计的数据来源。
- 增加公共内容修订与变更摘要协议。

### 阶段二：清理与迁移

- 实现只读清理扫描和报告。
- 备份、复核并执行正式清理。
- 修复当前草稿引用并验证历史快照。
- 将保留内容切换为公共工作区访问。

### 阶段三：教师业务功能

- 增加领域/原则二选一补题。
- 完整下线单题深学。
- 接通录入程序保存、批量同步和主程序局部刷新。

### 阶段四：导航体验

- 增加总览卡片跳转。
- 增加登录后首次四选一弹窗及多标签页去重。
- 遍历相关页面验证登录、退出、旧链接和入口跳转。

阶段按顺序实施和验收；后续阶段不能绕过公共数据基础直接继续增加浏览器本地共享键。

## 测试与验收

### 后端

- 管理员和两个不同教师账号对公共题库、题目、原则、试卷、课程和任务执行完整增删改查矩阵。
- 学员/游客访问草稿和管理写接口返回拒绝。
- 题目锁、修订冲突、批量同步回滚和删除引用保护测试。
- 数据清理 dry-run、正式执行、重复执行幂等性和失败回滚测试。
- 保留导入题目的数量、内容哈希和关联完整性测试。

### 前端与契约

- 管理后台总览四张统计卡的链接和键盘操作测试。
- 领域/原则切换、配额保存、手动题保留、去重、多原则单计数和缺额提示测试。
- 当前源码和生成站点中不再出现可启动单题深学的入口或发布选项。
- 旧单题深学 URL 携带上下文跳刷题及无上下文兜底测试。
- 四选一弹窗的每次登录一次、刷新不重复、多标签页不重复及四条路由测试。
- 录入程序保存/同步成功、失败、冲突和主程序局部刷新测试。

### 跨账号浏览器验收

至少使用一个管理员和两个教师账号：

1. 教师 A 创建题目、原则、试卷草稿和课程任务。
2. 教师 B 无需授权即可查看、编辑和删除。
3. 管理员看到相同数据和统计。
4. 教师 A 在录入程序保存，教师 B 已打开的主程序自动更新。
5. 学员只能看到符合发布与订阅规则的内容。

认证、权限和导航属于跨页面逻辑，必须遍历 `index.html`、`practice-mode.html`、`question-workspace.html`、`knowledge-recall.html`、教师工作台、管理总览及其他有账号菜单的相关页面，真实执行登录和退出，不能只检查跳转地址。

## 发布与回滚

1. 先执行数据库备份和清理 dry-run，保存报告和回滚点。
2. 源码只修改 `new-legacy/`、后端及必要同步适配器，不直接编辑 active release。
3. 运行后端测试、前端契约测试、浏览器跨账号测试和发布脚本测试。
4. 正式发布使用 `node frontend/scripts/manage-new-legacy.js update new-legacy --skip-browser`。
5. 发布前比较待发布 site 与当前 active release 的文件总数，并抽查 `admin-console.html`、`admin-subjects.html`、`teacher-workbench.html`、`paper-management.html`、`practice-mode.html` 等关键页面；文件数异常时停止发布。
6. 发布后在 active release 上复验公共数据、登录弹窗、总览跳转、单题深学旧链接和录入同步。
7. 应用回滚与数据回滚分离：应用可切回上一 active release；数据异常使用维护前备份和清理报告恢复，不能通过覆盖发布目录代替数据库回滚。

## 完成标准

- 所有管理员和教师看到并操作同一套公共教学内容，创建账号不再构成访问隔离。
- 正式导入题目及必要关联完整保留，测试和非导入题目清理完成且无当前引用断裂。
- 试卷领域和原则补题均可独立使用，手动题不丢失、题目不重复、缺额清晰。
- 当前产品不再提供可运行的单题深学入口、发布模式或新任务类型，旧链接正确跳转刷题。
- 总览统计卡按确认映射跳转。
- 每次登录首次进入知识图谱只显示一次四选一弹窗。
- 录入程序业务保存或同步成功后，主程序无需手动刷新即可看到变化。
- 并发冲突、保存失败和清理异常均有明确恢复路径，不发生静默覆盖或半批次提交。
- 后端、前端契约、跨账号浏览器和 active release 验证全部通过。
