# 微信做题小程序设计

**日期：** 2026-09-04  
**状态：** 待用户审阅  
**目标分支：** `codex/wechat-practice-miniprogram`

## 1. 目标

为现有幻谱系统新增一个学生端微信做题小程序。小程序在交互和视觉上按手机使用场景重新设计，不缩放、复制或使用 WebView 承载现有 PC 页面。

小程序与网页端共享同一套 FastAPI、PostgreSQL 和业务服务，确保用户、已发布试卷、题目、作答进度、错题、成绩、经验值与订阅权限始终是同一份数据。

## 2. 首版范围

### 2.1 包含

- 微信小程序登录、法律文件同意和现有账号绑定。
- 已发布试卷列表、免费/会员访问状态和试卷详情。
- 题量、顺序/随机、练习模式设置。
- 普通练习、挑战模式、学霸模式和复仇模式。
- 单选题、多选题、中文/中英对照内容和题目图片。
- 作答、标记、答题卡、上一题/下一题、自动保存、暂停和恢复。
- 交卷、成绩报告、题目解析、薄弱知识点和错题巩固。
- 学习记录、经验值摘要和复仇题池状态。
- 弱网提示、请求重试、作答冲突恢复和本地草稿。

### 2.2 不包含

- 教师工作台、题库编辑、试卷组卷、系统管理。
- 知识图谱画布、深度回忆画布、多题工作区。
- 在小程序内购买会员。首版只读取并执行现有订阅权限，对锁定试卷展示说明，不绕过权限。
- 离线下载整套试卷。弱网仅保障已打开会话的本地草稿不丢失。
- 其他小程序平台、H5 或原生 App 的同步交付。

## 3. 产品结构

### 3.1 底部导航

底部保留三个入口，避免将低频页面暴露为主导航：

1. **练习**：当前科目、继续作答、试卷库、四种练习模式。
2. **记录**：练习历史、成绩、错题和经验值摘要。
3. **我的**：账号、订阅状态、微信绑定、隐私政策、使用条款和退出。

### 3.2 页面清单

| 页面 | 主要职责 |
|---|---|
| 启动/登录 | 检查本地会话，执行 `wx.login`，完成账号绑定或创建。 |
| 练习首页 | 展示科目、本周摘要、可恢复会话和四种模式。 |
| 试卷库 | 分页读取发布试卷，筛选免费/会员，展示作答进度。 |
| 练习设置 | 选择题量、题目顺序和模式，处理已有可恢复会话。 |
| 答题 | 展示题干、选项、模式状态，提交作答并保存会话。 |
| 答题卡 | 查看已答/未答/标记状态，跳转题目，发起交卷。 |
| 解析 | 普通练习的即时解析，以及竞技模式交卷后的解析。 |
| 成绩 | 正确率、用时、经验、结果档位、薄弱域和错题入口。 |
| 复仇错题 | 待处理、需补救、待验证、已掌握四种状态及对应流程。 |
| 学习记录 | 会话列表、历史成绩、继续作答或查看报告。 |
| 我的 | 账号与订阅信息、条款、隐私、退出。 |

## 4. 已确认的移动端视觉基线

### 4.1 方向

视觉延续第一套“沉静学习型”方案，但使用真实微信小程序尺寸和信息密度。

- 画布参考宽度 390px，适配小屏和大屏手机。
- 米白背景、墨绿主色、黑绿正文，陶土红和暖金仅用于模式状态。
- 不使用渐变、发光、大面积英文口号、夸张动效或满屏卡片。
- 圆角统一在 11–15px，仅用于可点击区域和主要内容容器。
- 标题 17–24px，题干 17–18px，选项与解析 15.5–16px，辅助信息不低于 12px。
- 所有主要触控区不小于 48px；题目选项默认高度不小于 61px。
- 图标使用统一 1.6–1.8px 线性风格，不用文字伪装图标。
- 遮挡避让需考虑微信胶囊、状态栏和底部安全区。

### 4.2 答题页优先级

1. 题干与选项是第一优先级。
2. 作答进度、保存状态和答题卡是第二优先级。
3. 生命值、时间池和连对等游戏状态是第三优先级，只在对应模式中出现。
4. 除结果反馈外，不使用大面积动画打断阅读。

## 5. 技术架构

```text
miniprogram/ (WXML + WXSS + TypeScript)
  ↓ HTTPS + Authorization: Bearer <opaque token>
backend/app/api/v1/
  ↓ services
PostgreSQL
```

### 5.1 小程序端

- 新增独立 `miniprogram/` 目录，不写入 `new-legacy/` 或任何 active release。
- 使用微信原生 WXML、WXSS 和 TypeScript，不引入 React、Vue、Taro、uni-app 或 UI 组件库。
- 页面只负责显示和事件编排。请求、认证、会话草稿、错误归一化、题目格式化和模式状态放入明确的共享模块。
- 题干和解析使用受限 `rich-text` 渲染器，过滤不支持标签和事件属性。
- 图片使用配置的 HTTPS 业务域名，限制预览和下载来源。

### 5.2 后端

- 保留现有浏览器 SessionMiddleware 和 Cookie 登录行为，不破坏网页端。
- 在公共认证层扩展 Bearer 会话解析；所有现有 `CurrentUser` 路由无需复制小程序版 API。
- 新增微信小程序 code 换 session 服务，不复用网站扫码 OAuth 的 `qrconnect` 流程。
- 继续调用现有 `practice_session_service`、`learning_service`、发布试卷和订阅权限服务；小程序不复制判分、错题或经验规则。
- Bearer 做题请求使用共享响应脱敏器：普通练习只在本题提交后返回本题答案；挑战和学霸模式在整卷完成前不返回 `correctAnswer`、`correctOptionIds`、`option.correct` 或解析。该扩展不修改网页 Cookie 客户端的现有响应。

## 6. 微信小程序认证

### 6.1 配置

小程序 AppID 可能与网站微信开放平台 AppID 不同，因此新增独立环境变量：

- `WECHAT_MINI_APP_ID`
- `WECHAT_MINI_APP_SECRET`
- `WECHAT_MINI_ENABLE_DEMO`
- `WECHAT_MINI_SESSION_MAX_AGE_SECONDS`

密钥只存在后端环境，不返回小程序、日志或错误响应。

### 6.2 会话模型

新增 `wechat_mini_sessions` 表：

- `id`
- `username` 外键
- `token_digest`，只保存随机 token 的 SHA-256 摘要
- `login_session_id`
- `created_at`
- `last_seen_at`
- `expires_at`
- `revoked_at`
- `client_metadata` JSONB，只记录版本和设备类型等非敏感调试信息

小程序保存随机原始 token，请求通过 `Authorization: Bearer` 传递。后端校验摘要、到期时间、撤销状态和用户状态。退出登录会撤销服务端会话并清理本地 token。

新增 `wechat_mini_auth_tickets` 表保存未绑定微信身份的短期凭据：

- `ticket_digest`，只保存随机 ticket 摘要
- `openid`、`unionid`
- `created_at`、`expires_at`、`consumed_at`

绑定或创建账号在同一事务中锁定并消费 ticket，因此 ticket 是真正一次性，不依赖进程内缓存。

### 6.3 首次登录与账号联动

1. 小程序调用 `wx.login` 获取短期 code。
2. 后端通过 `jscode2session` 换取 `openid` 和可用的 `unionid`。
3. 若已有微信绑定，直接签发小程序会话。
4. 若尚未绑定，返回短期一次性 `bindingTicket`，不立即创建重复用户。
5. 用户选择：
   - 输入现有账号密码进行绑定，继承网页端全部数据；或
   - 明确选择“创建新学习账号”。
6. 用户同意当前隐私政策与使用条款后，才能完成登录或创建。

本地演示模式使用固定测试身份，但必须受 `ENV != prod` 和显式演示开关双重限制。

## 7. 做题数据流

### 7.1 启动

1. 验证本地 token，调用 `/api/v1/auth/me`。
2. 登录后并行请求：
   - `/api/v1/paper-releases/catalog`
   - `/api/v1/learning/practice/overview`
   - `/api/v1/learning/practice/experience-summary`
   - `/api/v1/learning/practice/revenge/summary`
   - `/api/v1/learning/practice/sessions/active`
3. 首页优先显示服务端最近更新的可恢复会话。

### 7.2 开始与恢复会话

- 新会话调用 `POST /api/v1/learning/practice/sessions/start`。
- 服务端返回 `RESUMABLE_SESSION_EXISTS` 时，小程序展示“继续上次”与“放弃后重新开始”，不暗中覆盖。
- 恢复调用 `POST /api/v1/learning/practice/sessions/enter`，再用详情接口取得服务端权威状态。

### 7.3 作答与保存

- 用户选择答案后，先在本地写入带 `sessionId`、`questionId`和 `revision` 的草稿，再提交服务端。
- 提交调用 `POST /api/v1/learning/practice/sessions/{session_id}/answers`。
- 服务端现有幂等与 revision 逻辑继续作为唯一权威判定；小程序不在本地实现判分。
- 请求成功后以返回的会话和 revision 覆盖本地快照，再删除对应待提交草稿。
- 请求结果不确定时，先重读会话；若服务端已包含相同答案，视为已成功，否则在当前 revision 上重试。

### 7.4 交卷

- 答题卡发起交卷前展示未答题数。
- 交卷调用 `POST /api/v1/learning/practice/sessions/{session_id}/complete`。
- 成绩和错题入库以该事务返回的 `session` 与 `report` 为准。
- 竞技模式在交卷前不展示解析；交卷后才从完成会话读取解析。

### 7.5 复仇模式

继续使用现有四状态流程：

```text
pending
  → 答对并交卷 → verification_due
  → 再次答错 → needs_remediation

needs_remediation
  → 查看解析/补救 → 使用不同题目验证

verification_due
  → 延迟后再次答对并交卷 → mastered
```

小程序仅展示和编排这个流程，状态转移仍由后端完成。

## 8. 状态管理与弱网

- 全局仅保存认证、当前用户和网络状态；页面业务状态按会话隔离。
- 本地草稿键必须包含 `username + sessionId`，禁止账号之间共享。
- 监听网络变化；断网时保留当前页面和未提交选择，禁止进入下一题造成未知判分。
- 后台或退出时调用 pause/state 保存；超时不阻塞小程序关闭，本地保留草稿。
- 从后台返回、切换设备或收到 409 时重读服务端会话，展示明确的“已在其他端更新”提示。

## 9. 错误处理

| 情况 | 小程序行为 |
|---|---|
| 401 | 清理无效 token，保留与原 username 隔离的草稿，重新登录后再决定恢复。 |
| 403 | 展示权限或会员说明，不本地绕过。 |
| 404 | 区分试卷下架、会话不存在和资源无权访问；返回相应安全页。 |
| 409 revision conflict | 重读服务端会话，对比当前草稿，已提交答案不允许覆盖。 |
| 409 resumable session | 显式让用户继续或放弃，不自动新建。 |
| 422 | 显示可理解的参数/作答错误，同时保留本地选择。 |
| 断网/超时 | 保留草稿，显示页内状态和重试入口，不用连续 toast 骚扰用户。 |
| 5xx | 保留当前内容和草稿，提供重试；不显示后端堆栈。 |

## 10. 安全与隐私

- `jscode2session` 只在后端调用；不将 AppSecret、session_key 或 token 明文写日志。
- 绑定 ticket 一次性、短有效期、服务端签名，不允许替换 openid。
- 所有做题、记录、错题和报告 API 继续使用 owner 过滤。
- 题目正确答案和解析的显示时机由服务端决定，小程序不从未授权字段推导答案。
- 本地存储不保存账号密码，退出时清理 token 和用户缓存。
- 隐私政策需补充小程序登录、本地草稿和必要学习数据用途。

## 11. 共享模块边界

### 小程序

- `services/api-client`：域名、Bearer token、超时、错误归一化。
- `services/auth-service`：登录、绑定、退出、token 恢复。
- `services/practice-service`：现有做题 API 的唯一调用入口。
- `services/draft-store`：按账号和会话隔离的草稿。
- `services/question-presenter`：单选/多选、中英文、图片和 rich-text 的展示模型。
- `services/practice-flow`：模式显示状态和导航判断，不包含服务端判分规则。
- `components`：题目、选项、进度、保存状态、空状态、错误状态等通用视图。

### 后端

- `wechat_mini_service`：code 换取、binding ticket 和小程序会话。
- `core/auth`：统一解析 Cookie 或 Bearer 身份。
- `api/v1/auth`：只编排输入、审计日志与响应。
- 现有做题服务保持为唯一业务实现。

## 12. 验证策略

### 12.1 后端自动化

- 正式和 demo 的小程序 code 换取、失败和超时。
- 新微信身份的绑定/创建分支、重复绑定、停用用户、条款未同意。
- ticket/token 摘要存储、ticket 单次消费、会话到期、撤销、非法 token 和用户隔离。
- Cookie 登录的现有行为不变。
- Bearer 用户可以访问现有 practice API，且 owner 隔离不变。
- Bearer 活动会话在各模式和提交阶段正确脱敏答案与解析，Cookie 客户端的旧响应保持兼容。
- 现有 `backend/tests/test_practice_sessions.py` 全量回归。

### 12.2 小程序自动化

- 用 Node 内置测试覆盖纯 TypeScript/JavaScript 模块：错误归一化、草稿键、单选/多选格式化、会话恢复、revision 冲突决策和模式状态。
- 静态合同测试检查页面注册、组件引用、字号/touch target token、禁用 WebView 和禁止密钥进包。
- 如本机存在可用的微信开发者工具 CLI，执行编译与预览校验；若不存在，明确列为未验证项，不伪造通过结果。

### 12.3 端到端验收场景

1. 新微信用户绑定现有学生账号，看到网页端的历史与错题。
2. 网页端开始会话后，小程序可恢复；小程序答题后，网页端能看到更新。
3. 普通练习完成单选和多选，解析显示时机正确。
4. 挑战模式的生命、交卷和成绩正确。
5. 学霸模式的时间池、答对加时和失败结束正确。
6. 复仇模式完成待处理、补救、延迟验证和已掌握流转。
7. 答题时断网、请求返回不确定、他端更新和重新登录后，已选答案不丢失且不重复记分。
8. 会员试卷对无权用户始终不可开始，而有效订阅可正常进入。

## 13. 实施分解

该功能涉及认证、移动端和已有复杂做题流程，不应当作单一大改动一次提交。使用三个纵向里程碑：

1. **基础设施与认证**  
   小程序工程、设计 token、API client、微信小程序登录、绑定、Bearer 会话与最小首页。
2. **核心做题闭环**  
   试卷库、设置、普通练习、单选/多选、答题卡、保存/恢复、交卷、成绩与解析。
3. **进阶模式与发布准备**  
   挑战、学霸、复仇、学习记录、弱网冲突、端到端验证、隐私说明和小程序提审清单。

每个里程碑均需独立通过定向测试和已有后端/前端回归，再进入下一个。

## 14. 完成标准

- 小程序不使用 WebView，页面在 320–430px 宽度下无横向溢出和关键遮挡。
- 所有首版页面遵循第 4 节视觉 token 和手机排版要求。
- 同一账号在网页端和小程序看到的会话、成绩、错题、经验和权限一致。
- 小程序端不复制服务端判分、生命、时间、经验、错题转移或订阅规则。
- 小程序活动会话在允许的显示时机前不包含可推导正确答案的字段。
- 网页 Cookie 登录、做题和 active release 行为不因 Bearer 扩展发生回归。
- 后端测试、小程序合同测试和能执行的微信开发者工具校验均通过。
- 功能分支先合入并部署 UAT，由用户本人完成微信真机与业务验收；未获得明确验收通过前不合入 `main`。
