# 微信做题小程序字体与间距重设计

**日期：** 2026-09-04

**状态：** 已确认方向，待实施

**视觉方向：** A・原生克制型

**目标分支：** `codex/wechat-practice-miniprogram`

## 1. 目标

本轮只解决小程序的字体与间距失控问题：消除宋体与无衬线字体混排、过多零散字号、同类内容不对齐、大块无效留白和网页式排版。

保留已实现的业务功能、数据流、页面导航与接口。不增加 UI 库，不重写页面结构，不用装饰性元素掩盖排版问题。

## 2. 设计原则

1. **字体统一：** 全站使用 `-apple-system, BlinkMacSystemFont, "PingFang SC", sans-serif`，移除 `STSong`、`Songti SC` 和页面级字体特例。
2. **层级有限：** 字号只能从公共字号表取值，同类信息在不同页面使用相同字号、字重和行高。
3. **网格对齐：** 所有间距使用 4px 基础网格的小程序等价值，禁止为单页增加随意间距。
4. **内容优先：** 题干、选项和主要操作获得最稳定的阅读空间；说明、标签和统计不与主内容争夺注意力。
5. **原生克制：** 不使用渐变、发光、装饰性英文、过度圆角、满屏卡片或大片空白。

## 3. 公共字体系统

| 用途 | 字号 | 字重 | 行高 | 使用场景 |
|---|---:|---:|---:|---|
| 页面大标题 | 44rpx（22px） | 650 | 1.30 | 登录页、首页主标题、结果主标题 |
| 题干 | 36rpx（18px） | 560 | 1.70 | 做题页问题正文 |
| 页面导航 | 34rpx（17px） | 620 | 1.35 | 顶部导航标题 |
| 模块标题 | 32rpx（16px） | 620 | 1.40 | 卡片标题、列表标题、成绩分区 |
| 选项 | 31rpx（15.5px） | 500 | 1.58 | 做题选项 |
| 正文 | 30rpx（15px） | 400/500 | 1.58 | 解析、列表正文、表单内容 |
| 辅助信息 | 26rpx（13px） | 400/550 | 1.45 | 时间、进度、状态、补充说明 |

不再保留 20–52rpx 之间的页面级自定义字号。特殊数值如成绩可使用独立展示字号，但不能影响页面正文系统。

## 4. 公共间距系统

| 令牌 | 小程序值 | 使用场景 |
|---|---:|---|
| `space-1` | 8rpx | 图标与文字、紧密元数据 |
| `space-2` | 16rpx | 同一组内的标签与说明 |
| `space-3` | 24rpx | 字段、小型列表项和选项内部 |
| `space-4` | 32rpx | 页面左右边距、卡片内边距 |
| `space-5` | 40rpx | 主模块之间 |
| `space-6` | 48rpx | 页面标题与首个内容区之间 |

超过 48rpx 的非结构性空白需要有明确原因，例如安全区或固定底部操作避让。

### 4.1 对齐约束

- 常规页面左右内容边缘统一为 32rpx；特殊题型最多可使用 36rpx，不允许同页混用多条主对齐线。
- 标题、说明、列表与底部主按钮默认共用同一左右边缘。
- 列表项、选项和输入框高度使用 96rpx 或 104rpx；需要换行时只增加内容高度，不压缩内边距。
- 同级组件的圆角、内边距和文字基线必须一致。

## 5. 页面收敛范围

| 页面 | 收敛重点 |
|---|---|
| 登录 | 缩短顶部空白，表单标签、输入框和主按钮对齐，移除宋体主标题。 |
| 首页 | 建立单一主对齐线，压缩无效分隔空白，统一模式入口和统计字号。 |
| 试卷库 | 统一筛选、试卷标题、进度和会员状态的基线与行高。 |
| 练习设置 | 将题量、顺序和模式控件归一为相同高度、内边距和选中态。 |
| 做题 | 实现 A 方案：题干 18px、选项 15.5px、稳定的 16px 左右边距和不小于 48px 的主要操作区。 |
| 成绩 | 保留成绩数字的展示性，其余标题、指标、解析与按钮回归公共系统。 |
| 复仇错题 | 状态标签、错题标题和操作按钮对齐，减少 20–26rpx 的过小文字。 |
| 学习记录 | 缩减空状态的大片空白，让标题、筛选、列表和底部导航形成连续节奏。 |
| 我的 | 统一用户信息、订阅状态、设置列表和退出操作的标题与行高。 |

## 6. 实现边界

- 先扩展 `miniprogram/styles/tokens.wxss` 的公共字号、行高和间距令牌，再让页面消费公共值。
- 公共排版和容器类放入 `miniprogram/app.wxss`；页面 WXSS 只保留该页特有结构。
- 现有 WXML 只在必要时补充公共 class，不改变数据绑定、事件和导航行为。
- `miniprogram/project.config.json` 中的本地 AppID 和微信开发者工具设置不纳入本次提交。

## 7. 验收标准

1. 代码搜索不再出现 `STSong` 或 `Songti SC`。
2. 业务页正文不再使用本规格外的零散字号；特殊数值必须有明确 class 和用途。
3. 页面主内容、列表和底部主按钮在截图中共用稳定的左右对齐线。
4. 同类列表项、选项、输入框和按钮高度及内边距一致，不因页面不同而改变。
5. 做题页的题干、选项和底部主按钮在 390px 参考机型上不发生遮挡、截断或不必要的横向滚动。
6. 历史页空状态不再出现首屏主体为空白、文字缩在局部的情况。
7. 微信开发者工具中逐页检查 9 个业务页，并覆盖默认、空、加载、选中、正确、错误和底部安全区状态。
8. 现有小程序自动化测试全部通过，且不改变任何 API 请求或业务结果。

## 8. 验证方法

- 静态检查：搜索字体声明、统计字号和间距值，确认已收敛到公共系统。
- 自动化检查：运行小程序现有测试，必要时增加字体和间距契约测试。
- 视觉检查：在微信开发者工具中以手机尺寸逐页检查，对齐 A 方案的字体层级和边距。
- 人工验收：开发自检通过后，再由用户在 UAT 环境中确认字体、对齐和阅读节奏。
