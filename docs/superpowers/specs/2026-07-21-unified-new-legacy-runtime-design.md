# 全 new-legacy 前端统一运行架构设计

**日期：** 2026-07-21  
**上游基线：** `new-legacy/VERSION` = `v8.6.0`  
**状态：** 已确认，进入实施

## 1. 目标与硬边界

当前项目同时运行 React 路由页面、`new-legacy` iframe 页面和两套消息桥接，导致导航链路、认证状态和后续升级边界复杂。最终生产架构必须满足：

1. 浏览器中只运行 `new-legacy` 原版页面，不再运行 React 页面、React Router、业务 iframe 或 `postMessage` 导航桥接。
2. 页面结构、样式、交互、动画、响应式行为和内部导航全部直接来自当前发布版本的 `new-legacy`。
3. FastAPI 与 PostgreSQL 继续作为唯一后端和正式数据源。
4. `new-legacy` 上游源码目录保持不可变；项目自有代码只负责数据适配、权限、页面服务和版本管理，不重写界面。
5. 页面与 `/api/v1` 使用同一来源和一个访问地址，消除多前端端口造成的误用。
6. 用户以后只需提供完整新版 `new-legacy` 目录，即可通过一条命令完成检查、构建、测试、上线或失败回退。

## 2. 最终运行架构

```text
new-legacy 原版页面
        ↓
无界面的服务端数据适配器
        ↓
FastAPI API 与页面服务
        ↓
PostgreSQL
```

FastAPI 同时承担 API、当前版本 HTML 和静态资源的同源服务。开发和本地交付统一使用 `http://127.0.0.1:5173`；不再单独启动 Vite 页面服务。现有 React 代码在切换前由 Git 标签保护，切换成功后从生产构建和依赖中移除，不在活动项目中保留第二套可运行页面。

`/login` 进入原版页面并打开原版登录弹窗；会员入口使用原版会员界面。学习模式到自由模式直接使用 `learning-path.html -> index.html?mode=free`，不再经过 iframe、消息协议或 React 路由。

## 4. 页面启动与数据适配

FastAPI 返回 HTML 前，根据 Session 和目标页面生成初始化数据，并在第一个上游业务脚本之前注入只读 bootstrap 与项目数据适配器。适配器预先建立同步内存视图，使依赖同步存储接口的原版脚本无需等待异步请求即可启动。

适配器按业务拆分：

- `bootstrap`：页面、版本、用户和页面数据初始化。
- `auth`：登录、退出、当前用户和角色。
- `files`：图谱文件、当前文件与文件正文。
- `learning`：课程、节点、跳级测试和学习偏好。
- `training`：训练快照、追加事件和多题工作区。
- `questions`：题库、试卷与题目。
- `recall`：回忆进度。
- `subscription`：会员状态、订单与兑换码。
- `admin`：用户和系统设置。

上游页面的同步写操作先更新内存视图，再由适配器排队提交相应 FastAPI 域接口。正式登录用户不能静默退回浏览器业务存储；网络失败必须显示未保存状态并重试。访客体验可使用临时浏览器数据，登录后由用户决定是否导入。

## 5. 认证、权限与数据一致性

登录仍使用后端 bcrypt 密码校验和签名 Session Cookie。当前账号包括 `佩奇007`、`老师`、`学生`、`乔治008`，密码均为 `111111`，角色分别是 `admin`、`teacher`、`student`、`viewer`。

前端按原版权限规则显示功能，后端对每个数据接口再次执行角色和 owner 校验。直接输入管理页面地址不能绕过后端权限。

每个写请求携带数据版本和幂等请求 ID：

- 文件保存使用乐观版本冲突检测。
- 学习进度采用单调合并，旧页面不能覆盖新完成状态。
- 训练过程使用追加事件与版本化快照。
- 用户和系统设置使用数据库事务。
- Session 过期时保留待提交内存，重新登录后继续。
- 冲突不能静默覆盖，必须刷新、合并或提示用户处理。

PostgreSQL 是唯一正式数据源；清除浏览器缓存不得导致已登录账号数据丢失。

## 6. 版本目录与发布元数据

每个成功导入的上游版本独立保存：

```text
new-legacy-releases/
├── v8.6.0/
├── v8.7.0/
└── v9.0.0/

current -> v8.7.0
```

原始导入快照与可运行派生版本分离。每个版本记录上游版本、完整 SHA-256、适配器版本、最低数据库版本、差异报告、测试报告、上线时间和前一个版本。上游源码快照不可修改；注入和必要的受控标识符转换只发生在可重复生成的派生目录。

## 7. 自动升级

用户提供完整新版目录后执行：

```bash
./manage-new-legacy update /path/to/new-legacy
```

命令依次执行：

1. 校验 `VERSION`、目录完整性和必需入口。
2. 计算并保存完整文件哈希。
3. 与当前版本比较页面、脚本、样式、路由、存储点和数据 Schema。
4. 创建独立候选版本，不覆盖当前版本。
5. 注入相同的后端数据适配器与运行配置。
6. 运行上游、适配器、后端、浏览器和视觉测试。
7. 生成中文兼容性报告。
8. 全部通过后以原子方式切换 `current` 指针。

候选版本可在 `/__preview/<version>/` 验证。预览默认连接测试数据；若使用生产数据只能只读。更新锁禁止并发升级。同一版本号对应不同文件内容时拒绝覆盖。

变化分为：

- 安全变化：普通页面、样式和既有接口内的功能变化，可自动上线。
- 需要适配：新增业务数据、存储点或接口，停止上线并生成处理清单。
- 破坏性变化：删除关键入口、全局契约或改变数据结构，拒绝升级。

## 8. 回滚与数据库兼容

```bash
./manage-new-legacy rollback
```

回滚仅原子切换到上一个成功版本，不覆盖文件或重新构建。默认保留最近三个成功版本，并始终保护当前、上一版本和数据迁移前版本。

普通前端升级不触发数据库迁移。需要迁移时只允许新增表、字段或索引等向后兼容操作；迁移前备份相关数据，新旧适配器在回滚窗口内必须同时可读。破坏性迁移不能随前端升级自动执行。迁移失败时回滚事务且不切换前端版本。

## 9. 异常处理

- 后端不可用：显示明确的连接失败状态，不伪装为已登录或已保存。
- 保存失败：保留待提交数据、显示状态并按幂等请求自动重试。
- 登录过期：打开原版登录弹窗，成功后继续待提交请求。
- 候选构建或测试失败：保持当前正式版本不变。
- 上线后健康检查失败：自动恢复前一版本指针。
- 数据库迁移失败：回滚事务且拒绝上线。
- 并发升级、磁盘不足或版本冲突：在复制和切换前失败关闭。

## 10. 测试与验收

每次升级必须覆盖：

1. 上游原版测试和源码完整性。
2. 后端认证、权限、文件、题库、学习、训练、回忆、会员和系统 API。
3. 访客、管理员、老师、学生和游客五种身份的全页面控制矩阵。
4. 学习模式与自由模式双向跳转、登录退出、文件保存、训练、节点、跳级测试和管理功能。
5. 同数据、同视口下原始候选页面与集成页面的视觉截图对比。
6. 升级失败保持旧版、重复导入一致、原子切换、回滚后正常和数据不丢失。

最终验收条件：

- 浏览器无 React 页面、React Router 和业务 iframe。
- 所有视觉与交互来自当前 `new-legacy`。
- 自由模式及全部内部链接直接跳转。
- 四个指定账号和未登录访客行为正确。
- 正式数据全部持久化到 PostgreSQL，并可跨浏览器恢复。
- 一条命令可导入、检查、测试和上线完整新版。
- 不兼容版本不能破坏当前服务。
- 一条命令可回滚。
- 全站只有一个访问地址和一套启动方式。
