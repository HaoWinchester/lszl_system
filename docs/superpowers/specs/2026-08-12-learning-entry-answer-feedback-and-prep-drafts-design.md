# 学习入口、单题作答反馈与公共录入草稿设计

**状态：已确认，直接实施（2026-08-12）**

## 目标

完成六项已确认的产品调整：

1. 首页“做题模式”改为可随时打开的“学习入口”，显示四个既有学习入口。
2. 单题深学的选项首次单击即作答，正确绿色闪烁、错误红色闪烁，随后锁定。
3. 首页图谱几何选框加深颜色，横向图元的边缘热区不能遮挡正文悬停与点击。
4. 题目管理的搜索框初始为空，不自动填入当前登录名。
5. Content Prep Studio 使用管理员与教师共用的数据库草稿列表。
6. 仅第七步同步到题库会写入正式题库；同步成功删除对应草稿。

## 约束

- 只修改 `new-legacy/` 源和后端；不得修改 `legacy/`。
- 正式数据以 PostgreSQL 为准；浏览器本地存储不承载公共草稿。
- 管理员和教师可查看、编辑、保存、同步和删除公共草稿；其他角色无权访问接口。
- 草稿保存采用乐观并发修订，冲突返回 409，客户端不静默覆盖。
- 活跃 release 必须通过 `manage-new-legacy.js update new-legacy` 正式生成和提升，候选 site 文件数不得少于当前活跃 release。

## 首页学习入口

首页右上链接文本改为“学习入口”，点击阻止普通跳转并调用既有 `KGLearningEntryChooser` 弹窗。弹窗保留四个既有目标：知识图谱、知识回忆、知识归纳、知识巩固。登录后每会话首次自动弹出规则保持不变；手动入口不会消费或修改自动弹窗标记。

## 单题深学作答

仅作用于 `question-training.html` 的答案卡：

- 选项按钮在未作答时可用；首次点击立即记录选项、标记已提交并渲染答案状态。
- 正确选项获得绿色 `is-correct-flash` 动画；错误的已选项获得红色 `is-wrong-flash` 动画。
- 一旦提交，全部选项禁用，后续点击不能改答或再次触发动画。
- `重置本题` 清除本题选择、提交状态和动画，重新开放选项。
- 减少动态效果环境保留正确/错误颜色，但不播放动画。

## 首页图谱选框

几何选框使用更深的蓝色。四角仍是可拖拽手柄；横向、纵向边缘拖拽热区只覆盖边框外沿，不覆盖被选图元的内容盒。选择框、手柄和拖动行为保持现有缩放补偿与多选逻辑。

## 题目管理搜索框

`qbQuestionSearch` 初始化时显式设为空字符串，`state.questionSearch` 也为空；输入使用 `autocomplete="off"`，避免浏览器恢复或账号自动填入。搜索内容仍只来自用户手动输入。

## 公共录入草稿

### 数据模型

新增 `content_prep_drafts`：

- `id`：稳定草稿 ID；
- `title`：列表显示名；
- `payload`：完整 Content Prep 工作区快照；
- `revision`：从 1 开始的乐观并发版本；
- `created_by`、`updated_by`、`created_at`、`updated_at`：公共协作审计字段。

草稿 payload 是尚未同步的工作区快照，不会写题库、题目、知识树、原则、归纳卡或标签正式表。

### API

在 `/api/v1/content-prep/drafts` 下提供：

- `GET /drafts`：返回公共草稿列表与元数据，不返回完整 payload；
- `POST /drafts`：创建一个公共草稿并返回完整记录；
- `GET /drafts/{draft_id}`：读取完整 payload；
- `PUT /drafts/{draft_id}`：必须带当前 revision，保存完整 payload；过期 revision 返回 `DRAFT_REVISION_CONFLICT` 和当前版本；
- `DELETE /drafts/{draft_id}`：删除未同步草稿；
- `POST /drafts/{draft_id}/sync`：在读取草稿、校验、正式批量同步和删除草稿之间保持同一数据库事务。成功响应批次结果；任何失败回滚，草稿不删除。

所有接口使用现有 Content Prep 编辑权限。`sync` 会复用既有批量上传服务与内容修订通知，确保主程序更新。

### Content Prep Studio 交互

进入录入程序后先显示“公共草稿”列表：新建草稿或打开现有草稿才能进入 1–6 步编辑。编辑不会自动保存。点击“保存草稿”才调用草稿创建/更新 API；冲突时保留当前屏幕内容并提供“重新载入最新草稿”。

第七个“导出中心”选项卡显示唯一的“同步到题库”操作。前六步不显示同步按钮。同步需要已保存的草稿、当前制作人和目标题库；同步成功后关闭工作区并回到公共草稿列表，已同步草稿不再存在。失败时显示逐项错误并留在当前草稿。

## 验证

- Node/浏览器测试：学习入口弹窗、单题一次作答红绿反馈和禁用、选框不拦截内容、搜索框空值。
- API pytest：管理员/教师共享读取，其他角色拒绝；创建、更新、修订冲突、同步成功删除、同步失败保留。
- Content Prep 客户端测试：草稿列表、显式保存、冲突恢复与仅第七步同步控制。
- 执行前端构建/发布验证、后端对应 pytest、Content Prep 构建与相关 Node 测试；发布后核查候选和 active release 文件数及关键页面。
