## 3. D01—D10 推荐决策

### D01：连线、手柄和固定端点

**推荐保留三次贝塞尔存储，改变交互手柄。** 比改为任意数量样条节点迁移更小，旧曲线可以原样显示。

- 首期提供两个内部可拖手柄，位于曲线参数 t=1/3 与 t=2/3；另显示两端点。拖动一个内部点时保留另一个曲线上点，由二元线性方程反求两个 `curveControls`。显示点在曲线上，底层仍用现有三次曲线。
- 不增加控制点任意增删工具；提供“恢复自动曲线”。多拐点折线保留现有 `waypoints`，不混用为曲线外手柄。
- 端点新增 `fromPort`、`toPort`，枚举 `auto|top|right|bottom|left`；旧数据缺省 auto。选中连线后分别选择两端方向，可恢复自动。
- 圆形／三角形用沿指定方向射线与真实轮廓的交点，避免固定到形状外的外接矩形上。
- 两端相同位移时所有手工点刚性平移一次；一端移动或重排时，以每点沿端点轴线的归一化位置加权分配两端位移。以 pointerdown 快照计算，禁止每帧累计误差。
- 多节点组拖动保留卡片绑定；现有“单独拖整条线使端点自由化”的显式行为保留，不混为组拖动。取消、撤销恢复端点绑定与控制点完整快照。
- 新字段必须进入 `00-config-state.js` 的 sanitizer；只在 renderer 添加字段会在保存／重载时丢失。

### D02：临时相关画布

**推荐默认一跳、独立内存副本、独立编辑历史。** 全量递归会把大型图谱几乎全部带入；直接操作正式 state 再尝试回滚会与自动保存竞争。

- 范围为所选卡片集合，加所有类型关系的一跳相邻卡片，再加入两端都落在集合内的关系；多选做并集，包含孤立选中卡片。
- 初始保留原图相对位置并 fit，不自动改变用户布局；需要整理时使用 R07 的临时布局命令。
- 将相关画布改为 `GraphSession` 的临时上下文，克隆节点／线／相关资源；保存函数固定为内存操作，正式文件自动保存适配器只接受正式上下文。
- 复用原有渲染与编辑控制器，通过上下文注入数据和 DOM 宿主；不把另一份 `10-graph-editor.js` 复制进去。
- 打开前完成正式画布当前编辑与待保存内容；若正式保存失败，保留原输入并暂停切换。临时会话不修改当前正式 fileId，不清空正式撤销栈。
- 关闭、切文件、登出或页面销毁时丢弃临时内容；不在 localStorage、数据库或文件恢复队列存副本。
- 推荐首期临时画布只提供内容编辑，不开放题目搜索、关联和作答入口，避免“临时丢弃”与正式练习记录冲突；正常图谱 R10 不受影响。此为推荐的产品范围选择。

### D03：XMind 格式、资源与导入

**推荐后端解析 ZIP，前端预览并确认后生成新文件。** 现有浏览器 ZIP 服务偏文本学习包，不适合直接套用图片和多工作表；Python 标准库 ZIP／JSON／XML 可避免新增重型白板依赖。

- 基于包内容识别 `content.json` 和旧式 `content.xml`＋`styles.xml` 两条解析路径，不按软件营销版本字符串猜测。XMind 官方历史加载器本身区分这两条路径；这不等于已验证当前所有版本。[官方加载器](https://github.com/xmindltd/xmind-viewer/blob/master/src/xmindLoader.ts)
- 第一批兼容样本包括 JSON／XML 两类各一份完整样本，以及图片、备注、多工作表、混合样式、损坏文件。版本名称写入测试样本清单，未测版本不标“完全支持”。
- 预览列出工作表，默认全选；每个工作表创建一个独立图谱，命名“文件名—工作表名”。不覆盖当前图谱。超出文件／节点配额时在确认前拦截，不能静默截断到 2500 节点。
- 标题→卡片标题；主题父子关系→标记为层级的关系；备注→`content.notes`／现有 notes 映射；图片→新增 `content.images` 资源引用；外观→现有 appearance＋导入来源信息。模型、sanitizer、renderer、复制、模板、导出都要保留新资源字段。
- 当前图谱没有已验证的卡片图片展示链路，因此图片支持单独成为任务。新增最小 graph asset 存储和访问接口，沿用已有题目资源的数据库二进制存储方式；提取通用图片字节校验供两域复用，不开放题目图片写权限给所有图谱用户。
- 推荐导入限制：压缩文件 50 MiB、解压总量 60 MiB、最多 1000 条 ZIP entry；单图片 5 MiB／4000 万像素，跟已有图片校验一致；每工作表节点仍遵守现有 2500 上限与账号配额。对路径逃逸、压缩炸弹、XML DTD／实体、损坏资源拒绝处理，不执行外链内容。
- 预览接口只解析返回计数、抽样与兼容报告，不写入；确认时重传同一文件及工作表选择，服务器重验并在一个事务内创建文件／资源。无需建立导入任务调度系统或持久预览会话。
- 原有字体无法使用、特殊形状／关系无法等价映射时列出具体对象和替代样式，允许用户明确接受近似后导入或取消；绝不默认静默接受。兼容缺口仍属于 R05 未完全满足的项，必须带入验收记录。

### D04：复制、模板、题目关联的独立性

**推荐版本化图谱片段＋服务器权威关联，不把授权放进用户可编辑 JSON。**

- 片段格式包含 `format:'kg-graph-fragment'`、`version:1`、nodes、内部 links、elements、tables、资源引用、来源 fileId 和 nodeIds。重新生成节点／线／元素 ID，并重映射内部引用。
- 正常文本输入仍走系统文本剪贴板。应用内片段保存在内存，切换图谱保留，登出／换账号清除；以显式复制／粘贴事件的 `application/x-kg-graph-fragment+json` 和带格式标识的纯文本支持跨标签页，解析失败不执行代码、不改变已有图谱。
- 图形片段本身不授予题目权利。题目关联复制只接受来源 fileId、nodeIds、来源 revision，服务端读取真实来源关联、检查来源读取和目标编辑权，然后生成映射；忽略客户端自带题号列表作为授权依据。
- 学生复制已获授权卡片属于继承既有授权，不能添加其他题目。卡片标题或正文修改不自动撤销原关联；传播依据是服务端实际存在的绑定记录及来源访问权，不依赖客户端声称“由教师创建”。
- 系统模板有不可变版本内容，发布／更新时产生新版本；加载到新文件，不改发布者来源，不自动更新已加载副本。教师可维护自己的模板，管理员维护全部；普通用户只加载。
- 下架阻止新加载，已加载的合法副本继续可用；免费／会员属性调整不追溯撤销已合法获得的副本。会员过期后不能新加载会员模板，已有副本可继续编辑。这是建议的授权时机，需产品确认。
- 模板包含关联题目时，由发布者权限及服务器已验证关联生成模板题目清单；加载时服务端复制授权。模板预览只提供缩略图／描述，不返回完整会员内容或答案。
- 当前文件 API 是 owner 私有模型。推荐第一期通过“教师发布模板→学生加载副本”分发可练习图谱；不增加教师私有文件的任意跨账号打开权限，也不顺便新建分享／协作系统。
- 删除来源卡片不删除已合法复制／加载副本。显式撤销某副本关联后，该副本的新作答请求失效；复制源 revision 已变化则返回冲突并要求重试。

### D05：布局与系统主题

- 四种布局：right、left、bilateral、down。优先使用已有／导入的层级边；普通关系图首次整理时要求指定一个根节点，按稳定顺序生成展示用生成树。
- 一个节点只在布局树中占一个位置；环和多父关系中的额外边保留为跨分支关系，不删除、不重复复制节点。非连通分量各自布局，再按区域排布。
- 左右展开按一级分支的子树规模做左右均衡；二次应用在内容未变时坐标稳定。推荐层间距 80、兄弟子树间距 32 个世界坐标单位，并根据真实节点尺寸留空。
- 布局只操作位置与必要路线重算；主题只操作外观。作用范围默认整个当前图谱，显式选区操作仅作用选区，不能让孤立选择改变整图。
- 首批推荐 6 种免费系统主题：简洁线框、蓝色圆角、彩色分支、黑白树形、纸感便签、胶囊节点。用现有形状／文字／连线字段组成，不增加主题商城。
- 保存 `mindmap` 元数据：rootIds、direction、themeId、schemaVersion；节点位置和 appearance 仍为最终事实。应用主题保留用户自定义字段，提供明确的“覆盖手工样式”选项；默认关闭。

### D06：搜索、关联题目与练习

- 教师／管理员的搜索词默认取卡片标题，可编辑；关键词作为可点击补充条件，学科可筛选。结果每页 20 条，按标题精确、标题包含、知识点／关键词命中、题干命中的顺序稳定排序，再按题目 ID 打破并列。
- 新增跨题库 search 服务，复用现有 catalog 序列化和教师范围；不由前端逐库拉全量题目。返回题型、题库、简要题干、已关联状态；不额外伪造“单题会员”标识，因为当前会员边界主要在试卷发布版本。
- 既有 `/question-catalog/learning/questions` 按 published/public 筛选，未读取订阅，并使用包含答案／解析的通用序列化。实施前要用真实发布属性验证是否存在“仅会员发布的题又被误标公开”的路径；有证据则纳入 R10 权限修复，不能仅验证付费试卷接口后宣布所有普通入口均安全。原本明确公开的题目不因也出现在会员试卷中就强制变为会员题。
- 首期支持追加、移除和按勾选顺序排列；不做拖拽排序器。提交携带 expectedFileRevision，防止卡片已被删除／改换时仍写入。
- `graph_question_bindings` 保存 fileId、nodeId、questionId、questionRevision、顺序、创建者和冻结题目快照；唯一约束为 fileId/nodeId/questionId。截图题库原题后续修改不悄悄改变已布置内容，教师可显式刷新关联版本。
- 快照沿用现有题目字段／判题服务、资源冻结逻辑，不重复实现各种题型判分。先冻结后再授予卡片范围读取，图片／材料二进制接口同样检查这项关联，不能出现正文可见但题图 403。
- 所有查看、作答、解析、材料请求都检查用户、文件、节点、绑定和快照版本；答案／解析不随未提交题目载荷提前下发。普通题库、试卷 release 权限函数保持独立。
- 推荐图谱内练习使用独立 `graph_question_attempts`：owner、bindingId、questionRevision、选择结果、服务端判分、提交时间、requestId；请求幂等，不自动混入正式考试成绩／复仇池。避免强行伪造 paper release 或放宽现有 session 的授权。
- 题目从题库删除但合法冻结快照仍在时继续可练习；管理员显式撤回绑定／快照才阻止新练习，历史记录只读保留。题目删除清理服务必须认识这些引用。
- 材料、匹配题、多选题使用现有呈现／判题公共入口。右侧抽屉建议桌面宽 440px（最大 40vw）、窄屏覆盖式；挂统一浮层宿主，不能塞进被缩放的 world。

### D07：失焦保存、四边拖动和字号

- 图谱标题／独立文本复用现有 inline editor；画笔文字保留既有 `tool:'text'` 存储，通过共享编辑会话替换保存／取消按钮。不强行一次迁移所有旧文字到新格式。
- 推荐范围扩展到三个页面共用的画笔文字，以避免同一工具三种行为；知识卡片标题沿用自身结构，业务详情表单的保存／取消按钮保留。
- 文本框四边及角点可拖。开始时记录 w0、h0、f0；候选尺寸 w1、h1 对应字号 `f1 = clamp(f0 * sqrt(w1*h1/(w0*h0)), 6, 288)`。横向拖动主要变宽，纵向主要变高，面积变化使字号一起变；按新宽度重新排版。
- 推荐框最小 40×24、最大 4000×4000 世界坐标单位。内容放不下时框高自动增长到实际排版高度，显示拖动后的真实尺寸，不裁切、不继续缩字号抵消用户拖动。所有计算基于开始快照，不在每帧复用上次已放大字号。
- 一次拖动一个历史步骤；Esc 取消本次拖动／编辑，保留快捷键但无显式取消按钮。点击外部提交；点击自身格式工具继续编辑；IME 组合输入期间不提前提交。
- 新建空文字不创建对象；已存在文字清空后保持空对象可撤销；卡片标题清空时保留“未命名知识点”。后端笔迹文本当前拒绝空字符串且限 12—72 字号，必须同步改契约，不能只改 UI。
- 画笔文本增补可选 `boxWidth`、`boxHeight`；`width` 继续兼容表示字号。旧数据按旧文字实际边界推导框。异步保存失败保留草稿并提示，不把关闭编辑器当作保存成功。

### D08：关键词匹配与自定义卡牌

- 自动匹配优先级：有效显式 recallNodeId → 明确唯一的 concept 关联 → 当前学科内唯一规范化标题／别名全等。
- 规范化只做首尾空白、Unicode NFKC、英文大小写，不删除中文语义词或做子串自动绑定。多候选、失效显式 ID、无结果一律按未匹配处理。
- 模糊检索仍可用于主动搜索建议，但不自动选中写入；通过新 `resolveExact` 公共入口服务深度回忆，保留其他依赖 `resolve` 的搜索行为，逐一迁移自动绑定调用点。
- 未匹配生成 `custom:true` 和 `personal:` dataId 的根卡，标题预填原关键词，内容为空并提供输入提示；相同来源关键词重复点击复用该自定义根卡。
- 复用 `customNodes`、`DeepRecallFlow.personalNodeId`、现有进度服务；根卡和子卡都能编辑，已手工编辑内容永不自动覆盖。
- 历史数据无可靠匹配来源时不批量改库。提供当前会话显式“转为自定义卡牌”修正入口、单步撤销；旧已保存卡牌不因加载自动重绑定。新增匹配结果记录来源，后续才有可核对修复依据。

### D09：表格行为和保存

- 推荐默认 3×3；网格选择 1—10 行列，数字输入最大 100 行×50 列；每表最多 5000 格，每画布最多 20000 格，超限操作完整拒绝，不能截断 Excel 数据。每格最多 3000 字符。
- 使用 HTML table 作为可编辑 DOM，复用 viewport 和共享 resize，禁止渲染成整表位图；移动／缩放用世界坐标，行列尺寸单独存储。
- 模型单独为 `tables[]`，包含 id、x/y、columnWidths、rowHeights、cells、merges、schemaVersion。三个页面同一 JSON 契约；不放进目前仅支持文本的 `elements` 或严格笔迹 `strokes`。
- 支持拖外框调整整表、拖列边界／行边界调整列宽行高；字号固定，表格拖动不适用 R12 的文本框字号规则。
- 合并仅允许连续矩形，已有合并范围只能整体包含；内容按行优先、跳过空格、用换行拼入左上格。提供“拆分”，保留当前左上内容、其他格为空；想还原合并前每格内容使用撤销。合并前有内容时预览结果，不能静默丢弃。
- Excel 优先解析剪贴板 HTML 表格的文本、rowspan、colspan；无 HTML 时按 TSV 解析，保留空单元格、行尾空列、引号内换行。舍弃公式计算和外部样式脚本；使用复制出的显示文本，不执行公式。
- 粘贴到选中起始格，必要时扩充行列；与目标合并区域冲突时明确拒绝并说明先拆分；超过上限不部分写入。粘贴在空画布创建一张表，编辑格内常规文本粘贴优先。
- 图谱 `graphData.tables`、多题 `payload.tables`、深度回忆新增 JSONB `tables` 列与请求字段，均接入读取、保存、重置、复制／模板／导出、撤销历史。

### D10：清晰度、缩放和文本范围

- 统一保留现有 UI 的 1%—400% 缩放；修正深度回忆后端最低值至 0.01，且所有坐标计算仍防零值。不能缩窄前端范围来绕过保存失败。
- 先在 Chrome／Safari 的 DPR 1／2、浏览器页面缩放 100% 下测 1%、10%、20%、50%、100%、200%、400%；另测浏览器缩放 125%。在极小比例检查无异常缓存／重影和回到 100% 恢复，不要求 1% 文字可读。
- 推荐先移除静止状态下强制合成文本大层的 CSS，平移缩放期间短暂使用性能提示、结束即还原；比较 2D transform 与当前 3D transform 的实测，不凭“矢量一定清晰”直接结案。
- 如果局部修复仍不能满足正常比例清晰度，再对受影响文字使用按视图比例重新排版的 DOM 展示方案，并验证连线／命中坐标；不默认引入全画布第二套渲染器。
- 字体加载完成再取测试截图；正常、全屏、拖动结束、连续缩放返回同倍率都检查。大图测试用现有性能 fixture，避免通过每帧全量重建换清晰度。
- R12 的共用画笔文字在三页统一；卡片正文的业务输入表单不改成无按钮保存。图谱缩放控制的滑轨与文字字号滑轨是不同功能，保留前者。

## 4. 两项补充设计

### 4.1 全屏浮层与快捷键共用边界

新增最小 `canvas/dom-interaction.js`，提供 `isEditingTarget(eventOrElement)` 和 `overlayHost(surface)`。输入判定读取 composedPath／activeElement，涵盖 input、textarea、select、所有有效 contenteditable、IME。浮层宿主在全屏时必须位于 `document.fullscreenElement` 内，正常时使用约定顶层 overlay root。

将 nodeModal、图谱颜色窗口、共享笔迹文字编辑器、临时相关画布和新增题目抽屉统一迁移；原来在 stage 内的 detailPanel 不盲目搬动。保留 DOM 原位置占位以便退出全屏恢复，避免丢监听或创建重复元素。焦点、坐标、滚动、Escape 优先关闭当前浮层，不同时触发画布删除／清选。

### 4.2 背景与主题解耦

多题 `workspace.background` 保存独立的底色／图案／资源引用；主题只更新卡片、线条和控件。首次读取旧 workspace 时，将当前有效背景固化为该文件背景，之后主题变更不再覆盖。保留深度回忆现有主题同步行为，单独取消多题背景对 `--kr-bg-*` 的依赖。

共享颜色面板要使用稳定按钮锚点：从事件目标找到 `[data-qw-selection-action="color"]`，不要把委托监听的整条 toolbar 当按钮锚点。此为代码可见的改进点，是否为无响应根因必须由复现确认；同时检查选区被全局 pointerdown 清除及面板即时关闭。

## 5. 数据与接口建议

### 5.1 JSON 增量契约

```js
// 推荐新增字段；其他现有字段保留。
link = { id, from, to, fromPort: 'auto', toPort: 'auto', curveControls, waypoints };
graphData = { ...existingGraphData, mindmap, tables: [] };
node.content.images = [{ assetId, alt, width, height }];
workspace = { ...existingWorkspace, background, tables: [] };
recallProgress = { ...existingRecallProgress, tables: [] };
textStroke = { ...existingTextStroke, boxWidth, boxHeight }; // width 仍为字号
```

`00-config-state.js` 构建新 state 会忽略未知顶层字段；`graph-persistence.js` 当前把 elements 当文本；多题 store 和深度 adapter 也挑字段。因此每个新增字段必须覆盖 normalize→render→snapshot→save→load→export，不得只依赖 JSONB “什么都能存”。表格独立字段避免被 text sanitizer 强制转型。

### 5.2 推荐新增持久对象

| 对象 | 主要职责 | 复用边界 |
| --- | --- | --- |
| GraphAsset | 图谱图片二进制、所属账号、类型／尺寸；关联图谱或模板版本资源清单 | 抽取题目资源字节校验；不复用其教师权限 |
| GraphQuestionBinding | 文件／卡片与题目冻结版本及授权来源 | 复用题目快照形状、材料冻结和判题，不伪造试卷 release |
| GraphQuestionAttempt | 卡片内练习记录、幂等提交、解析展示状态 | 复用答案归一化与判分；不自动计入正式考试 |
| GraphTemplate | 模板名称、发布者、当前版本、免费／会员、上下架状态 | 与用户私有 graph_files 分离 |
| GraphTemplateVersion | 不可变 graphData、资源清单、服务器生成的关联题目快照清单 | 加载时经 file_service 创建合法副本 |
| RecallProgress.tables | 深度回忆表格独立 JSONB 列 | 现有 optimistic revision、重置与保存链路 |

文件创建／复制服务当前会自行 commit。模板加载、XMind 导入、受控片段复制需要原子写入，因此仅为这些组合流程抽出“不自行 commit 的创建内部函数”，原外部服务仍负责 commit＋refresh；不能在路由里复制创建逻辑或通过半完成文件承载失败结果。

### 5.3 推荐 API 范围

所有路由前缀均为 `/api/v1`；这是新增接口建议，不是现有接口清单。

| 方法与路径 | 输入／输出概要 | 权限 |
| --- | --- | --- |
| POST `/files/import/xmind/preview` | file → sheets、counts、warnings | 有创建图谱权限；不写入 |
| POST `/files/import/xmind` | file、sheetIds、acceptedWarnings → files | 同上，按实际配额检查，事务创建 |
| POST `/files/{fileId}/fragments` | 片段＋可选受控 source 引用＋expectedRevision → idMap、revision | 目标编辑权，来源引用须独立验证 |
| GET `/graph-question-search` | query、subject、page、pageSize → items、total | 教师／管理员 |
| GET／POST `/files/{fileId}/nodes/{nodeId}/questions` | 读取关联／提交题目 IDs＋expectedFileRevision | 读取需文件访问权；写仅教师／管理员且有图谱编辑权 |
| DELETE `/files/{fileId}/nodes/{nodeId}/questions/{bindingId}` | expectedFileRevision → 新版本 | 同上，显式撤销 |
| POST `/files/{fileId}/nodes/{nodeId}/questions/{bindingId}/attempts` | selectedAnswer、questionRevision、requestId → 判分＋解析可见状态 | 卡片可访问且关联有效，不检查整题库会员权限 |
| GET 同一 binding 下 `/explanation`、`/assets/{assetId}` | 解析／关联资源 | 同一授权，解析检查作答状态 |
| GET／POST `/graph-templates` | 目录／从 sourceFileId 发布 | 列表按登录权限；发布仅教师／管理员 |
| POST `/graph-templates/{templateId}/versions` | sourceFileId → 新不可变版本 | 发布者或管理员 |
| PATCH `/graph-templates/{templateId}` | 名称、access、status | 发布者或管理员 |
| POST `/graph-templates/{templateId}/load` | versionId、requestId → 新 file | 服务端校验有效会员／角色；幂等 |

图谱资源读取额外按其被有权访问的文件或模板版本引用来授权，不使用“知道 assetId 即可读取”。解析、绑定、模板 API 必须放到各自 service，router 只编排参数和权限。

## 6. 主要风险及控制方式

1. **渲染质量尚未复现**：先建立倍率与 DPR 证据，再选方案；不要把改 CSS 属性视为验收通过。
2. **临时上下文与自动保存串写**：GraphSession 适配器硬隔离＋服务端写请求计数为零的测试；不能只在 UI 隐藏保存。
3. **图片与扩展字段丢失**：覆盖 sanitizer、片段、模板、导出、三个保存边界的往返测试。
4. **会员例外扩大**：客户端不得提供可信授权标志；同一绑定校验覆盖正文、答案、解析、材料，普通试卷 release 门禁保持原样。
5. **导入保真与版式差异**：用真实 XMind 样本建立映射清单；近似须显式确认，不能把未支持对象算完成。
6. **基础测试已有失败**：T00 先核对恢复草稿的语义和字段契约，再修 fixture 或实现；不能删除测试或吞掉新增字段。
7. **共享改动范围**：文本、浮层、表格、主题的测试矩阵按所有调用方覆盖；不只看首页。

## 7. 推荐实施顺序

先完成基线与交互修复，再补连线、复制、临时会话及文本；接着完成布局／图片／XMind；随后实现教师关联题、模板及学生合法副本；最后接入三页表格并做全量 UAT。清晰度实验应在第一阶段就做，验证需贯穿后续文字和表格交付。

设计选择全部已给出推荐，不再用空白“待定”阻塞计划。是否采用上述具体参数和范围由用户审阅；下一份开发计划按这些推荐方案编排，不自动启动实现。
