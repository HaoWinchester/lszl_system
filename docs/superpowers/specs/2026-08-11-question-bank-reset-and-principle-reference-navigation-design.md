# 题库重置与原则引用定位设计

日期：2026-08-11

## 目标

本次改动同时完成三件事：

1. 清空当前题目池中的全部题目，包括管理员、教师和用户通过录入程序上传的题目。
2. 删除全部题库，并清空原则、系统归纳卡及其共享投影。
3. 原则删除被题目引用阻止时，展示每一道引用题目的题名和所属题库；点击引用项直接进入对应题库并选中该题。

已发布试卷的冻结历史快照与既有审计记录保留，不参与当前原则引用判断，也不阻止清理。

## 当前状态与根因

生产数据库只读盘点结果为：17 个题库、14 道题、0 条原则、0 张系统归纳卡；原则和归纳卡共享投影已经为空。现存题目主要为测试或上传遗留数据。

原则删除服务当前会扫描题目的 `metadata.stemPrincipleIds`、`metadata.principleIds` 和 `metadata.optionPrincipleMap`，但冲突异常只保留每条原则的引用数量。API 的 409 `PRINCIPLE_IN_USE` 响应也只返回 `referenceCounts`，前端因此无法得知具体题目，更不能生成题库深链接。

## 方案

采用已确认的方案 A：原则删除冲突由后端在同一次 409 响应中返回完整、确定排序的引用题目明细。前端不从本地缓存推断引用关系。

### 后端引用契约

原则删除、归档和组合导入共用一个引用扫描结果。409 响应保留现有字段，并新增 `referenceQuestions`：

```json
{
  "detail": {
    "code": "PRINCIPLE_IN_USE",
    "referencedIds": ["principle-a"],
    "referenceCounts": {"principle-a": 2},
    "referenceQuestions": {
      "principle-a": [
        {
          "questionId": "q-1",
          "questionTitle": "沟通场景题",
          "teacherNumber": "PMP-001",
          "bankId": "b-1",
          "bankName": "PMP 题库"
        }
      ]
    }
  }
}
```

题目按题库名、题名、题目 ID 稳定排序。同一道题无论在一个原则的几个元数据位置重复出现，都只返回一次。扫描以数据库为唯一事实来源，包含所有管理员和教师共享题库中的当前题目，不包含已经不存在的题目和冻结历史快照。

### 前端冲突体验

复用题库页已有的“所属题目”对话框，不增加另一套弹窗：

- 删除失败时不再只显示短暂 toast。
- 对话框标题显示“原则仍被题目引用”，列表显示题目编号或 ID、题名和题库名。
- 单击任一引用项，直接跳转至：
  `question-bank.html?mode=simple&step=questions&bankId=<bankId>&questionId=<questionId>`。
- 目标页沿用现有深链接逻辑，选择对应题库、对应题目并打开基础信息编辑区。
- 若响应缺少明细或题目已被其他人删除，保留现有错误提示作为恢复路径；刷新后可以重新尝试删除。

原有双击原则查看所属题目的功能保留。删除冲突弹窗使用服务器返回的明细，避免本地目录过期造成前后端不一致。

## 数据清理

清理前生成带时间戳的 PostgreSQL 自定义格式备份，并记录以下清理前数量：题库、题目、题目编辑锁、题库协作者、上传批次、训练进度、回忆进度、学习事件、试卷当前关联、原则、归纳卡和两个共享投影。

清理流程在教学内容全局锁下执行：

1. 修复并移除当前试卷、课程、任务等可变数据中的题目引用。
2. 删除题目依赖的编辑锁、训练/回忆记录和学习事件。
3. 删除题库上传批次、题库协作者、全部题目和全部题库。
4. 删除归纳卡和原则，重写两个共享投影为空集合。
5. 内容修订只在清理事务成功时递增；任何一步失败则回滚，不留下部分清理状态。

以下内容保留：用户账号、题目审计日志、清理备份、已发布试卷冻结快照及其他不可变发布历史。

清理后必须验证题库、题目、原则、归纳卡和所有当前引用计数均为 0；两个共享投影必须是合法的空 `items` 结构。

## 权限与安全

- 原则写入和删除仍仅允许管理员与教师。
- 409 明细只在已有原则管理权限的接口中返回，不向学生或查看者新增题库可见性。
- 清理是一次受控维护操作，不在普通页面增加“清空全部”按钮。
- 备份路径、SHA-256、清理前后计数和执行者写入维护报告。

## 测试与验收

按测试驱动顺序完成：

1. 后端真实 API 测试先证明当前 409 缺少引用题目明细。
2. 实现后验证题目三个原则字段都能被识别、重复引用去重、结果稳定排序、无引用时仍可删除。
3. 验证管理员和教师可获得明细，学生和查看者仍被拒绝。
4. 前端真实 DOM/VM 测试验证删除冲突打开明细弹窗，单击题目产生精确深链接；缺少明细时仍有可恢复提示。
5. 使用一次性测试数据库验证清理事务：成功后当前数据归零，注入异常时全部回滚，发布历史与审计保留。
6. 运行相关后端、前端集成测试和真实浏览器流程；正式发布后再次核对生产 API、页面跳转和数据库计数。

## 非目标

- 不删除已发布历史快照。
- 不删除用户账号或登录审计。
- 不增加题库或原则的批量清空 UI。
- 不开发“科目与知识树看板点击跳转”。
