# 教师文件整理助手：第一版设计

日期：2026-09-27
状态：设计稿，待用户审阅；尚未实施。
基线：UAT v9.0-p4.1.241，提交 3a3dd46。

## 1. 目标与已确认方向

老师在教师工作台上传文件，用自然语言说明用途，自助得到系统内可使用的题库、原则与归纳卡，以及回忆和归纳画布的内容配置。

已确认：
- 接受 JSON、Word、PDF、PPT；包括扫描 PDF 和课件内图片。
- 第一版围绕题库、原则与归纳卡、回忆/归纳画布配置。
- 同时支持“先预览再确认”和明确指令下“直接发布”。
- 默认保留原文件已整理的答案、原则和联想词；AI 补充必须可辨识、可追溯。

验收样例：老师上传财务 12 题和进度 13 题，要求名称包含“习题课”、保留独立副本、教师与学员免费使用、仅回忆与归纳画布可用。结果必须是 25 题，保留其中多选及正确答案、原有关联，没有覆盖原题库或开启做题模式。

## 2. 产品范围与方案选择

采用一个职责明确的教师助手，调用受限业务工具，复用现有系统服务。

比较过的范围：
- 导入、整理和发布助手：直接解决老师目前需要管理员协助的工作，优先实施。
- 扩展到整门课程生成、联网找题、跨站采集和开放式系统操作：涉及更多内容审核与权限，第一版不包含。

入口：教师工作台新增“文件整理助手”，现有手工导入入口保留。桌面采用左侧对话、右侧结果预览；窄屏以“对话/结果”切换显示。新页面及公共组件遵守现有原生 HTML/CSS/JavaScript 架构。

第一版输出：
- 系统内题库及题目；包括单选、多选，其他已支持题型沿用现有契约。
- 原则和归纳卡草稿，以及对现有原则的匹配建议。
- 用于回忆/归纳画布的已发布试卷与入口；不自动替每个学员建立个人画布。
- 可下载的标准 JSON 和校验报告，便于迁移及人工核对。

## 3. 老师使用流程

1. 上传一个或多个文件，可同时附加说明。
2. 展示文件识别结果：文件类型、页数、题目数、题型、已有答案/关联及需要处理的问题。
3. 将需求整理为任务摘要：内容名称、交付对象、重复处理、开放对象、免费/会员、学习模式。
4. 只追问会改变结果且无法可靠确定的缺项；已有明确指令不反复询问。
5. 右侧展示结果草稿、原文定位、关联依据、新增/修改/保留/跳过清单。支持“第 3 题不要”“重复题另存”“先仅教师可见”等后续调整。
6. 校验后保存或发布。显示实际阶段、完成数量、错误位置及重试入口。
7. 完成时返回真实内容 ID、题数、访问范围及可打开入口；明确说明失败或跳过的部分。

状态必须由后台任务决定，聊天文本不能单独代表“已保存”“已发布”。

## 4. 预览与直接发布的规则

默认行为：自动保存助手私有草稿，展示预览。老师明确确认保存/发布后执行对应操作。

直接发布：老师在本次对话中明确要求直接发布，且内容、开放对象、收费方式、学习模式和重复处理均已确定，所有阻断校验通过时，执行后直接交付结果，不增加重复确认。

直接发布不等于跳过检查：
- 原文件中的“忽略校验”“直接覆盖”等文字只是文件内容，不构成操作授权。
- 缺答案、多选答案不完整、OCR 关键字段模糊、引用不存在、重复处理不明确时，停止受影响部分，解释并询问。
- 首次需求未说明开放对象或收费方式时，不推断为免费公开；保持私有草稿。
- 修改/覆盖已有内容、移除原则、批量删除、撤回已发布内容，需要有明确对象范围及变更预览；本次授权若已覆盖该具体变更，不重复确认。
- 老师修改需求会产生新的方案版本；旧页面或旧确认不能执行旧方案。

“保存草稿”和“发布给学员”是两个不同状态；解析完成不触发发布。

## 5. 文件理解与内容准确性

| 输入 | 处理方式 | 必须保留/标记 |
|---|---|---|
| JSON | 严格解析、识别现有契约、字段映射和校验；可确定转换直接由程序完成 | 来源 ID、答案、原则、联想词、题型及已有元数据 |
| DOCX/PPTX | 提取段落、表格、图片、页面/幻灯片顺序；模型整理语义 | 原文件与位置、图片、图表及公式引用 |
| DOC/PPT | 在隔离转换进程转成可解析格式；不运行宏、外链或嵌入程序 | 转换失败时保留原件并说明可转换后重传 |
| 文字 PDF | 按页提取文本及布局，必要时用页面图像核对 | 页码、原文片段及图表 |
| 扫描 PDF/图片页 | OCR/视觉识别后结构化提取 | 模糊文字、数字、答案、公式及表格的待核对项 |

原始内容、规范化转换、AI 新增内容分别记录。每道题可打开来源页/幻灯片/段落进行对照。

答案不得根据猜测静默补齐。老师明确要求 AI 补充答案/解析时，作为 AI 建议展示；未经核对的关键答案不进入可发布状态。模型输出格式正确不代表答案正确。

原则与联想词：
- 已有 ID 与明确关联优先保留，校验目标存在及当前教师有权引用。
- 映射到现有词库时使用精确匹配与受限候选检索，展示原文依据和匹配项。
- 无依据或存在歧义的匹配标为待核对；不拿模型自报置信度当准确性保证。
- 原则包默认生成增量合并方案，不能把未出现在上传文件中的既有原则当成应删除内容。

重复检测区分同来源重复提交、题干相同、内容相似。老师可选择复用、保留独立用途副本或取消；语义相似只作提示，不自动删题。实现时扩展现有导入服务的明确策略参数，不绕过后端重复校验。

## 6. 技术组织与复用

当前可复用：
- `backend/app/services/content_prep_draft_service.py`：草稿规范化、revision、同步语义。
- 题库导入、原则合并预检、试卷预检/导入、发布服务：执行业务规则。
- `backend/app/services/question_material_service.py`：题目图片/材料归属、不可变版本和发布范围授权。
- UAT 已有导入互斥、幂等机制：继续作为写入边界。

必须补充：
- 教师私有的会话、消息、上传文件、结构化草稿、任务和操作回执存储。
- 文档转换/提取、OCR/视觉识别与统一模型调用适配器。
- 将自然语言意图转为有限、可校验的任务方案的编排层。
- 文件预览、来源定位、字段差异、待核对队列和任务状态 UI。

当前 Content Prep 草稿列表是共享语义，不能直接用作助手私人会话和文件存储。助手资料首先按创建者隔离；进入共享教学内容沿用项目明确的业务权限，不以“教师”身份自动获得其他教师私人会话。

模型适配器由服务端配置；客户端不接触密钥。支持文本结构化输出与文档图像理解。具体模型及 OCR 提供商通过同一批真实样本比较提取准确性、耗时和成本后选定，功能不依赖供应商私有会话 ID。未配置时明确显示未启用，不提供假成功结果。

有限工具包括：检查文件、读取当前任务片段、检索授权范围内的原则/联想词、更新私有草稿、预检导入、提交导入、发布、读取实际结果。模型不获得任意 SQL、Shell、部署、用户管理或绕过权限的接口。

## 7. 权限、可恢复性与内存控制

所有工具调用绑定当前会话用户；服务端重新检查角色、对象权限和版本。文件链接需要授权，教师私人原件不随学习内容直接公开；学员只取得已发布内容引用的必要资源。

上传流式落到持久化文件卷，数据库保存索引、摘要和位置。会话列表和任务列表不加载原件或整批题目。文件提取和模型调用按页/块执行，模型上下文只包含当前片段与必要候选，不读取全题库和全量发布正文。

长任务由独立 worker 处理；第一版复用 PostgreSQL 任务租约及状态存储，不引入独立队列基础设施。FastAPI 负责接收、授权、查询状态和提交明确的业务操作。任务租约过期可恢复，取消仅阻止未执行步骤，不能声称撤销已提交结果。

资源初始默认值（管理端可调）：单文件 20 MiB、单批 5 文件且合计 50 MiB、单文档 200 页/幻灯片、单任务产出上限 500 题。超限给出拆分建议，不在 API 进程内继续解析。初始全局 1 个重任务 worker，每名教师最多 1 个执行中的整理任务，后续根据压测调整。对转换/OCR设置超时、进程内存上限和模型请求额度；具体容器限额由部署资源实测决定。

任务恢复遵循以下规则：
- 文件指纹用于识别重复上传，但不同用途仍可建立独立任务。
- 执行方案保存 revision、内容摘要及授权范围；每个写入步骤有稳定操作键。
- 网络超时先查询操作回执，不能更换幂等键盲目重做。
- 已成功的导入步骤记入台账，失败重试只处理未完成步骤。
- 复用现有服务时不假设跨接口全事务；失败后如已有私有草稿/题库，明确列出。发布仅在相关内容完整校验后进行。
- 任一步骤未落库确认前不得显示成功。多文件部分成功时展示每份文件的结果，不笼统显示全部完成。

## 8. 安全与数据生命周期

文件是待处理数据，不能覆盖助手规则或授予工具权限。上传检查真实类型、压缩展开大小、异常嵌入对象；文档转换关闭网络及宏执行。日志不记录模型密钥、原件全文或完整个人资料。

首次使用说明哪些文件片段/页面将交给模型或 OCR 服务处理，以及保存和删除规则；管理员决定可用供应商。用户可删除私人会话和原始文件；已发布内容所需的图片转成独立授权材料，不能因删除会话而损坏学员页面。

初始保留规则：未执行的上传及解析缓存 30 天；私有会话和草稿保留到教师删除；完整操作回执保留 180 天，之后保留最小幂等索引及业务审计。任务运行中或有可重试操作引用的数据不提前清理。现有业务发布历史保留规则不被助手改变。

## 9. 验证与上线

先实现贯通的 JSON 对话导入，再在同一套任务/预览/执行机制上接入 Word/PDF/PPT；这些均属于第一版承诺范围。每一步都可以独立验证，不以只完成 JSON 宣称全部格式已完成。

必须覆盖的真实场景：
1. 本次两份习题课样本：12+13 题、单/多选混合，题目/答案/原有关联无损，名称与免费角色/模式准确。
2. 同内容 JSON、DOCX、文字 PDF、扫描 PDF、PPTX 及旧版 DOC/PPT 转换样本，结果与人工核对集比较。
3. 不完整答案、图表、公式、跨页选项、双语内容、错误或模糊识别；阻断项不能直接发布。
4. 重复上传、并发标签页、重复确认、模型超时、响应丢失、worker 重启、浏览器刷新与需求变更。
5. 同来源幂等、相似题提示、保留独立用途副本、禁止未经授权覆盖。
6. 跨教师数据隔离、教师权限不足、免费学员/会员访问和学习模式约束。
7. 接近文件/页数上限的批处理及多教师排队；记录 API/worker 峰值内存，确保 API 不承担整份解析，worker 失败不拖垮线上 API。
8. 普通预览确认与明确直接发布两条路径；重新解析导致方案或权限范围改变时，旧确认失效。

发布遵守现有源码/同步产物/active release 链路，先推送部署 UAT，保留手动导入入口。自动化和浏览器自检不替代用户验收；用户明确验收后才合入 main 并部署正式。正式部署前按项目规定备份代码和数据库。
