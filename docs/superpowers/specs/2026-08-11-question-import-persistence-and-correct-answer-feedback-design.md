# 题目导入持久化与正确答案反馈设计

**状态：已确认（2026-08-11）**

## 背景与问题

后台“题目管理”页的“导入 JSON”会先把题库对象放进 `state.banks`，但不写入服务端题目目录。用户随后点击“保存题目”时，保存链路以服务端快照为准刷新目录；刚导入、尚未持久化的题库因此被覆盖，表现为题目消失或清空。

多题画布中，正确选项点击处理已经添加 `is-correct-flash`，但样式表没有这个选择器或绿色动画，故用户看不到正确答案的短暂绿色反馈。

## 目标

1. 在后台“题目管理 → 导入 JSON”中，将导入的题库与题目作为一个服务端原子操作持久化；成功后选中服务器返回的题库/题目，后续“保存题目”不会清空它们。
2. 任一导入项目无效或服务端失败时，不提交任何该次导入数据，并保留原页面数据与明确错误提示。
3. 保留本地试卷导入能力，并根据服务端返回的 ID 映射改写其题库/题目引用，避免导入后试卷指向旧 ID。
4. 在多题画布单击正确选项时，提供与现有错误闪烁一致、时长为 560ms 的绿色反馈；尊重“减少动态效果”系统设置。

## 不在本次范围

- 不改变 Prep Studio 的“同步到题库”批次上传协议。该入口已有独立的本地草稿保留与批次提交逻辑，未使用后台 JSON 导入的覆盖路径。
- 不修改 `legacy/` 源文件，也不重做题目或归纳卡的业务规则。
- 不把本地试卷管理整体迁移到后端；仅修正随 JSON 导入进入本地状态的引用映射。

## 方案比较

| 方案 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- |
| 前端逐题创建题库、题目 | 改动表面最小 | 网络中断会留下部分数据；重试可能重复创建 | 不采用 |
| 首次“保存题目”时补建题库 | 初次导入无需请求 | 其余题仍是草稿，刷新/切换仍可能丢失 | 不采用 |
| 服务端原子导入 | 成功即全部可见，失败即零写入，可返回稳定映射 | 需要新增受权限保护的接口与测试 | 采用 |

## 架构与数据流

```text
JSON 文件
  -> 前端解析、规范化、导入前快照
  -> POST /api/v1/banks/import
  -> 事务：创建题库 -> 创建题目 -> 写一次内容版本
  -> { banks, sourceBankIdMap, sourceQuestionIdMap, contentRevision }
  -> 刷新受管目录、定位最后一题、映射本地试卷引用
```

### 服务端接口

新增 `POST /api/v1/banks/import`，要求 `accessQuestionBank + manageQuestionBank` 权限。请求包含已规范化的 `banks`（每项含源 `id`、题库字段与 `questions`）；可选带 `papers` 仅用于客户端映射，不发送给服务端。

服务端永远生成新的 `b_*` 和 `q_*` ID，不信任文件中的 ID 作为数据库主键。响应包含：

- `banks`：完整、可直接写入受管目录的已持久化题库和题目；
- `sourceBankIdMap`：源题库 ID 到新服务端 ID；
- `sourceQuestionIdMap`：以 `"{sourceBankId}::{sourceQuestionId}"` 为键的新题目 ID；
- `contentRevision`：本次导入成功后递增一次的教学内容版本。

在同一个数据库事务内，先验证所有源 ID 不重复、题库均至少含一题，再规范化并创建所有对象。任何验证、权限、数据库异常都回滚事务；不发布内容版本，也不返回半成品。

### 前端交互

`importJson` 改为异步：解析文件后保存页面级导入前快照，调用目录适配器的 `importBanks`。适配器收到响应后刷新受管目录并发布一次远端内容变更事件。

成功时，前端只用服务端返回/刷新后的目录重建 `state.banks`，选中最后导入题库的第一道题；若 JSON 含本地试卷，使用映射重写 `bankId`、`questionId` 后才保存本地试卷状态。

失败时，不调用 `reloadBanksFromCatalog`，恢复导入前页面状态，显示“导入未提交”的错误；不会把已显示的题目替换为空目录。

### 正确答案反馈

保留现有 `handleOptionSingleChoice` 与 `CORRECT_FLASH_DURATION = 560`。在 `question-workspace.css` 添加 `.qw-card-option-key.is-correct-flash` 及 `qw-option-correct-flash`：绿色背景、边框、文字颜色和短暂亮度脉冲。`prefers-reduced-motion` 下不播放动画，但仍显示静态绿色提示。

## 验收标准

1. 导入一个含题库和题目的 JSON 后，题库列表和题目列表展示的是服务端生成 ID 的记录；保存该题后记录仍存在。
2. 导入包含重复源 ID 或不合法题目的 JSON 时，接口返回失败，服务端不新增该次的任何题库或题目，页面当前题目不被清空。
3. 随 JSON 导入的本地试卷引用会指向新生成的服务端题库/题目 ID。
4. 单击正确答案在画布中出现绿色闪烁；点击错误答案仍为既有红色闪烁；减少动态效果设置下不产生动画但保持绿色状态。
5. Prep Studio 的上传入口与现有批次同步测试保持通过。

## 验证策略

- 后端 pytest 覆盖成功导入、原子回滚、权限拒绝、内容版本单次递增与 ID 映射。
- Node 受管目录测试覆盖前端请求、成功定位和失败快照恢复；不允许再由 `saveBanks()` 伪装为持久化。
- 多题画布测试覆盖正确闪烁类、绿色样式和减少动态效果规则。
- 发布前运行相关 Node/Python 测试、完整后端测试与前端类型检查；按发布纪律核对候选 release 与 active release 的文件数后再发布。

## 追加范围：原则与归纳卡管理（2026-08-11）

训练配置的工具栏提供紧凑的导出、导入按钮，文件格式与 Prep Studio 完全一致：`kg-principle-card-bundle-v1`，每条原则恰好有一张归纳卡，归纳卡标题由原则名称统一生成。导入走服务端单一事务替换全局配置；若替换会移除仍被任何题目引用的原则，整个导入拒绝且不改变现有配置。

“归档所选”改为“删除所选”。删除先检查所有题干/选项原则绑定；未被引用的原则及其归纳卡在关系表、共享运行时投影和列表中彻底移除，同时清理其他原则的易混淆引用。被引用时返回具体题数，前端不伪装成已删除或仅改成停用。

原则列表中的卡片支持双击：先弹出该原则关联的跨题库题目列表；再双击列表中的题目打开完整题干、选项、正确答案和解析预览。预览的“编辑”入口使用既有 `question-bank.html?mode=simple&step=questions&bankId=…&questionId=…` 深链接，直接进入同一题目的编辑页。

追加验收：

1. 导出的组合包能被 Prep Studio 和训练配置重新导入，且标题始终为“原则：{原则名称}”。
2. 未引用原则删除后刷新页面不再出现；已引用原则删除/导入替换被拒绝并显示引用数量。
3. 双击原则、双击关联题目可分别打开列表和预览，预览的编辑链接包含准确的题库与题目 ID。
