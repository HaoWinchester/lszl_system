# 深度回忆 P4.5 数据库化纵向迁移设计

日期：2026-08-14
状态：用户已批准直接实施

## 背景

当前服务器源 `new-legacy/` 为 `v9.0-p4.1.54`，同事提供的最新功能源
`updata-legacy/` 为 `v9.0-p4.5.28`。后者已经实现深度回忆连续流程、正式 Recall
命中、大图增量渲染、节点拖拽、当前画布搜索、连续工具栏和 Keyword v2 运行时，
但其业务进度与联想库治理仍以浏览器存储为主，并且 P4.5.26 会在学员端视觉强调核心
关键词。

目标是在现有 FastAPI + PostgreSQL 服务器底座上选择性迁移这些成熟能力，并以
P4.5.29 的安全规则覆盖 P4.5.26：普通与核心关键词初始均不可见，揭示后使用完全
相同的视觉样式；核心身份只参与后台匹配优先级和后续诊断。

## 目标

第一阶段完成可独立发布的学员端深度回忆闭环：

- 迁移同事版已验证的学员端流程、搜索、大图性能和画布行为。
- 题目、正式 Recall 联想库和个人深度回忆进度全部以 PostgreSQL 为权威。
- 未命中正式 Recall/Alias 的手输内容可以创建账号与题目隔离的个人节点。
- 题目更新后保留旧回忆图，禁止新旧关键词和联想关系静默混合。
- 保留服务器权限、订阅限额、访客只读、Focus/Vega 皮肤和发布纪律。

## 非目标

本阶段不实现：

- 教师端 Recall 联想库导入、编辑、发布历史和审批 UI。
- 将个人节点自动升级为正式节点。
- 学习诊断评分、掌握度计算和个性化推荐。
- 整体覆盖 `new-legacy/`、`frontend/public/new-legacy/` 或 active release。
- 迁移同事版 `localStorage-v2`、IndexedDB 或任何浏览器业务真源。

## 方案

采用数据库优先的选择性纵向迁移：复用同事版经过验证的纯业务行为和测试意图，保留
服务器版 DOM、Focus/Vega 视觉、权限和发布链路。前端新增异步服务器适配层，控制器
只在内存中持有当前会话状态；服务端使用专用关系表和 API 持久化。

不采用先复制再数据库化，因为这会形成可被误发布的本地业务真源中间态；不采用整页
重写，因为会扩大 UI 和画布回归范围。

## 数据模型

### 题目版本快照

新增不可变题目快照表，以 `question_id + question_revision` 唯一标识。快照只保存深度
回忆运行所需内容：题干、选项、关键词、概念、Recall 绑定、科目、题库和内容哈希。
学员首次打开某题当前版本时确保快照存在。题目更新后，已经存在的旧快照继续可读。

### 正式 Recall 联想库快照

第一阶段从服务器已发布的科目联想库读取，只提供学员端只读接口。服务端为被深度回忆
会话使用的正式库生成内容哈希与不可变快照，个人进度记录所使用的库哈希，避免正式库
更新后向旧图静默注入新关系。

### 个人深度回忆进度

扩充现有 `recall_progress`，保留 `owner_id + question_id` 账号隔离，并增加：

- 来源题库、题目 revision、内容 hash、联想库 hash。
- 图模型 schema 版本。
- 节点、边、个人节点和已激活关键词。
- 推荐轮换位置、画布 transform 和会话指标。
- 乐观并发 revision 与保存时间。

个人节点只存在于个人进度，不进入正式联想库。节点保存标题等显示快照，保证历史图在
正式库更新后仍可阅读。

“揭示关键词”属于每次进入页面的会话状态，不持久化；刷新或重新进入时重新隐藏，图谱
进度本身继续保留。

## API 与数据流

### 会话读取

`GET /api/v1/recall/session/{question_id}` 返回：

- 当前题目与当前 revision/content hash。
- 当前账号的个人进度及 progress revision。
- 进度对应的历史题目快照。
- 当前与历史版本是否一致。
- 进度绑定的正式 Recall 联想库快照。
- 当前权限与节点限额。

如果当前题目版本与进度版本不同，前端必须进入版本选择状态，不能自动合并。

### 进度保存

`PUT /api/v1/recall/progress/{question_id}` 携带期望的 progress revision、题目 revision
和联想库 hash。服务端校验题目访问权、负载结构、节点限额和并发 revision，成功后在
单个事务内提交并返回新 revision。

同账号多标签页发生并发冲突时返回 `409`。前端保留内存状态，提示重新加载，不静默
覆盖。

### 重置到新版本

`POST /api/v1/recall/progress/{question_id}/reset` 要求期望的 progress revision 和目标
题目 revision。服务端在事务内把进度重置到当前题目与当前正式联想库快照。

### 正式联想库

`GET /api/v1/recall/libraries/{subject}` 只读返回当前已发布联想库、内容 hash 和更新时间。
第一阶段不提供学员写接口。

### 失败语义

- 读取失败：显示明确错误和重试，不用演示数据冒充当前账号数据。
- 保存失败：保留页面内存状态，显示“尚未保存”和重试入口，不写浏览器业务缓存。
- 页面隐藏、切题和退出前强制提交；无法完成时保持失败状态，不显示保存成功。
- 数据库不可用时不降级为本地业务持久化。

## 学员端交互

### 关键词安全揭示

1. 进入题目时题干和选项按普通正文显示，不能看出关键词位置。
2. 学员点击一次“揭示关键词”，全部普通和核心关键词以同一种样式显示。
3. 学员点击具体关键词后才生成或定位第一层节点。
4. 核心关键词不使用额外颜色、加粗、徽章或加载闪现，只在重叠匹配排序中优先。
5. Recall 为空的关键词仍可作为个人探索入口，但不得生成伪造的正式 Recall ID。

### 正式节点与个人节点

- 手输内容先按正式 ID、中文名、英文名和 Alias 查询当前会话绑定的正式库快照。
- 命中时复用正式节点稳定 ID。
- 未命中时生成仅当前账号、当前题目可见的个人节点。
- 学员不能修改正式节点，也不能把个人节点反向写回正式库。

### 连续回忆

- 推荐候选过滤当前节点、父节点和祖先节点，避免即时回跳。
- 输入框和“生成”常驻，支持 Enter 提交。
- “换一组”位置固定；没有第二组时禁用并说明原因。
- 无推荐时仍允许手输，不形成流程死路。

### 大图与画布

- 联想库读取、索引和手输解析使用页面内存缓存。
- 新节点与新关系增量渲染，不重建全图。
- 每条关系只绘制一个轻量 Path，不使用 glow/filter。
- 节点拖动只更新当前节点和关联关系。
- 当前画布搜索支持中文、英文和 Alias；选择结果后定位并打开引导。
- 搜索与重置保持连续工具栏。
- `100%` 只恢复缩放；“回到题目”单独定位中央题目。

### 版本变化

题目 revision 变化时显示版本选择：

- “查看旧图”使用旧题目和旧联想库快照，只读展示，不再修改旧版本进度。
- “按新题重置”需要二次确认，重置后使用当前题目和当前正式库。
- 不提供自动合并。

## 权限与限制

- 访客维持现有示例只读模式，不能揭示关键词、创建节点、修改图或重置进度。
- 已登录且具备 `useDeepRecall` 权限的角色保存自己的进度。
- 保留免费学员单题节点上限和既有会员权益。
- 正式 Recall 库读取受题目/科目访问权限约束。
- 不改变 admin、teacher、student、viewer 的既有角色矩阵。

## 迁移来源与裁决

从 `updata-legacy/` 选择性迁移以下行为：

- P4.5.12：正式 Recall 手输命中、祖先过滤、常驻输入和“换一组”。
- P4.5.17：联想缓存、增量渲染、轻量关系、节点拖拽和缩放语义。
- P4.5.19：当前画布节点搜索。
- P4.5.20：搜索/重置连续工具栏。
- P4.5.26：共享 Keyword v2 匹配优先级。

明确不迁移：P4.5.21 的本地存储治理实现。其“预检、事务、回滚、容量诊断”意图改由
PostgreSQL 事务、API 校验和服务端错误响应实现。

P4.5.26 的核心关键词视觉强调被 P4.5.29 覆盖；学员端不得暴露核心身份。

## 验收与测试 Gate

### 后端

- 同一题目的两个账号进度完全隔离。
- 相同账号在不同题目、不同题目 revision 下不串数据。
- 正式 Recall 库只读，个人节点不进入正式库。
- 进度保存、重置和快照建立具有事务性。
- 期望 revision 不一致返回 `409`，失败不覆盖原记录。
- 清理浏览器数据或换设备后仍可从数据库恢复。
- 数据库失败时没有本地业务写入和伪成功。

### 前端静态与单元

- 移植并改写 P4.5.12、P4.5.17、P4.5.19、P4.5.20 的行为契约测试。
- 断言深度回忆业务进度不直接调用 `localStorage`、IndexedDB 或 Runtime State 写入。
- 断言核心/普通关键词揭示后使用相同 class 与可见样式契约。
- 断言增量节点/边、局部拖动更新、单 Path 和内存缓存保留。

### 浏览器 E2E

- 初始状态看不出任何关键词；无核心词加载闪现。
- 点击“揭示关键词”后全部关键词出现，普通/核心计算样式一致。
- 正式 ID、中文、英文、Alias 均可命中；未命中创建个人节点。
- 父节点和祖先节点不出现在当前分支推荐中。
- 刷新、重新登录和换浏览器上下文后进度恢复。
- 两个账号、两个标签页、题目更新、保存失败和重试均符合设计。
- 搜索、拖拽、换一组、重置、100% 和回到题目都有可观察结果。
- 访客只读、权限不足、免费节点上限和会员无限规则回归通过。

### 大图回归

使用不少于 500 个节点、2,000 条关系的固定测试数据：

- 新增节点不触发全图重建。
- 拖动节点只更新相关关系。
- 搜索不重建图层。
- 关系保持单 Path、无 glow/filter。
- 性能断言以调用次数和增量更新范围为主，避免依赖机器性能的脆弱绝对耗时。

### 发布

- 发布前核对候选 site 与当前 active release 文件数和关键页面。
- 必须验证 `knowledge-recall.html`、题库预览入口、训练入口和访客入口。
- 正式发布只走 `manage-new-legacy.js update new-legacy --skip-browser`，不手工覆盖 release。

## 完成标准

- 第一阶段所有学员端功能、异常路径和恢复路径通过自动化与真实浏览器测试。
- 深度回忆个人进度、个人节点和版本关系全部在 PostgreSQL，可跨设备恢复。
- 正式 Recall 命中和未命中个人节点行为正确，数据不跨账号、不污染正式库。
- 题目更新不静默混合旧图。
- 核心关键词在学员端没有任何提前泄露。
- 服务器权限、会员限额、Focus/Vega 视觉和 active release 内容没有回退。
