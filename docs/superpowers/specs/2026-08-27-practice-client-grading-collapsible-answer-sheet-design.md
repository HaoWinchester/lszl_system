# 做题模式前端即时判题、显式保存与折叠答题卡设计

## 1. 背景与问题

本规格是
`2026-08-26-practice-answer-sheet-resume-pmp-result-design.md` 的定向修订，覆盖其中
“逐题服务器判题、短间隔自动保存、桌面常驻答题卡”相关决策；成绩报告、领域配比、
账号隔离和不可变发布版本等未被本规格修改的内容继续有效。

当前 `practice-mode.html` 的可恢复会话在用户每次选择答案时调用
`POST /api/v1/learning/practice/sessions/{session_id}/answers`。服务器立即判题、
写入答案和错题状态，再把正确答案与解析返回前端；页面另外每 5 秒调用一次
`PATCH .../state` 保存运行状态。

这条链路产生了三个产品问题：

1. 选择一次选项就产生一次写请求，请求失败时直接打断做题并显示“进度保存失败”；
2. 游戏反馈依赖网络往返，挑战、学霸和复仇模式在弱网下无法顺畅运行；
3. 桌面端答题概览长期占用 300px 宽度，压缩题目区域。

退出弹窗还存在独立布局缺陷：内容区约 368px，三个按钮的最小总宽度加间距
超过容器，桌面端会向左溢出；窄屏断点则形成不稳定的“2+1”排列。现有测试只
验证按钮存在和可点击，没有验证实际几何边界。

## 2. 已确认的产品决策

- 本产品用于练习，不以隐藏正确答案作为防作弊边界。
- 开始练习时一次性向前端提供本次冻结题目及正确答案。
- 选择答案只在前端判定，不调用答案或进度保存接口。
- 不做 30 秒或其他固定间隔的自动保存。
- 只有“保存并退出”和“交卷”会向服务器写入本次整卷数据。
- 交卷前已选答案沿用既有规则：选择成功后锁定，不能反复试答案。
- 服务器在交卷时根据发布快照重新判分，不接受客户端上传的 `correct`、分数、
  PASS/FAIL、领域等级或错题判定作为事实。
- 答题概览默认折叠为右上角紧凑入口，用户点击后再打开完整答题卡。
- 退出弹窗三个按钮使用等宽纵向排列，不再根据宽度自动形成“2+1”。
- 做题页所有由点击触发的接口请求，在等待响应期间统一显示现有公共加载框。

## 3. 范围

### 3.1 包含

- 挑战、学霸、复仇三种模式的前端即时判题；
- 整卷草稿显式保存与恢复；
- 整卷原子交卷、服务端重算、错题推进和报告冻结；
- 可折叠答题卡及桌面、移动端响应式呈现；
- 退出弹窗三按钮布局修复；
- 请求次数、草稿恢复、整卷交卷、布局几何和失败恢复测试。

### 3.2 不包含

- 定时自动保存、逐题保存或页面卸载时发送业务写请求；
- 将答案、成绩或会话保存到 `localStorage`、`sessionStorage` 或 IndexedDB；
- 修改当前 `42% / 50% / 8%` 领域配比；
- 修改 PMP 风格成绩单、饼图和模拟合格判定规则；
- UAT 部署或合并到 `main`。

## 4. 判题与数据所有权

### 4.1 前端负责临时交互事实

本次页面打开期间，前端内存维护：

- 每题所选答案和选择顺序；
- 本地即时正误状态；
- 当前题号、生命值、连胜、经验、剩余时间；
- 复仇模式当前补救或验证阶段；
- 答题卡筛选和打开状态。

这些值用于即时反馈和游戏表现，不直接成为最终成绩事实。

### 4.2 服务器负责持久业务事实

服务器继续负责：

- 账号、试卷和发布版本隔离；
- 冻结本次题目顺序与判分依据；
- 显式保存的未完成整卷草稿；
- 交卷时逐题重算正误、错题状态和统计；
- 冻结成绩报告与学习事件；
- revision 冲突和终态不可逆约束。

正确答案可以随本次会话题目下发，但服务器不得相信客户端回传的判题结果。

## 5. 会话数据结构

`practice_sessions.answers` 在未完成状态保存未判题草稿，完成后保存服务端判题事实。
每条记录显式区分阶段：

```json
{
  "question-id": {
    "selectedAnswer": "B",
    "timedOut": false,
    "selectionIndex": 3
  }
}
```

未完成会话的答案不得包含由客户端决定的 `correct`、`correctAnswer` 或分数。
交卷事务用冻结发布快照重建完成态答案：

```json
{
  "question-id": {
    "selectedAnswer": "B",
    "correctAnswer": "C",
    "correct": false,
    "submittedAt": "server-time",
    "submissionIndex": 3
  }
}
```

`runtime_state` 继续保存当前题号、生命、时间和复仇阶段。草稿答案与运行状态在
同一个显式保存请求中写入，避免答案已保存但界面状态未保存。

## 6. API 设计

### 6.1 开始或恢复

`POST /practice/sessions/start` 和 `GET /practice/sessions/{id}` 返回本次冻结顺序中的
完整题目快照，包括正确答案和即时反馈所需解析。只返回当前登录账号有权练习的
发布版本。

恢复未完成会话时，同时返回未判题草稿答案和运行状态。前端根据正确答案重建
答题卡颜色、生命、连胜和其他即时状态，但最终成绩仍未生成。

### 6.2 显式保存

新增或调整统一草稿写入口，使“保存并退出”一次提交：

```json
{
  "revision": 4,
  "answers": {
    "question-id": {
      "selectedAnswer": "B",
      "timedOut": false,
      "selectionIndex": 3
    }
  },
  "runtimeState": {
    "currentIndex": 6,
    "health": 2,
    "streak": 1,
    "remainingMs": 42000,
    "durationMs": 158000,
    "revengeState": null
  }
}
```

请求成功后会话改为 `paused`。失败时停留在做题页，保留全部内存答案并提供重试，
不能显示“已经退出”。

### 6.3 交卷

`POST /practice/sessions/{id}/complete` 接收与显式保存相同的整卷答案和运行状态。
答完最后一道题只更新本地答题卡，不自动调用交卷接口；用户必须明确点击“交卷并查看
成绩”。若仍有未答题，继续显示“返回未答题 / 仍要交卷”确认。
服务器在一个事务内：

1. 校验 owner、revision、会话状态、题目归属和选项合法性；
2. 按 `selectionIndex` 和冻结快照重新判定全部已答题；
3. 将未答题计为零分并保留 `unanswered` 统计；
4. 按顺序重算挑战/学霸经验等派生统计；
5. 推进错题与复仇相关状态；
6. 生成并冻结成绩报告；
7. 把会话改为 `completed` 并追加完成事件。

任一步失败则整笔回滚，前端保留当前答案并显示可重试的交卷错误。

### 6.4 旧逐题接口

做题页不再调用 `/answers`。接口可以在迁移期保留给旧版本兼容，但新前端请求矩阵
必须断言选择选项不会调用它。确认所有活动版本退出兼容期后再单独评估删除，不在
本轮直接移除路由。

## 7. 三种模式交互

### 7.1 挑战模式

前端根据正确答案即时显示正误、扣减生命和更新连胜。生命归零提示仍允许用户按
现有规则继续完成全卷。服务器只在交卷时生成正式错题和报告事实。

### 7.2 学霸模式

前端即时加减时间、扣减生命和处理连续答对回血。超时只记录为本地
`timedOut: true`，不立即写服务器。保存退出时保存剩余时间；暂停期间时间不减少。

### 7.3 复仇模式

前端根据答案即时进入补救和验证交互，未交卷时只作为本次会话草稿状态存在。
保存退出需要完整保存当前复仇阶段。交卷时服务器按冻结题目和提交顺序统一推进
长期错题状态，防止客户端直接伪造“已掌握”。

## 8. 折叠答题卡

### 8.1 入口

做题顶部右侧始终显示紧凑按钮：`答题卡 已答/总数`。该按钮在桌面和移动端共用
同一 DOM 与事件入口，避免两套状态分叉。

### 8.2 打开方式

- 桌面端：从右侧打开覆盖式抽屉，不再给 `.practice-game` 预留 324px；
- 移动端：沿用底部抽屉；
- 抽屉内继续提供总数、已答、未答、正确、错误、题号、筛选和交卷；
- 点击题号后切题并关闭抽屉，顶部入口继续可见；
- 点击关闭按钮、遮罩或按 `Escape` 均可关闭并把焦点还给入口。

开始做题时答题卡默认关闭。用户关闭后不会因为切题或答题自动重新打开。

### 8.3 状态来源

交卷前答题卡正误来自前端即时判题；交卷后和错题复盘页只使用服务器冻结结果。
颜色以外继续提供状态文字和 `aria-label`。

## 9. 退出与离开

退出弹窗操作顺序固定为：

1. `继续做题`；
2. `保存并退出`；
3. `放弃本次练习`。

三个按钮在所有宽度下纵向、等宽、完整包含在弹窗内容区。放弃仍需要二次确认。

页面存在未显式保存的答案或运行状态时，刷新、关闭标签页或跳离页面触发浏览器
原生离开提醒；不在 `beforeunload` 中发送网络请求。用户选择离开后，最后一次显式
保存之后产生的变化会丢失，这是取消自动保存后的明确产品行为。

## 10. 错误与并发恢复

### 10.1 点击请求加载反馈

做题页复用 `src/110-learning-loading.js` 暴露的 `KGLearningLoading.show/hide`，不新增
另一套遮罩或旋转图标。所有由用户点击直接触发并需要等待接口结果的操作，都必须
在请求开始前显示加载框，并在 `finally` 中关闭：

- 开始或继续练习：`正在进入练习` / `正在读取试题…`；
- 保存并退出：`正在保存进度` / `正在保存整份练习…`；
- 交卷：`正在提交试卷` / `正在核对成绩并生成报告…`；
- 放弃练习：`正在放弃练习` / `正在更新练习状态…`；
- 加载服务器最新进度：`正在恢复进度` / `正在读取服务器版本…`；
- 从学习记录打开成绩报告：`正在加载成绩` / `正在读取成绩报告…`。

加载框显示期间禁用触发按钮或使用统一的请求中锁，防止双击产生重复请求。无论成功、
业务失败、网络异常还是 409，加载框都必须关闭；失败后页面保留可重试操作。选择题目
选项和本地切题不调用接口，因此不显示加载框。

### 10.2 错误与并发

- 开始题目加载失败：停留大厅并允许重试；
- 本地选择答案：不再出现“进度保存失败”；
- 保存并退出失败：保留当前页面、答案和计时状态，按钮恢复可点击；
- 交卷失败：保留整卷答案，不显示成绩成功页；
- revision 409：锁定持久化动作，提供“加载服务器版本”；不能静默覆盖；
- 重复保存：相同 revision 和相同草稿可幂等返回；
- 重复交卷：已完成会话返回相同冻结报告，不重复累计经验或错题；
- 恢复草稿数据损坏：服务器拒绝非法题号或选项，前端展示明确恢复失败，不猜测修复。

## 11. 需求追踪与测试

| 区域 | 正向路径 | 失败/反向路径 | 恢复路径 |
| --- | --- | --- | --- |
| 选答案 | 本地即时判题和游戏反馈 | 断网时仍可继续当前页面作答 | 恢复网络后可保存或交卷 |
| 请求矩阵 | 连续选择多题不产生写请求 | 捕获任何 `/answers` 或 `/state` 写请求即失败 | 不适用 |
| 保存退出 | 一次请求保存整卷草稿并回大厅 | 500/超时不退出、不丢内存答案 | 重试后恢复成功 |
| 恢复 | 题目顺序、答案、运行状态一致 | 非法草稿被拒绝 | 放弃损坏会话后可重开 |
| 交卷 | 一次整卷请求，服务器重算报告 | 伪造 correct/score/PASS 被忽略 | 失败后再次交卷 |
| 并发 | 最新 revision 成功 | 旧标签页返回 409 | 加载服务器版本 |
| 答题卡 | 右上入口打开、切题、关闭 | 重复开关不出现双抽屉或焦点丢失 | 入口始终可再次打开 |
| 退出弹窗 | 三按钮顺序、文案、动作正确 | 取消和保存失败均留在题页 | 可继续作答或重试 |
| 点击请求加载 | 请求开始显示公共加载框并阻止双击 | 500、超时和 409 均关闭加载框 | 失败后按钮恢复并可重试 |

### 11.1 后端测试

- 开始/恢复载荷包含正确答案，但只返回有权访问的冻结题目；
- 整卷草稿字段白名单、题目归属和选项校验；
- 保存退出原子保存答案与运行状态；
- 交卷忽略客户端判题字段并从发布快照重算；
- 复仇错题状态只由服务器根据整卷选择推进；
- 未答、超时、重复保存、重复交卷、409、账号隔离和终态不可逆。

### 11.2 前端契约测试

- 选择选项不调用 `answerSession`、`updateState` 或其他写接口；
- 保存退出只产生一次草稿写请求；
- 交卷只产生一次整卷完成请求；
- 离开提醒仅在存在未保存变化时启用；
- 桌面不再存在永久侧栏占位样式；
- 答题卡入口与抽屉使用同一渲染状态；
- 退出三个按钮固定纵向等宽。
- 点击触发的开始、保存、交卷、放弃、恢复和成绩加载统一调用公共加载框，且异常路径
  必须执行 `hide`。

### 11.3 真实浏览器测试

- 挑战、学霸、复仇各完成一次多题作答并记录请求列表；
- 断网后选择多题仍能即时反馈，保存/交卷失败后可恢复；
- 保存退出、刷新、重新登录后恢复到相同题号和答案；
- 交卷后成绩、错题位置和服务器重算结果一致；
- 1280、1024、768、390px 视口下打开和关闭答题卡；
- 退出弹窗三个按钮的左右边界均位于弹窗内容区内，宽度一致且互不重叠；
- 延迟接口响应时加载框保持可见、触发按钮不可重复提交，成功和失败后都关闭；
- 所有可见按钮进行正向点击、取消、失败、重试和重复点击检查。

## 12. 发布约束

- 权威前端修改只进入 `new-legacy/` 和职责明确的同步适配层；
- 后端变更遵循 API → service → model 分层，写后 `refresh`；
- 先新增失败测试，再修改实现；
- 定向测试通过后运行后端、前端契约和真实浏览器全量相关测试；
- 正式 release 继续由 `manage-new-legacy.js update new-legacy --skip-browser` 生成；
- 本轮先留在 `uat` 分支供本地验证，不部署 UAT、不合并 `main`，除非用户再次明确授权。
