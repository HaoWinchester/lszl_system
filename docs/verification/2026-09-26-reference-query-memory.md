# 生产题库引用查询内存故障

## 根因与范围

2026-09-26 正式站点失去响应时，占用异常的是 `lszl-kg-backend-1` 内的 Python/Uvicorn 进程；第一次约 1.7 GiB RSS 加 3.7 GiB swap，恢复后再次达到约 2 GiB RSS。内核栈显示等待交换页读取，数据库有长时间的试卷发布引用查询。不是 JSON 导入格式导致的内存问题。

`GET /api/v1/questions/reference-snapshot` 调用共享引用服务，旧查询选择完整的 `PaperRelease` 与 `PaperReleaseQuestion` ORM 实体。每条题目引用都重复携带整份试卷 `source_payload`，随后被驱动解码成 Python JSON 对象。教师页面关系数据初始化会请求此接口。清理引用盘点存在相同连接方式。

只读 SQL 统计：43 个发布、5,468 条发布引用，正文只取一次约 12 MB，按旧连接结果重复后约 1,054 MB；单个发布最多 185 道题。全库 67 个题库、3,298 道题。证据位于工作区 `output/production-memory-fix-2026-09-26/`，没有在本报告输出题目正文、数据库内容或凭据。

## 修复

- 引用索引只读取实际响应需要的列，不读取试卷正文、冻结题目快照和题目解析。
- 清理盘点仍校验每条冻结题目快照，但按 100 条分批读取；不读取重复的整卷正文。
- 保留 owner 过滤、空容器、历史发布、排序、分数和快照指纹；不修改业务数据、接口格式或数据库结构。
- 新增真实 PostgreSQL 回归，原实现先出现内存断言失败；修复后通过。最终夹具 132 条引用覆盖游标批次边界，SQL 断言阻止重新加载无用大字段。

## 验证

- 定向后端：18 passed；最终 132 条夹具：2 passed。
- 独立代码审查无阻断项；建议覆盖超过 100 条引用，已补充。
- 在正式容器中启动独立短时 Python 进程，将候选函数仅载入该进程；事务 `READ ONLY`，30 秒 SQL 超时，768 MiB 地址空间限制。没有替换运行中的 Uvicorn 代码或修改正式数据。
- 引用索引连续 3 次：3.843 / 3.530 / 3.292 秒，Python 分配峰值 116.10 / 112.47 / 112.56 MiB，进程 RSS 峰值 268.98 MiB；每次返回完整 43 个发布、5,468 条引用与 3,298 道题。
- 清理盘点：8,638 条引用，20.081 秒（含 tracemalloc 开销），Python 分配峰值 33.58 MiB，RSS 峰值 146.64 MiB。
- 完整后端：739 passed，355.26 秒。完整前端复核：279 个 Node 契约、9 个 Python 契约和 4 组 UAT 部署检查通过。初次前端运行受工作区输出日志持续变动影响，发布上下文防变更检查拒绝通过；等待后台日志写入结束、将前端日志放入忽略目录后重新完整运行通过，没有修改或绕过门禁。
- 3 个并发生产数据只读请求：11.701 秒（含 tracemalloc 开销），Python 分配峰值 237.93 MiB，进程 RSS 峰值 572.99 MiB；三个响应指纹一致。
