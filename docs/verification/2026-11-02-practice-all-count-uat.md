# 做题题量“全部”：UAT验证记录

用户要求在现有10、20、60、180题之外增加“全部”，以便一次完成93/99题试卷。开发自检不替代用户业务验收，最终只发布UAT，不合入main。

## 实现

- `new-legacy/practice-mode.html`增加独立题量选项“全部（N题）”；`100-practice-mode.js`统一解析题量并在切换试卷、空卷恢复、再次练习时保留整卷选择意图。
- 后端现有会话服务接受`count: "all"`，校验发布版本、模式和访问权限后，从当前冻结题目表统计真实题数。固定数字仍限制1–180，复仇入口保留现有策略。
- 沿用原案例组完整选择与服务端冻结会话、题序和保存流程。继续已有练习不擅自改变题数；用户要按新设置练习时走原“新开一轮”及确认流程。
- 调整全部选项的宽度，完整显示中文和题数；布局及其他模式不重做。

## 星空测试首帧同步修复

静态布局模型创建时`settled`即为true，Canvas实际绘制由后续requestAnimationFrame调度；旧测试只等模型稳定，可能在首帧前断言星点数量。给测试首帧注入500ms延迟，旧等待条件确定性复现失败；改为同时等待模型稳定且真实Canvas星点绘制次数达到81。原绘制断言、布局与交互断言保留，未增加固定sleep或修改星空产品代码。修复后正常与500ms延迟两种运行均在1440/559/390宽度通过。证据为`semantic-delayed-red.log`、`semantic-delayed-green.log`、`semantic-normal-green.log`。
