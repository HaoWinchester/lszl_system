# 小程序底栏响应与协议一致性修复

## 用户反馈
- 微信开发者工具内，每次点击底部栏目都有明显等待。
- 隐私政策、用户协议必须与PC端内容一致。

## 已定位的原因
- 原先每次底栏点击都走 wx.switchTab，创建/切换原生页面。开发工具实测点击处理到调用路由仅3ms，但首次调用到完成约1486ms，已加载页面返回约226–241ms。
- 减少重复主题桥接调用、改用navigator的实验分别仍约225ms和242ms，首次仍约1.4–1.5秒；不能声称这些实验已解决根因。navigator实验已撤回。
- 最终采用一个原生页面保留四个栏目组件，底栏只切换可见性。渲染完成回调实测练习31ms、成长26ms、我的24ms、首页25ms，后续另一次练习49ms；这不是接口耗时，也不代表所有手机的上限。
- 四个栏目原文件与业务方法继续复用，公共适配器处理生命周期、可见性和返回；二级页面维持既有流程。
- 原协议只有简短摘要。现在从new-legacy两份PC协议article生成完整文本，含标题、日期、所有段落和末尾说明；不改写法律文本。npm test先校验生成产物与PC来源一致，PC更新后需npm run sync:legal。
