# 当前客户端登录分支排查与修正（1.0.9）

## 排查边界

按用户要求检查当前提审/测试客户端，不以正式服务可访问代替当前版本验收。微信“登录无法加载完整内容/白屏/报错”是合并描述；本次未取得审核设备的具体错误，也未复现纯白屏，因此不能将下列故障注入结果直接宣称为该次驳回的唯一根因。

## 当前代码已复现的问题

在原 services/auth.ts 上新增测试，初次运行 4 项失败、1 项成功：

1. wx.getDeviceInfo 抛错时，登录在请求服务前中断；可选设备元数据不应成为身份认证前置条件。
2. wx.login 返回空 code 时仍发起登录 HTTP 请求，无法在客户端给出明确恢复提示。
3. 登录 HTTP 返回未识别的 status 时，页面没有后续分支，submitting 保持 true，按钮一直等待。
4. 绑定/注册接口返回不完整的 authenticated 数据时，也会调用 setSession，留下无效会话。

## 修复

公共 auth 服务对两个可选设备 API 独立容错，并按后端字段长度约束元数据。微信登录设置 12 秒 SDK 超时，失败或空凭证返回可重试错误。校验登录状态、绑定凭证、token 和 username；非法响应在写入缓存和导航前拒绝，由既有页面 catch 恢复按钮。

正常首次绑定、已绑定账号登录及协议流程保留。未调整域名、后端、数据库、账号权限或协议内容。

- 排查后恢复“普通编译”；原账号数据与草稿保留。
