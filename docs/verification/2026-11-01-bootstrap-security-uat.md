# Bootstrap 全量读取防护与 UAT 验证

## 本次行为

- `question-catalog/bootstrap` 的 `include_questions=true` 仅保留给具有 `accessQuestionBank` 权限的有效教师/管理员；普通目录摘要、分页题目读取和正常做题保持原有契约。
- 匿名或普通学员明确请求全量题目时，第一次即返回 `403 / BULK_READ_BLOCKED`，不返回题目或答案；持久化锁定可识别的来源 IP，已识别的登录账号设为 `paused`。匿名请求不推断或封禁其他账号。
- 已锁 IP 后续全站请求返回 `403 / IP_LOCKED`；健康检查例外。数据库封禁跨进程、重启有效。
- 普通请求超频仍为 `429`，不触发封号。教师题库导入后的合法批量刷新保持正常。
- 明确跨站的 Fetch Metadata、Origin 或 Referer 请求只拒绝读取，不处罚可能被第三方页面诱导的用户。缺少这些来源标记的客户端无法可靠区分人工直连与诱导请求，这是首次封禁策略的边界。
- 同一公网出口可能由多人共用，IP 锁定会影响该出口下的其他用户，直到管理员解锁。

## 管理员恢复

- `GET /api/v1/system/security/ip-blocks?limit=100&offset=0`：分页查询 IP 锁定记录，仅管理员。
- `DELETE /api/v1/system/security/ip-blocks/{ip}`：解除指定 IP 锁定并写审计，仅管理员；需要从未锁定的来源操作。
- IP 解锁不会自动恢复账号。通过现有用户管理把账号从“暂停”恢复为“正常”。
- 审计事件：`bulk_read_blocked`、`ip_block_released`。
