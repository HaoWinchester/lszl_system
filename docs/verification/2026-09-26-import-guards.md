# 导入重复操作保护

用户要求补齐导入按钮限制。沿用现有导入、冲突确认和数据格式，不改变重复题业务政策。

## 实现范围

- 公共 `new-legacy/src/00-import-guard.js`：按操作复用进行中的 Promise，文件读取前锁定，直到提交及必要刷新结束；按钮/输入禁用并标记 aria-busy，成功或失败都释放。无时间防抖窗口，也不缓存文件正文。
- 原则与归纳卡、题库（首页、教师旧入口、批量对话框）、试卷、图谱/学习包、闪卡、用户、活动包、知识树、联想库使用公共保护。文件管理原有 busy 保留，公共锁延长至导入后列表刷新。
- 题库/试卷进行中不能通过取消、重新打开、换文件、修改策略清除锁。试卷预检合并；成功后重复确认复用结果。
- 试卷不确定结果重试复用完整 payload 和幂等键；明确的版本/预检/权限策略拒绝后可重新预检。重试按钮区分“重试导入”和“重试预检”。
- Prep Studio 11 类文件输入共用同一锁，防止不同文件同时覆盖工作区；服务器同步单独复用 Promise。离线构建直接内嵌同一公共模块，无复制变体。
- 后端扩展现有 `idempotency_service`，独立事务 PostgreSQL try-advisory-lock，在多个进程/标签页之间拒绝同一账号并发导入，返回 `409 IMPORT_IN_PROGRESS`，不排队执行重复大请求。锁贯穿业务 commit/rollback，在失败或连接关闭时释放；不同账号不互相阻塞。
- 覆盖题库批量、题库内题目批量、试卷预检/导入、原则预览/应用/组合导入、活动导入、备课批次/草稿同步、共享目录与联想库写入、用户导入、旧图谱迁移、图谱文件导入创建。
- 后端新增的是并发准入控制；跨刷新/进程重启的结果重放继续依赖各业务已有幂等或版本机制，不宣称所有接口都有永久幂等回执。
