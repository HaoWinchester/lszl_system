# V9.0-P3.1 管理后台信息架构调整报告

## 1. 开发基线

本次仅以 `V9.0-P2.2` 完整包为基线，版本升级为 `v9.0-p3.1`。P2.2 已完成的知识树导入、草稿编辑、9 层限制、发布、历史切换、归档、安全删除、当前版本唯一性、事务快照、审计和引用检查均保留。

## 2. 现有代码审计结论

### 2.1 技术结构

- 项目为无构建步骤的静态前端，页面通过原生 HTML、CSS 和 JavaScript 运行。
- `src/admin/*` 已形成仓库、权限、审计、事务、引用索引、科目、知识树、活动、课程和发布服务。
- 数据主要保存在浏览器本地仓库，管理端写入由事务服务自动创建快照并记录审计。
- 旧页面继续通过 `KGLearningContent` 兼容门面访问数据，适合渐进式改造，不需要一次性重写。

### 2.2 与 P3 目标的主要差距

1. 原 `admin-console.html` 以“知识树版本与发布”为首页，版本列表、发布流程、仓库状态、引用索引、快照、权限和审计集中堆放，缺少业务型后台导航。
2. 科目与知识树没有统一业务工作区；知识树维护在内容中心，版本操作在管理首页，两者入口割裂。
3. `SubjectService` 目前只有整表校验和保存，没有新增、停用、恢复、删除检查等独立业务方法。
4. `TaxonomyService` 明确限制只有草稿可编辑，当前知识树的节点保存、停用和删除仍会返回只读错误。
5. 题目数据已经使用稳定题目 ID；试卷保存 `activityId`，知识点移动不会天然改写试卷。这为 P3.4 的批量移动提供了正确基础。
6. 题目元数据已有 `primaryNodeId` 和 `mappingStatus`，可直接扩展“待分类”；但旧结构仍保留 `relatedNodeIds`，P3.4 需要停止普通界面继续使用多知识点能力。
7. 节点删除已有知识点引用检查基础，但后续需要明确区分“有题目”“有子节点”“历史使用过”三类业务规则。

## 3. P3.1—P3.5 实施计划

### P3.1：后台信息架构调整

- 建立八个一级入口：总览、科目与知识树、题库管理、试卷管理、课程与任务、用户管理、操作记录、系统设置。
- 首页只展示业务指标、常用工作、待处理事项和最近操作摘要。
- 建立“科目与知识树”双栏工作区，版本导入、切换、归档和删除移到“历史版本”。
- 审计记录迁移到“操作记录”。
- 仓库、引用索引、快照和权限边界迁移到“系统设置与诊断”。
- 为现有题库、课程、用户和基础系统设置页面补充统一后台上下文导航。

### P3.2：科目管理

- 扩展 `SubjectService`：新增、编辑、排序、停用、恢复、删除检查和永久删除。
- 新增科目级引用检查：知识树、题目、试卷、课程、任务或历史数据存在时禁止永久删除。
- 删除只允许空科目；有数据科目只能停用。
- 左侧科目列表加入创建、编辑、拖动排序、状态筛选和恢复入口。
- 所有写入走事务、自动快照和审计。

### P3.3：当前知识树直接维护

- 将当前知识树从“完全只读”调整为“允许安全日常维护”。
- 新增明确的日常写入方法：新增节点、改名、修改说明、移动、排序和停用。
- 保留最大 9 层、循环引用、父节点存在性和结构完整性校验。
- 日常操作不生成新版本、不要求重新发布，但每次创建轻量恢复点并保存前后差异。
- 历史使用节点默认停用；永久删除仅允许无题目、无子节点、无受保护历史引用的节点。

### P3.4：题目归属调整

- 新建题目分类服务，围绕一个 `primaryNodeId` 工作。
- 支持节点题目列表、多选、批量移动和移入待分类。
- 批量操作只修改题目分类，不复制题目，不改试卷中的题目 ID。
- 确认框明确列出“不影响”和“将影响”的范围。
- 节点删除检查加入题目数量和子节点数量。
- 普通界面停止提供一题多主要知识点；旧 `relatedNodeIds` 仅做兼容读取，不再作为新运营能力。

### P3.5：版本功能简化

- 统一状态语义：当前知识树、重大调整草稿、历史版本、归档版本。
- 日常编辑入口不再出现“复制版本后编辑”的强制提示。
- 新版本只用于整树导入、重大层级调整、拆分合并和整体分类体系更换。
- 保留现有发布切换、回退、归档、安全删除、引用阻断和恢复点。
- 清理重复入口与技术化文案，不引入跨版本节点自动合并、题目副本或复杂迁移。

## 4. 本次 P3.1 已完成内容

### 4.1 新后台总览

`admin-console.html` 已改为业务型总览：

- 展示启用科目、当前知识树、题库题目、试卷与任务数量；
- 展示待分类题目、知识树草稿和缺少当前知识树的科目；
- 提供科目与知识树、题库、试卷、课程与任务的直接入口；
- 仅保留最近操作摘要，不再展示版本表和技术诊断。

### 4.2 科目与知识树统一工作区

新增 `admin-subjects.html`：

- 左侧为科目列表；
- 右侧分为“当前知识树”“待分类题目”“历史版本”；
- 当前知识树展示节点数、最大层级和已分类题目数；
- 待分类题目作为固定状态呈现，不创建虚假节点；
- 导入、切换当前、复制重大调整草稿、归档、恢复和安全删除集中在历史版本页签；
- 现有 P2.2 生命周期服务和权限边界未被削弱。

### 4.3 操作记录与系统诊断分离

新增：

- `admin-operations.html`：审计、知识树生命周期和安全删除记录；
- `admin-settings.html`：仓库健康、统一引用索引、恢复快照、权限边界和基础系统设置入口。

### 4.4 统一后台上下文导航

题库、课程、用户和基础系统设置页面已增加后台一级导航，可在业务模块之间直接切换并返回总览。

## 5. 本次未提前实现的功能

P3.1 不改变以下业务行为：

- 当前知识树仍由服务层保持只读；直接维护将在 P3.3 实施。
- 科目新增、编辑、停用、恢复和删除保护将在 P3.2 实施。
- 题目批量移动、待分类写入和节点题目列表将在 P3.4 实施。
- 日常编辑与版本逻辑的最终解耦将在 P3.5 完成。

这样可以避免在信息架构重构时同时修改核心数据规则，降低回归风险。

## 7. 下一步

下一开发批次应从 P3.2 开始，先补齐科目领域服务和删除保护，再接入左侧科目列表的完整操作。P3.2 完成前，不应直接在界面层绕过服务写入科目数据。
