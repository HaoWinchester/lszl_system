# v8.6.1.1.1：代码健康、知识树性能与聚焦工作区报告

## 一、版本定位

- 主程序：v8.6.1.1.1
- 录入中心：Question Studio v0.2.1.1
- 数据标准保持不变：Activity Schema v1、Knowledge Taxonomy Schema v1、Course Configuration Schema v1
- 下一功能版本仍保留为 v8.6.1.2：活动分组、标签、题集与基础组卷

本版本是 v8.6.1.1 的维护与结构整理版本，不改变现有活动 ID、知识点 ID、课程引用和学习进度。

## 二、代码审查结论

教师工作台并没有把三个中心的完整业务代码嵌入同一页面。`teacher-workbench.html` 只是导航和状态摘要页，因此本身复杂度不高，不会成为主要技术债务。

本轮识别出的真实技术债务主要有三处：

1. 知识树图谱渲染时，每个节点反复读取、规范化和遍历整棵知识树，并重复统计活动数量；节点增多后会明显放大计算量。
2. 图谱视图与目录视图即使只有一个可见，也会同时生成 DOM；缩放操作还会重新生成整棵图谱。
3. 三个中心都需要“放大 / 收起”能力，如果分别实现，会形成三套重复逻辑；工作台首页的样式与状态脚本也写在 HTML 内，不利于继续维护。

## 三、本轮重构

### 1. 新增知识树只读索引层

新增：

```text
src/91-knowledge-tree-index.js
```

它在一次构建中生成：

- 节点 ID 索引；
- 父子节点索引；
- 路径缓存；
- 下级节点缓存；
- 搜索文本缓存；
- 节点直接归属活动数量。

图谱渲染不再针对每个节点重复读取 localStorage 和遍历全部活动。

### 2. 图谱渲染策略优化

- 只渲染当前可见的“图谱视图”或“目录视图”，不再同时渲染两套界面；
- 缩放只更新场景变换，不再重建节点 DOM；
- 搜索输入增加 90ms 合并刷新，连续输入时不重复执行完整渲染；
- 展开、折叠只重绘当前树视图；
- 重绘后保留画布和目录的滚动位置；
- 知识树变化时才重建索引。

在受限 Chromium 测试环境中，构造 360 个知识节点并让搜索结果显示全部节点时，搜索到完整 DOM 更新约为 281ms。该数值仅作为本次回归环境参考，不代表所有设备的固定性能。

### 3. 提取共享工作区管理器

新增：

```text
src/92-workspace-panel-manager.js
styles/workspace-panels.css
```

录入中心、内容中心和配置中心共用同一套：

- 放大到页面；
- 还原；
- 收起到右侧栏；
- 从侧栏恢复；
- Esc 退出放大；
- 工作区收起后的自动重新排版。

避免三个中心各维护一套状态与样式。

### 4. 整理工作台首页

原先 `teacher-workbench.html` 中的大段内联样式和内联统计脚本已拆分为：

```text
styles/workbench-home.css
src/91-teacher-workbench-app.js
```

工作台继续保持轻量导航页，不承担录入、活动库或课程配置的业务逻辑。

## 四、知识点删除规则

图谱视图、目录视图和右侧属性栏都增加了“删除 / 停用”入口。

删除采用安全规则：

- 没有下级、没有活动引用：可直接删除；
- 有下级但整个分支没有活动引用：确认后级联删除完整分支；
- 当前节点或下级节点仍被活动引用：禁止物理删除，并提示改为“停用”；
- 停用不会破坏历史活动、历史课程和已有学习记录；
- 删除操作可以通过知识树“撤销”恢复。

核心层新增：

```javascript
deleteKnowledgeNode(taxonomyId, nodeId, { cascade })
```

该接口也会被未来服务器端知识树管理功能复用。

## 六、后续技术债务判断

当前结构可以继续进入 v8.6.1.2，不需要推倒重写。

仍建议在后续控制两项边界：

1. `91-content-center-app.js` 已同时负责知识树控制和活动列表控制。开始加入标签、题集、组卷后，应把“活动库列表控制器”拆成独立模块，避免内容中心继续膨胀。
2. 四个静态 HTML 页面仍有少量重复顶部栏标记。当前离线纯前端阶段可接受；服务器化后应使用统一模板或前端壳组件生成顶部栏，避免多个页面分别修改版本和导航。

因此，工作台页面本身不是高风险点；未来最需要控制的是内容中心业务不断集中到单一脚本。
