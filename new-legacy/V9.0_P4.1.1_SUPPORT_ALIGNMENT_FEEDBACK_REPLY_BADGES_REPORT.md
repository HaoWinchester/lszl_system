# V9.0-P4.1.1 支持入口对齐与反馈回复提醒开发报告

## 一、本轮缺陷复查

基于 V9.0-P4.1 对首页支持入口、反馈闭环、消息未读状态和后台导航进行了专项复查。

本轮确认并修复的用户可见问题：

1. 首页问号 SVG 在按钮中存在视觉中心偏移；
2. 需求反馈与消息共用弹窗的关闭字符受字体基线影响，无法稳定居中；
3. 管理员回复反馈后，用户端没有未读角标，反馈闭环缺少主动提醒；
4. 历史后台浏览器测试仍按七个导航入口断言，未覆盖 P4.1 新增的反馈管理和消息管理。

在已执行的回归范围内，没有发现影响题目、题库、试卷发布快照、做题模式或安全删除的阻断性缺陷。

## 二、图标按钮对齐修复

首页问号按钮和弹窗关闭按钮统一采用稳定的图标按钮布局：

- 使用 `inline-flex` 水平和垂直居中；
- 清除字体字号、行高和默认内边距对 SVG 的影响；
- SVG 使用 `display: block`，不再参与文字基线排版；
- 固定按钮和图标尺寸；
- 保留键盘焦点、悬停和触控点击区域；
- 弹窗关闭按钮由文本字符 `×` 改为 SVG 关闭图标。

浏览器回归会直接读取按钮和 SVG 的边界矩形，校验二者中心点偏差小于 0.6 像素。

## 三、反馈回复未读提醒

管理员新增用户可见回复后，用户端现在会产生独立的反馈回复未读状态。

提醒位置包括：

- 首页问号按钮总角标；
- 支持菜单中的“需求反馈”独立角标；
- 反馈弹窗中的“我的反馈”页签角标；
- 对应反馈卡片的“管理员新回复”标记。

顶部总角标的计算规则为：

```text
未读总数 = 未读站内消息 + 未读管理员反馈回复
```

消息和反馈菜单继续显示各自数量，不会混淆来源。

### 已读规则

- 打开“需求反馈”弹窗不会直接清除角标；
- 用户进入“我的反馈”并实际看到回复列表后，相关回复标记为已读；
- 已读状态按账号隔离；
- 管理员只修改处理状态但没有新增回复时，不产生反馈角标；
- 新增下一条管理员回复后，会再次产生提醒；
- 同一浏览器中的标签页通过存储事件和仓库事件同步刷新。

本地演示模式新增存储键：

```text
kg_user_feedback_reply_reads_v1__<账号>
```

原有反馈数据 `kg_user_feedback_v1` 不需要迁移，题目和试卷数据完全不受影响。

## 四、服务器接口补充

正式远程模式需要补充：

```text
POST /api/feedback/:id/read
```

同时 `GET /api/feedback/mine` 的每条反馈应返回：

```json
{
  "lastReadAt": 0,
  "unreadReplyCount": 1
}
```

服务端必须根据当前登录会话隔离已读状态，并验证反馈确实属于当前用户。完整约束已更新到 `SERVER_ENGAGEMENT_API_V1.md`。

## 五、模块化重构评估

### 结论

程序已经需要模块化整理，但不建议在马上部署前进行一次性全面重写。

当前 `src` 中共有 134 个 JavaScript 文件，约 42,397 行代码；其中部分核心文件已经较大：

```text
src/77-multi-question-workspace.js   4,058 行
src/65-question-bank-admin.js        3,732 行
src/10-graph-editor.js               2,665 行
```

同时存在以下演进信号：

- 页面外壳、账号区、导航和弹窗在多个页面重复实现；
- 图标按钮、角标、悬浮窗和提示组件的样式逐渐分散；
- 本地存储与远程 REST 适配职责开始增加；
- 大型页面脚本同时承担数据、状态、渲染和事件处理；
- 使用全局对象保持静态部署兼容，模块边界依赖人工约束。

### 不建议“大爆炸式”重构的原因

一次性改为全新框架或全面 ES Module 会同时影响：

- 现有页面加载顺序；
- 大量全局兼容接口；
- 浏览器本地数据；
- 题库、试卷和学习页面闭环；
- 当前部署进度和回归成本。

### 推荐渐进顺序

#### M1：共享 UI 基础组件

优先抽取：

```text
IconButton
Badge
Modal / Drawer
Popover
Toast
```

本轮已先统一支持入口和关闭按钮的图标布局，可作为后续基础组件的样板。

#### M2：公共页面外壳

统一：

```text
顶部导航
账号区域
角色权限过滤
帮助与通知入口
页面级返回规则
```

#### M3：领域仓库和状态服务

按领域整理：

```text
题库与题目
试卷与发布版本
学习页面只读数据源
反馈与消息
用户与权限
```

页面只调用仓库和服务，不直接操作多个存储键。

#### M4：拆分大型页面控制器

将 2,000 行以上脚本逐步拆为：

```text
state
repository
renderer
interaction controller
commands / audit
```

每拆一个模块都保留旧全局适配层，并运行现有回归，不改变页面地址和数据结构。

## 六、验证结果

- 101 / 101 个既有 Node 回归测试通过；
- 8 项关键浏览器闭环通过；
- 241 个 JavaScript 文件语法检查通过；
- 24 个 HTML 页面检查通过，重复 ID 为 0；
- 本地脚本和样式引用缺失数为 0；
- 问号按钮和弹窗关闭 SVG 中心对齐浏览器几何校验通过；
- 管理员回复 → 用户角标 → 查看反馈 → 清除角标闭环通过；
- 消息未读角标与反馈回复角标并行计算通过。

## 七、安全与兼容性

本轮没有修改：

- 题目 ID 或题库 ID；
- 题目正文和分类；
- 试卷引用与不可变发布快照；
- 做题模式经验、血量和倒计时规则；
- 学习记录；
- 安全删除和历史引用保护。

浏览器存储无需强制迁移。旧反馈回复在首次升级后可能被视为未读，用户进入“我的反馈”查看后即会按账号记录已读状态。
