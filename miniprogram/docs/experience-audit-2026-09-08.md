# 小程序业务、体验与响应时间自检

日期：2026-09-08；最终 UAT 采样截至北京时间 12:15:57。

## 结论

**不能按“全部做好、可以正式发布”放行。** 保存退出主流程已通过复测，但 UAT 错题复仇存在两个稳定复现的功能缺陷；另有列表载荷过大、选项编号重复及发布配置一致性风险。此次只增加/完善测试工具与报告，没有修产品代码、合分支、发布小程序或重启服务。

本报告按“前端需求质量门禁”区分成功、失败、恢复和跨端一致性。自动化通过、开发者工具观察、真实 UAT 接口、真机验证分别记录，不能互相替代。自检不是用户 UAT 验收。

## 确认缺陷及改进项

### P1：纠错中断后无法继续，UAT 缺少接口

复现：完成一轮包含错题的练习 → 错题复仇再次答错 → 进入纠错 → 重新打开错题复仇。

实际：`GET /api/v1/learning/practice/mistakes/:mistake/remediation` 返回 404，页面 `loadError` 为“页面资源不存在”。免费、有效会员、过期会员均复现。

定位：本地 `backend/app/api/v1/learning.py` 已有 `get_remediation` 路由；读取 UAT 容器源码确认缺少此 GET 路由，只存在其他纠错 POST 路由。小程序 `pages/revenge/index.ts` 已经依赖它。**这是运行版本不匹配，不是学员账号问题。**

放行条件：UAT 部署包含该接口及权限控制的对应后端，并复测“重进纠错”、其他账号不可读，以及无变式时的退出/等待状态。

### P1：错题答题重试会重复计数

复现：同一个错题用相同 `requestId`、相同答案连续提交两次 `revenge-answer`。

实际：第一次计数为 2，第二次变成 3。三类账号均复现。网络回包丢失后的重试可能被当作新的作答。

定位：小程序公共写入协调器已经保留重试键；UAT `learning_service.py` 直接递增 `revenge_attempt_count`，缺少本地对应的请求去重逻辑。不能只靠按钮禁用解决。

放行条件：服务端同键同内容重试不重复计数，同键不同内容不能静默覆盖；验证变式提交也应跑同类用例。

### P2：未完成列表返回整卷，主页面存在性能放大风险

实测只有一份 180 题暂停练习时，`sessions/active` 已返回 **735,384 字节**解码后 JSON。首页只需要最近进度，记录页只需要摘要，我的页面只需要统计，但三者都会请求它。

定位：`backend/app/services/practice_session_service.py:list_active_sessions` 对每个会话构造完整 `_session_payload`；`miniprogram/services/practice.ts:listSessions` 又在记录/个人页加载中调用 active。180 题的暂停响应也有 884,296 字节。

这是已量到的冗余载荷；多会话、移动弱网下卡顿是风险判断，**本轮没有做多人大并发或真机弱网压测**。建议列表使用统一轻量摘要，进入练习再取题目详情，避免各页面自行裁剪却仍下载整卷。

### P2：选项编号重复

开发者工具真实练习页显示圆标 `A` 后，正文又是 `A. …`；B/C 等相同，读屏标签也重复。

定位：`components/question-view/index.wxml` 分别显示 `item.id` 与 `item.text`；`domain/question.ts` 未处理源内容里已有的选项前缀。需要在明确规则下规范选项显示，保留原始答案标识，不能粗暴删除正文中任意字母。

### P2（容量边界）：试卷列表只取前 100 条

`pages/papers/index.ts:loadPapers` 固定 `listPublishedPapers(1, 100)`，忽略返回的 total，没有下一页/触底加载。科目和会员筛选也只对这批数据执行。当前 UAT 未超过此容量，本轮没有创建 101 份真实试卷；这是代码确认的扩容缺口，不是假称已在 UAT 复现漏卷。

### 发布链路风险：普通 UAT 部署未包含小程序配置叠加文件

`deploy/update-uat.sh` 的启动命令只指定 `docker-compose.uat.yml`，没有叠加独立的小程序配置文件。当前服务可用不代表下一次常规部署仍会保留微信登录所需配置。

需将独立小程序配置明确接入部署链路，并加入不泄露密钥的配置存在性/登录健康检查；保持 PC 登录与支付原配置不动。此轮仅审查，没有执行部署来“试坏”环境。

### 产品内容待完善

- `domain/legal-copy.ts` 的隐私政策和用户协议目前各是一小段说明，不是可查阅的完整产品文档；这里指出内容完整性，不作法律合规结论。
- 未关联身份的微信用户仍会进入绑定/注册用户名密码流程，不能对外宣称所有新用户都能微信一键直接使用；本轮未用全新真实微信身份重走此流程。
- `docs/release-checklist.md` 仍含旧导入目录/游客 AppID 提示及 108 项历史结果，不能拿它当本次版本的发布证据。

## 响应时间

测量：本机到 UAT 公网 HTTPS。接口时间覆盖发出请求至读完响应；页面时间覆盖调用真实 Page 加载方法至数据准备完成，**不包含原生布局/绘制，不等于点击到可见或帧率**。没有进行并发压力测试。统计采用最近秩 P50/P95；样本少时 P95 等同最大值，只作观察。

| 页面数据准备 | 样本数 | P50 | P95/最大 |
| --- | ---: | ---: | ---: |
| 首页 | 15 | 481 ms | 591 ms |
| 记录 | 15 | 218 ms | 241 ms |
| 我的 | 15 | 537 ms | 582 ms |
| 试卷列表 | 3 | 780 ms | 1069 ms |
| 会员详情 | 3 | 157 ms | 168 ms |
| 练习结果 | 3 | 276 ms | 320 ms |

首页/记录/我的各为三类账号 × 五次新 Page 加载；标记 warm 的样本是同一进程/连接下的重复加载，不是宣称“缓存切页耗时”。另有独立断言确认刚加载的记录页连续触发三次 onShow 不重复请求。

180 题单次样本：创建 522 ms、暂停 603 ms、重新读取 318 ms。三题练习的交卷接口 n=3，P50 287 ms、最大 296 ms。此轮未对 180 题完成全部作答交卷做性能采样。

多轮采样中试卷库数据准备约 0.73～1.07 秒，个人页曾出现约 0.95 秒样本，说明存在波动；不能只用最终较快的一轮保证体验。优先处理列表冗余载荷与无必要的请求，再进行固定真机环境下的前后对比。

## 恢复、安全与未测边界

通过：保存响应丢失不丢多选暂存、恢复无虚假冲突、取消退出不放弃、完成重试不重复完成、记录与 PC 报告一致、服务端会员门禁、跨用户会话隔离、刷新失败保留数据、当前设备注销不踢掉另一设备。

故障注入在请求边界模拟离线/回包丢失，不是手机飞行模式。未做真实 iOS/Android 扫码体验包、触控帧率、网络切换、系统强杀、真实微信支付（已不在范围）、生产性能或高并发测试。当前环境无可用独立 tsc 命令，未额外宣称 TypeScript 全量类型检查通过；已有 Node 检查与开发者工具运行不等于该检查。

## 复跑与后续顺序

1. 先补齐 UAT 错题接口和服务端去重，保留 PC 业务与账号隔离规则。
2. 对 active 列表做轻量化，并修选项重复；分别做前后时延/载荷对比。
3. 复跑本地全套、`tests/manual/uat-save-exit.mjs`、`tests/manual/uat-experience-audit.mjs`，要求已确认的 6 个失败全部转绿。
4. 修正部署/发布文档与配置链路后，用对应体验包做真机测试；不能自动将自检结果当用户验收或合入 main 的授权。

测试入口：`npm test --prefix miniprogram`；后端现有环境运行 `python -m pytest tests/ -q`；本地十账号入口 `backend/tests/manual_ten_mini_accounts.py` 有本地数据库保护，不可拿它跑 UAT。

UAT 独立账号由 `backend/tests/manual_uat_save_exit.py --audit` 在 UAT 容器执行，凭据只经内存 stdin 传给 Node 探针，绝不可直接把其 JSON 输出到终端/报告。完成后以这次精确生成的三个账号名调用撤销/归档分支。综合探针现在失败返回非零状态，不能在流水线中忽略退出码。仅适用于明确授权的 UAT 自检，不用于正式库。
