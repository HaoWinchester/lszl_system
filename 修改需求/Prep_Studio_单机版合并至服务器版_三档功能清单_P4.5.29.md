# Prep Studio 单机版 → 服务器版功能合并清单

**目标基线：** 以服务器版的多人协作/同步架构为底座，合并单机版已经成熟的内容制作能力。
**目标版本：** 合并完成后统一到 V9.0-P4.5.29（或后续明确的新统一版本）。
**原则：** 不用单机 HTML 直接覆盖服务器版；优先统一数据契约，再合并业务功能和 UI；服务器独有的协作能力必须保留。

---

## A. 必须同步

这些项目涉及数据契约、题库兼容、核心内容模型或主程序兼容，建议作为本轮合并的硬性范围。

- [ ] **M01｜Recall 允许留空**：只有填写了不存在的 Recall ID 才报错。（原差异 #3）
- [ ] **M02｜关键词位置来源隔离**：题干关键词只定位题干，选项关键词只定位指定选项。（#4）
- [ ] **M03｜同词跨来源可独立存在**：同一个词可分别作为题干 clue 和选项 clue。（#5）
- [ ] **M04｜原则包双格式兼容**：同时支持 `kg-principle-card-bundle-v1` 与 `pmp-principle-preset-bundle-v1`。（#6）
- [ ] **M05｜Subject Facets 系统**：服务器版补齐完整 Subject Facet 数据模型。（#9）
- [ ] **M06｜Facet Registry 管理**：支持导入、编辑、校验、导出。（#10）
- [ ] **M07｜题目绑定 Subject Facets**：题目编辑与导入导出均保留 Facet 绑定。（#11）
- [ ] **M08｜Question Family v1**：服务器版补齐完整题目家族模型。（#12）
- [ ] **M09｜家族角色**：支持母题、家族成员、独立题。（#13）
- [ ] **M10｜家族关系类型**：支持等价变体、能力拆解、高阶扩展等关系。（#14）
- [ ] **M11｜家族诊断字段**：支持 A/B/C 等价等级、`diagnosticTarget`、L1–L4 等字段。（#15）
- [ ] **M12｜家族用途与质量确认字段**：保留用途多选及人工质量确认数据。（#16）
- [ ] **M13｜家族最低覆盖校验**：支持强等价、概念、理解、高阶验证的覆盖提醒。（#19）
- [ ] **M14｜难度契约统一**：普通题难度使用“简单/中等/困难”，与家族 L1–L4 分离。（#21）
- [ ] **M15｜Global Tag ID 新体系**：升级为 `global/...` 命名体系，并兼容旧 ID 迁移。（#26）
- [ ] **M16｜完整内容包结构升级**：完整包中包含 Subject Facet Registry 等新增配置。（#27）
- [ ] **M17｜Question Family 校验**：校验中心支持家族数据完整性检查。（#28）
- [ ] **M18｜Subject Facet 校验**：校验中心支持 Facet Registry 与题目绑定检查。（#29）
- [ ] **M19｜P4.5.29 programCompatibility**：服务器版导出题库携带统一兼容契约。（#31）
- [ ] **M20｜Deep Recall 揭示策略**：写入 `deepRecallKeywordRevealPolicy=click-to-reveal-all-keywords`。（#32）
- [ ] **M21｜核心关键词策略**：写入核心关键词仅用于重叠匹配优先级、不提前显示的契约。（#33）
- [ ] **M22｜Recall 兼容策略**：写入 Recall 为 optional-existing-id-only。（#34）
- [ ] **M23｜关键词位置兼容策略**：写入 `keywordLocationPolicy=source-isolated-derived`。（#35）
- [ ] **M24｜版本统一**：主程序、服务器 Prep Studio、兼容契约、导出元数据使用同一正式版本。（#36）
- [ ] **M25｜兼容主程序版本显示**：服务器 Prep Studio 明确显示当前兼容主程序版本。（#37）
- [ ] **M26｜External AI Authoring Contract 升级**：覆盖 Family、Facet、Keyword v2、Recall 可选等新字段。（#40）

### A 类验收门槛

- [ ] 服务器版导入/导出后，Family、Facet、Keyword、Recall、Principle、Global Tag 字段不丢失。
- [ ] 单机版导出的 P4.5.29 内容包可被服务器版正常导入。
- [ ] 服务器版导出的内容包可被当前主程序正常消费。
- [ ] 自动重算关键词位置时不改变 clue 的原始来源语义。
- [ ] 空 Recall 不报错；无效 Recall ID 才报错。
- [ ] 核心关键词在学习端默认不提前高亮或泄露。

## B. 建议同步

这些项目主要提升制作效率、迁移体验或编辑 UI，可以在核心数据契约稳定后合并。

- [ ] **R01｜Recall 手动输入模糊搜索**：在下拉选择之外增加手工搜索入口。（原差异 #1）
- [ ] **R02｜Recall 多字段搜索**：支持中文名、英文名、Alias、Recall ID。（#2）
- [ ] **R03｜旧原则/归纳卡独立迁移入口**：兼容历史 JSON 资产。（#7）
- [ ] **R04｜原则与归纳卡合并导入**：按 ID/名称更新已有数据，不只做整体替换。（#8）
- [ ] **R05｜从母题创建家族成员**：提供快捷创建流程。（#17）
- [ ] **R06｜家族 JSON 模板与 AI 提示词**：方便外部 AI 按契约生成家族成员。（#18）
- [ ] **R07｜家族导航与识别 UI**：题目列表、编辑区增加家族导航、页签、颜色识别。（#20）
- [ ] **R08｜校验结果定位跳转**：从错误/警告直接跳转到对应题目或配置对象。（#30）
- [ ] **R09｜粘性题目预览/家族页签**：保留单机版新版编辑体验。（#38）
- [ ] **R10｜Delete 快捷删除**：在不影响输入框的前提下支持快捷删除当前题目。（#39）

### B 类验收门槛

- [ ] 新 UI 不影响服务器版多人锁、草稿同步和发布流程。
- [ ] 搜索、导航和快捷键在无服务器连接异常时不会破坏数据。
- [ ] 旧资产迁移入口仅做兼容，不改变当前权威数据格式。

## C. 不建议从单机版原样同步

以下功能在服务器版已有更合适的服务器机制。建议避免再引入第二套本地状态源，以免继续造成配置和数据混乱。

- [ ] **N01｜不原样同步本地 Workspace 自动保存**：服务器版优先使用共享草稿/服务器持久化。（原差异 #22）
- [ ] **N02｜不原样同步自动恢复本机 Workspace**：避免与服务器最新草稿产生双重“真源”。（#23）
- [ ] **N03｜不原样同步本机 Workspace 手动保存/恢复/删除**：如需离线容灾，应单独设计明确的离线缓存机制。（#24）
- [ ] **N04｜不把本机 Workspace 作为完整配置真源**：题库、知识树、Recall、原则、标签等应以服务器配置/发布版本为准。（#25）

---

## D. 服务器版独有能力：合并过程中必须保留

这些不是“单机版缺少功能”，而是服务器版的核心优势。合并单机版功能时不得回退或删除。

- [ ] **S01｜共享草稿**
- [ ] **S02｜服务器题库/内容目录**
- [ ] **S03｜多人编辑锁**
- [ ] **S04｜锁心跳与超时释放**
- [ ] **S05｜远程版本刷新/更新检测**
- [ ] **S06｜发布与服务器内容同步**
- [ ] **S07｜冲突处理/冲突题复制**
- [ ] **S08｜服务器身份、权限或协作上下文（现有实现保持不变）**

### D 类保护性验收

- [ ] 两个浏览器同时编辑同一对象时，锁机制仍正常。
- [ ] 草稿保存、刷新恢复、发布、重新读取服务器版本流程不回退。
- [ ] 新增 Family/Facet/Keyword 字段能够完整经过共享草稿与发布链路。
- [ ] 发生版本冲突时，不因新字段导致静默覆盖或数据丢失。

## 建议合并顺序

- [ ] **阶段 0｜冻结基线**：固定服务器当前版本、单机 P4.5.29 版本和测试样本，建立可回滚标签。
- [ ] **阶段 1｜统一数据契约**：完成 M01–M26 中的数据模型、兼容字段和迁移逻辑。
- [ ] **阶段 2｜补齐编辑能力**：完成 Family、Facet、Recall、Principle 的服务器版编辑入口。
- [ ] **阶段 3｜补齐导入导出与校验**：确保完整包、外部 AI 契约和校验中心一致。
- [ ] **阶段 4｜合并体验功能**：执行 R01–R10。
- [ ] **阶段 5｜服务器协作回归**：重点验证 S01–S08 无回退。
- [ ] **阶段 6｜统一版本发布**：只保留一个正式用户版本号；Build 仅作为内部开发元数据。

## 最终发布 Gate

以下项目全部通过后，再把服务器版标记为新的统一基线：

- [ ] 数据契约一致
- [ ] 单机 → 服务器导入通过
- [ ] 服务器 → 主程序消费通过
- [ ] Family / Facet / Keyword / Recall / Principle 数据无丢失
- [ ] Deep Recall 核心关键词揭示策略正确
- [ ] 服务器多人锁与共享草稿无回退
- [ ] 发布/同步/冲突处理无回退
- [ ] 版本号与兼容声明一致
- [ ] 回归测试通过并留存结果
- [ ] 新统一基线已打包、校验并归档
