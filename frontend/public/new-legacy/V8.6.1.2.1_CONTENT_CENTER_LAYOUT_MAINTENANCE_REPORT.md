# v8.6.1.2.1 内容中心布局维护报告

## 一、维护范围

本版以 `v8.6.1.2` 为唯一基线，只处理内容中心布局、工作区显示控制和录入中心试题定位问题，不提前开发 `v8.6.2` 复杂学习任务编辑器。

维护边界：

- 不改变 Activity Schema v1、Knowledge Taxonomy Schema v1、学习任务和试卷数据结构；
- 不改变活动 ID、知识点 ID、题集引用、课程节点 ID 和学习进度存储；
- 不新增复杂学习任务编辑能力；
- 保留图谱视图，目录视图改为默认入口。

## 二、复现与根因

### 1. 工作区被错误改成三列

`content-center.html` 的主布局原本是“两列主工作区 + 一行全宽组织区”。共享工作区控制器初始化时，把以下三个 section 全部计入可见列数：

1. 知识树工作区；
2. 统一活动库；
3. 标签与题集。

随后 `workspace-panels.css` 的通用规则把 `.cc-layout` 强制设为三等分列。标签与题集仍通过 `grid-column:1/-1` 占满下一行，因此首行出现一个没有内容的第三列。问题截图中的右侧大块空白由此产生。

### 2. 活动筛选栏使用固定十列，按页面宽度而非容器宽度响应

`content-organization.css` 把活动工具栏覆盖成十个固定列。由于统一活动库在错误的三列布局中只剩约 600px，筛选栏仍要求超过 1200px 的内部宽度，最终越过活动库边界并覆盖右侧空白列。

即使恢复两列，1920px 屏幕下单个活动库面板也不足以稳定容纳十个固定列；原媒体查询只观察浏览器视口宽度，无法知道活动库自身的实际容器宽度。

### 3. 最小宽度阻止浏览器缩放后的响应式重排

以下约束共同造成 125% 和 150% 缩放下的横向风险：

- `.cc-app{min-width:1180px}`；
- 双列布局每列 `minmax(650px,...)`；
- 旧断点中再次设置 `.cc-app{min-width:980px}`；
- 图谱主区、检查器和固定工具栏同时争夺宽度。

### 4. 全局放大/收起规则与内容中心语义不一致

共享控制器只知道“面板数量”，不知道标签与题集属于全宽辅助区。收起或恢复任一面板时，会重新按所有可见 section 计算列数，导致布局不可逆或出现不合理的半宽面板。

### 5. 结构化修改缺少独立试题定位入口

录入中心已有左侧活动列表，但结构化修改面板放大后，左侧列表不再可见。编辑器标题只显示 `1 / N`，没有上一题、下一题或下拉定位控件，因此用户容易误以为只能编辑第一题。

## 三、修复内容

### 工作区和 DOM 语义

- 给“标签与题集”增加 `data-workspace-span="full"`；
- 共享工作区控制器只用非全宽面板计算列数；
- 给内容中心增加 `data-workspace-responsive="stack-1280"`；
- CSS 视口低于 1280px 时自动改为单列，达到 1280px 时保留双列；
- 收起知识树后活动库自动占满主列，恢复后回到原布局；
- 全宽组织区不再干扰主工作区列数。

### 内容中心 CSS

- 移除应用级最小宽度；
- 双列使用 `repeat(2,minmax(0,1fr))`，避免固定 650px 下限；
- 活动筛选栏改为 `auto-fit + minmax` 自适应网格；
- 搜索框占两格，批量知识点按钮在窄屏独占一行；
- 标题、统计、放大/收起控件允许安全换行；
- 1050px 以下知识树检查器移动到主区下方；
- 表格继续在自身滚动容器内横向滚动，不把页面撑宽；
- 批量操作栏保持换行并限制在活动库面板内。

### 知识树视图

- 目录视图改为默认视图，适合日常维护和浏览器缩放；
- 图谱视图、缩放、拖动、增删改、撤销和重做仍保留；
- 回归测试会从目录切换到图谱并确认节点成功渲染。

本轮不删除图谱视图，因为根因可通过小范围布局修复解决，删除图谱会造成不必要的兼容性变化。后续若实际使用仍低，可在独立版本中正式弃用。

### 结构化修改试题定位

结构化修改标题区新增：

- 上一题按钮；
- “试题定位”下拉框；
- 下一题按钮；
- 当前题号 `N / 总数`。

切换后同步更新左侧活动列表、结构化表单、运行预览和校验结果；结构化修改放大后仍可切题。

## 四、视觉回归矩阵

浏览器缩放通过“物理屏幕尺寸 ÷ 缩放比例”的 CSS 视口，并配合同倍率 device scale factor 复现。

| 屏幕 | 100% | 125% | 150% |
|---|---|---|---|
| 1366×768 | 通过，双列 | 通过，单列 | 通过，单列 |
| 1440×900 | 通过，双列 | 通过，单列 | 通过，单列 |
| 1920×1080 | 通过，双列 | 通过，双列 | 通过，双列 |

每个组合均验证：

- 页面无横向溢出；
- 活动筛选子项不越出工具栏；
- 标签与题集横跨完整内容区域；
- 82 个活动正常渲染；
- 目录/图谱切换；
- 批量选择和批量操作栏；
- 活动库放大与还原；
- 知识树收起、侧栏恢复和列数回归；
- 1920→960→1920 无刷新重排。

## 六、内容中心拆分评估

当前内容中心已经具备合理的第一层模块边界：

- `91-content-center-app.js`：活动库、知识树和页面协同；
- `93-content-organization-app.js`：标签、题集、收藏和批量属性；
- `93-content-organization-core.js`：组织数据层；
- `92-workspace-panel-manager.js`：共享显示控制；
- 独立 CSS：内容中心、组织区和工作区控制。

本次错误来自“共享布局控制器缺少全宽语义”和“工具栏响应依据错误”，不是主脚本体积本身造成。为避免维护版引入新的重构风险，本轮不做大规模模块拆分。

建议在 `v8.6.2` 真正进入复杂学习任务编辑器前，再按功能增长情况考虑：

1. 抽出 `content-center-layout-controller.js`，只负责断点、面板语义和重排；
2. 抽出 `activity-library-view.js`，只负责筛选、表格和批量栏；
3. 学习任务编辑器作为独立页面或独立应用模块，不继续塞入内容中心主脚本。

本版只完成布局维护、试题定位可用性和回归保障。`v8.6.2` 的复杂学习任务编辑器未在本轮开发。
