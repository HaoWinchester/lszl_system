# V9.0-P0 管理端基础架构

## 范围

V9.0-P0 在 P2.2.38 冻结基线上建立管理端的可替换基础层，不重写学员端，也不在本阶段建设完整发布中心或多人服务端。

## 分层

```text
管理页面
  ↓
Subject / Taxonomy / Activity / Course / Release Service
  ↓
Permission + Reference Index + Transaction + Audit
  ↓
Content Repository Contract
  ↓
LocalContentRepository（当前） / HttpContentRepository（后续）
```

现有 `window.KGLearningContent` 保留为兼容门面。V9.0 管理页面使用 `window.KGAdminServices`，旧内容中心、课程设置和教师工作台仍可调用原接口，写入由新领域服务承接。

## 本地仓库

`KGLocalContentRepository` 统一管理以下资源：

- 科目、知识树、活动覆盖；
- 课程草稿、课程发布和当前发布指针；
- 标签、题集、试卷、学习任务；
- 管理端审计、事务快照、知识树导入记录。

仓库提供 `read / write / remove / snapshot / restore / health`。未来的 HTTP 仓库只需遵守同一契约。

## 写入事务

领域写入遵循：

```text
权限检查
→ 保存相关资源快照
→ 结构校验
→ 一次提交
→ 无效结果或异常时恢复快照
→ 记录审计
```

本地快照默认保留最近 30 份；审计默认保留最近 500 条。

## 引用索引

索引覆盖：

```text
知识节点
  → 主/相关活动
    → 课程草稿与发布版本
    → 学习任务
    → 试卷
    → 题集与收藏
```

P0 先提供统一查询和统计接口。后续删除、替换、导入及发布检查直接复用该索引。

## 权限边界

当前角色体系保持兼容：

- `teacher`：知识树、活动、课程、任务、试卷和基础版本导入；
- `admin`：教师权限 + 科目、知识树发布、审计和快照恢复；
- `student / viewer / guest`：不执行管理写入。

当前仍为浏览器本地原型；服务端接入后必须在 API 层再次校验。

## 知识树导入原则

P0 已落实简化版本策略：

1. 目标科目没有知识树：直接导入为 `v1.0`。
2. 目标科目已有知识树：保留全部旧版，自动新增下一整数版本，例如 `v2.0`。
3. 不覆盖、不做节点级合并、不要求人工选择冲突策略。
4. 新导入版本默认为草稿；教师后续调整。
5. 仍执行必要结构校验：稳定 ID、父节点、循环、层级连续和最大六层。
6. 记录文件名、操作者、时间、生成版本和节点数。

完整导入导出工作区、版本切换和发布动作进入 V9.0-P1。
