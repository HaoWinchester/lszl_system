① 基础数据与导入

这里负责把外部 AI / Word 内容、知识树、联想库、原则、归纳卡和标签配置装入当前工作区。建议先选择制作人，再导入基础数据。

推荐顺序

  1. 确认当前制作人。
  2. 导入知识树和科目级联想库。
  3. 优先导入“完整内容准备包 JSON”，或使用 Word / AI 文本粘贴助手。
  4. 题量大时开启本机保存或自动保存。
示例：一次导入 50 道沟通题后，程序会自动给 50 道题生成 Question UUID，并给整批题记录同一个 Batch ID。

② 原则归纳卡 / 标签

原则用于解释“为什么这个选项应该/不应该这样做”；归纳卡是原则的可阅读教学卡片。标签用于训练阶段、题目特征、来源等分类。

原则示例

原则：确认沟通是否真正有效
归纳卡：信息已经发送，不代表沟通完成。应确认接收、理解并能够据此行动。

训练阶段标签

第一个二级标签“训练阶段”现在固定 7 个槽位：基础练习、阶段测试、模拟考试、冲刺复习、预习练习、强化训练、错题复盘。前 4 个保留旧版槽位不变，新增加的 3 个放在后面，避免历史配置错位。后期仍可在标签管理中改名和配置 Alias。

标签 Alias 示例

规范标签：基础练习
兼容别名：入门题, 基础题
旧资料出现“基础题”时可归一到“基础练习”。

修改标签名不会自动把旧名称偷偷加入 Alias；Alias 只按当前槽位明确保存。

③ 题目录入与检查

这是主要人工校核区。中部题目预览用于快速标关键词；完整表单位于下方，用于细改双语、解析、知识点和原则映射。

关键词操作

  • 框选未标记词：弹出新增关键词编辑框。
  • 点击已有关键词：修改普通/核心、联想入口、Solution Role、Core Reason。
  • 点击其他区域：关键词编辑浮窗自动关闭。
普通关键词：“项目经理”“相关方”——用于知识回忆。
核心关键词：“首先”——可标为 decision-cue，说明它决定解题顺序。

快速检查

右侧“本题快速检查”会优先提示缺失字段、核心关键词数量、联想入口、知识点等问题，再查看关键词明细。

④ 联想词编辑

这里维护“看到一个词，应该联想到哪个知识入口，以及还能继续想到什么”的关系网络。

同义词原则

规范节点：相关方
Aliases：利益相关方, 干系人, Stakeholder
不要为了不同译名建立多个等义节点。

关系图怎么点

上位/下位知识点普通点击只做预览选择，不会修改绑定。只有明确点击“将当前联想词绑定到此知识点”才会改变 metadata.taxonomyNodeId。

底部“被哪些节点联想”可点击直接跳到对应联想节点继续编辑。

⑤ 题目演示校验

以未来做题大厅的视角检查完整题目，而不是看数据表。

  • 左侧按题目列表切换。
  • 右上角切换：中 / EN / 双语。
  • 正确答案直接高亮。
  • 关键词默认不高亮，鼠标悬浮临时高亮。
  • 点击关键词：右侧显示最多 4 层联想通路。
  • 点击 A/B/C/D：顶部原则归纳卡显示该选项对应原则。
检查目标：点击“有效沟通”后，应能看到有效的 Recall 入口和后续通路；点击错误选项 C，应能看到例如“避免过早升级”的原则归纳卡。

⑥ 校验中心

这是全工作区的结构完整性检查。建议正式导出前运行一次，并尽量清除所有 Error。

主要检查

  • 题干、选项、正确答案、解析完整性。
  • 双语内容提醒。
  • 知识点稳定 Node ID。
  • 普通/核心关键词及 Core Reason。
  • Recall 节点、Alias 冲突、关系端点。
  • 原则 / 归纳卡 / 标签绑定。
  • Question ID 重复。
  • 不同 Question ID 但 Content Hash 相同的疑似重复题。
Error：核心关键词指向不存在的 Recall ID。
Warning：两个不同 UUID 的题目有相同 SHA-256 Content Hash，需要确认是否重复题。

⑦ 导出与审计

这里输出题库、完整内容包、联想库、原则与归纳卡组合、标签配置、校验报告和工作区草稿。

v0.3.5 导出审计

每次正式导出会写入一条设备级审计事件，记录：

  • Audit ID
  • 导出时间
  • 制作人 Creator ID / 姓名
  • Device ID
  • 导出类型与文件名
  • 题目数量
  • 最近 Batch ID
  • 校验 Error / Warning 数
  • 导出 payload 的 SHA-256 指纹
  • Prep Studio 版本
用途：未来管理员收到一个 JSON 后，可以把文件重新计算 SHA-256，与 Audit Trail 中的 payloadHash 对比，确认是否就是某位制作人在某个时间导出的那一版。

“导出审计日志”本身不会再写一条新的审计事件，避免递归记录。
