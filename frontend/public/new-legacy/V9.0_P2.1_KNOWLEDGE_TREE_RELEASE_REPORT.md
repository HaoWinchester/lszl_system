# V9.0-P2.1 知识树版本查看、编辑与发布报告

## 版本目标

V9.0-P2.1 将 V9.0-P0 已有的“知识树版本导入”能力补齐为可实际使用的闭环：

```text
导入 / 基于旧版创建草稿
→ 查看与编辑草稿
→ 管理员发布为当前
→ 历史已发布版本保留
→ 必要时切换回历史版本
```

## 已实现内容

### 1. 最大层级调整为 9

- `KGLearningContent.MAX_DEPTH` 从 6 调整为 9。
- 知识树 JSON Schema 的 `nodes[].level.maximum` 调整为 9。
- 题目录入中心知识树适配器同步调整为 9。
- 内容中心新增节点、拖动层级和导入校验均按 9 层执行。
- 已存在的旧知识树在读取时自动获得 9 层编辑上限，不需要手工迁移。

### 2. 导入后可以直接查看和编辑

- 管理端版本列表为每个版本提供“查看 / 编辑”入口。
- 内容中心新增知识树版本选择器。
- 可以通过 `content-center.html?subjectId=...&taxonomyId=...#knowledge` 精确打开一个版本。
- 草稿版本支持新增、改名、属性修改、移动、删除和撤销 / 重做。
- 导入成功后提示进入草稿继续编辑。

### 3. 管理员发布为当前

管理端版本列表直接提供：

- **发布为当前**：用于草稿版本；
- **设为当前**：用于历史已发布版本；
- **复制为新草稿**：基于已发布版本创建下一版本草稿；
- **查看 / 编辑**：草稿可编辑，已发布版本只读。

发布后：

- 目标版本状态变为 `published`；
- 目标版本成为该科目唯一 `isDefault=true` 的知识树；
- 科目的 `defaultTaxonomyId` 指向目标版本；
- 原当前版本继续作为历史已发布版本保留；
- 学员端和默认知识树引用开始使用新当前版本。

### 4. 发布安全边界

- 只有管理员具有 `publishTaxonomies` 权限。
- 教师可以导入、创建和编辑草稿，但不能发布。
- 已发布版本不可直接编辑；继续调整必须先复制为新草稿。
- 发布前执行结构校验、空树检查、根节点检查和最大层级检查。
- 发布、切换当前、创建草稿均由事务服务处理，并在写入前创建快照。
- 操作写入审计日志和知识树发布记录。

## 数据规则

### 版本号

```text
无历史版本 → v1.0
已有 v1.0 → v2.0
已有 v2.0 → v3.0
```

编辑一个草稿不会自动增加版本号；再次导入或“复制为新草稿”时才增加版本号。

### 当前版本

每个科目最多一个当前知识树：

```text
subject.defaultTaxonomyId = 当前 taxonomy.id
当前 taxonomy.isDefault = true
同科目其他 taxonomy.isDefault = false
```

### 状态

- `draft`：可编辑，尚未供学员端默认使用；
- `published`：已发布，只读；其中一个可以是当前版本；
- 历史已发布版本可以重新“设为当前”。

## 使用入口

### 管理员发布

1. 使用管理员账号打开 `admin-console.html`；如果发布按钮禁用，可从右上角“登录 / 切换账号”进入管理员账号。
2. 在“知识树版本”中找到草稿。
3. 可先点击“查看 / 编辑”检查内容。
4. 返回管理端，点击“发布为当前”。
5. 确认并填写可选的发布说明。

### 教师编辑草稿

1. 在管理端导入知识树，或对已发布版本点击“复制为新草稿”。
2. 点击“查看 / 编辑”。
3. 在内容中心的版本选择器中确认当前版本带有“草稿”标记。
4. 完成节点编辑并保存。
5. 由管理员发布。
